## 一、虚拟屏预览窗（照 Operit `VirtualDisplayOverlay` 的形状）

### 做了什么

新文件 `app/.../device/shower/VirtualScreenOverlay.kt`，用 `WindowManager` +
`TYPE_APPLICATION_OVERLAY` 挂一个小窗：

- 内容 = `ShowerSurfaceView`（showerclient 的 MediaCodec 渲染视图），`bindController(VirtualScreenSession.controller)`；
- 顶部 30dp 工具条：`虚拟屏 #<displayId>` + 关闭 `×`；工具条可拖动（位置记在 `dsh` prefs，重开还原）；
- 尺寸按视频宽高比算（宽 170dp，高 140dp～420dp 之间），默认贴右侧、y=110dp；
- 窗口带 `FLAG_NOT_FOCUSABLE`，不抢输入法；画面本身可触摸，触摸坐标按视频尺寸映射后走 `controller.touchDown/Move/Up`
  （和 `VirtualScreenPage` 同一套映射）；
- `×` 只收起预览，**不销毁虚拟显示**（AI 还在用）；`VirtualScreenManager.stop()` /
  `close_all_virtual_displays` 时一起收起；
- 没有「显示在其他应用上层」权限时 `show()` 返回 false，工具结果里会带一句
  `Preview window needs the 'display over other apps' permission`，让模型去请用户授权。

### 触发点

- `AndroidDeviceTools.start_virtual_display` 成功后立刻 `VirtualScreenOverlay.show(app, displayId)`；
- `VirtualScreenPage` 打开时先 `hide()`：页面自己的 Surface 才是主画面（同一条视频流只能有一个
  `setBinaryHandler` 的接收者，两个 Surface 会互相抢）。

### 真机证据

`start_virtual_display(app=微信)` 真机跑通，屏幕上直接浮出预览窗（显示的是微信朋友圈/微信运动页），
AI 回复「虚拟屏已开」：`docs/shots/74-vs-overlay.png`。

## 二、提问/审批卡：可以取消选择、可以直接停

用户反馈：「长任务时模型自己中断提问，选错了预设答案没法取消，也没法换成别的回答 / 停掉」。

### 改动

1. **单选可取消**（`ChatScreen.AskUserDialog`）：单选选项再点一次 = 取消选择；
   以前选中后只能提交或跳过，选错就卡住。
2. **点外部/返回键 = 跳过**：以前 `onDismissRequest` 走 `submit()`，误触外部会把半截选择当答案发出去；
   现在等同「跳过」（空答案），不会误提交。
3. **新增「停止本轮」**：提问卡与审批卡都加了一个红色 `停止本轮`，直接 `onStop()`
   —— 不想回答、想换个问法/换个任务时不用先编一个答案。
4. **审批卡收尾修复**（`AppViewModel.awaitApproval`）：加 `try/finally` 清 `pendingApproval`；
   以前在审批挂起时点停止/切会话，审批卡会永远挂在聊天页上（`askUser` 有 finally，审批没有）。

### 真机证据

- `ask_user_question` 三个选项：选中「虚拟屏」→ 整行品牌底 + 「已选」+ 提交按钮变「提交（已选 1）」
  （`docs/shots/74-ask-selected.png`）；
- 再点一次同一项 → 取消选中，提交按钮回到「提交」（`docs/shots/74-ask-cleared.png`）；
- 点「停止本轮」→ 弹窗消失、`生成中` 结束、回到可发送状态（`docs/shots/74-ask-stopped.png`）。

## 三、没做 / 下一步

1. 审批卡的「停止本轮」没真机验（当前 `approval_mode=auto`，要临时切 `ask` 再造一个写工具调用）；
2. 预览窗与虚拟屏页面的画面互斥（开页面会把预览收掉）；Operit 的「自动化进度浮层 / 拖动缩放手势」还没搬；
