写原始输入、发 Ctrl+C。

## 二、6 个工具（名字/参数逐字对齐 Operit）

来源：`.thirdparty-src/Operit/.../SystemToolPromptsInternal.kt:57-173`
（实现：`.../core/tools/defaultTool/standard/StandardTerminalCommandExecutor.kt`）。

| 工具名 | 参数 | 行为（DSH 实现） |
|---|---|---|
| `create_terminal_session` | `session_name`(string, 必填) | 同名会话存在就复用，否则新建；返回 `session_id` / `is_new_session` / `state`。内部 `TerminalManager.createNewSession`（先 `initializeEnvironment()` 再起 PTY，等 READY，30s 上限） |
| `execute_in_terminal_session` | `session_id`(必填), `command`(必填), `timeout_ms`(默认 1800000) | 在会话里执行命令，收集完整输出；超时 → 发 Ctrl+C + `timed_out=true`；已进入交互模式 → 只写输入并立刻返回 |
| `execute_hidden_terminal_command` | `command`(必填), `executor_key`(默认 `default`), `timeout_ms`(默认 120000) | 隐藏的非 PTY 执行器，同 `executor_key` 复用同一登录上下文，不出现在终端页；返回真实 `exit_code` |
| `input_in_terminal_session` | `session_id`(必填), `input`/`control` 至少一个 | 写输入；`control` 支持 enter/tab/esc/up/down/left/right/home/end/pageup/pagedown/backspace/delete，`ctrl`+`input=c` 发 Ctrl+C，`alt`/`shift` 组合 |
| `close_terminal_session` | `session_id`(必填) | 关会话（不存在会报错并列出当前会话） |
| `get_terminal_session_screen` | `session_id`(必填) | 只取当前可见 PTY 屏幕（60×40 文本网格，不含 scrollback） |

## 三、落地实现（对照立项时的设计）

1. **模块补 2 个按 sessionId 写内核的方法**（原 `sendInput`/`sendInterruptSignal` 只作用于
   「终端页当前会话」，AI 写输入不能把用户正在看的会话切走）：
   ```kotlin
   fun sendInputToSession(sessionId: String, input: String): Boolean
   fun sendInterruptSignalToSession(sessionId: String): Boolean
   ```
   位置 `thirdparty/terminal/.../TerminalManager.kt`（包 `writeInputToKernel`；writer 没了返回 false）。
   第三方模块改动记录补在 docs/40 §2.2（第三处）。
2. **`TerminalTools.kt`**：6 个 `DshTool`，Android 实现；`:core:tools` 仍是纯 JVM，不依赖 Android 模块。
3. **注册**：`AppViewModel` 的 `registry = DefaultTools(32) + AndroidDeviceTools(12) + TerminalTools(6)`
   → 现在共 **50 个工具**；`PromptPack.androidApiTools()` 追加 schema，上层按 `registry.names` 过滤，
   注册了才进请求。
4. **schema**：`core/prompt/src/main/resources/prompt/0.2.2-rc.1/tools-android.json` 追加 6 条；
   描述里写清和 `bash` 的差别、timeout 默认值、交互式程序的正确打开方式。
5. **输出收集**：`commandExecutionEvents` 是**没有 replay** 的 SharedFlow —— 先
   `launch(start = CoroutineStart.UNDISPATCHED)` 订阅（立刻注册）再发命令；按 `commandId` 过滤，
   `isCompleted` 的 `outputChunk` 优先，逐行过程量只作兜底；`>30k` 取尾部。
6. **超时**：`withTimeoutOrNull(timeout_ms)` → `sendInterruptSignalToSession` → 再等 3s 落定，
   把 `^C` 之后的尾部输出一起返回（`timed_out: true`，不算工具错误）。
7. **多行命令**：PTY 一次喂多行时，bash 在第一条命令的提示符处就会触发「命令完成」，
   后续行输出会丢（`currentExecutingCommand` 已清空）。所以多行命令包成一行：
   `bash -c "$(printf %s '<base64>' | base64 -d)"`（cwd/环境不变，单行不动）。
8. **`clear` 特例**：`TerminalManager` 对 `clear` 不建命令历史、不发完成事件；工具写完直接返回
   `(screen cleared)`，否则会干等到 timeout。
9. **交互式程序的正确用法**（重要）：静默等输入的程序（`cat`）在**写入之前**检测不到 interactive
   （PTY 输出为空，`OutputProcessor` 不会判交互）。推荐：
   `input_in_terminal_session(session_id, input="cat", control="enter")` 启动 → `get_terminal_session_screen`
   看屏幕 → `input_in_terminal_session` 发内容/回车/Ctrl+D；这样不会阻塞。
   `execute_in_terminal_session` 只在**已经**进入交互模式时（比如程序先打印了提示符）才只写输入返回。
10. **调试入口**（仅 debug 包）：
    - `--ez dsh_terminal_selftest true`：不经过模型，按 registry 直接跑 17 项检查，
      结果写 `filesDir/terminal-selftest.log` + logcat `DshTerminal`；
    - 加 `--ez dsh_terminal_selftest_keep true`：跑完不关会话，并落到终端页（截图用）。

## 五、已知限制

1. **会话只在内存**：进程被杀/重启后 PTY 和会话都没了（与 Operit 一致，不持久化）。
2. **首次创建上限 30s**：rootfs 没展开/第一次初始化时 `createNewSession` 可能超时；工具会报错让模型
   稍后重试。本机 rootfs 在 2026-11-07 已展开，实测 5.1s。
3. **单条命令输出上限**：`OutputProcessor` 每 10 行一页、最多 100 页（1000 行）；工具再截 30k 尾部。
4. **屏幕网格 60×40**：终端页没打开时对 AI 的会话 emulator 用默认尺寸；打开终端页后按画布 resize，
   AI 读到的行列会变。屏幕内容只取可见区，不含 scrollback。
5. **静默交互程序**：见 §三.9；`execute_in_terminal_session` 直接跑 `cat` 会等 timeout（跟 Operit 一样），
   用 `input_in_terminal_session` 启动。
6. **多行命令语义**：走 `bash -c "..."`，cwd/环境变量保留，但 `$0`/位置参数与逐行敲不同；
   heredoc 可以正常用。
7. **审批**：终端工具和 `bash` 一样走工具审批（`ask` 模式下会弹审批卡，`auto` 模式直接执行）。
8. **`execute_hidden_terminal_command` 与 PTY 会话是两套 shell**：隐藏执行器里的 `cd` 不会影响
   `create_terminal_session` 的会话，反之亦然。
