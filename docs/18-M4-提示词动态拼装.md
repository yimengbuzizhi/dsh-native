# 18 · M4：system 提示词动态拼装（契约 #1）

> 2026-11-07｜基线 `3f6549f`。上一篇 `17-M3` 的「下一步 1」已完成。

## 一、问题

之前直接发 `system.txt`（桌面 19 段快照），里面写着 `web_search` / `create_goal` / `workflow` / 子代理 / 桌面 Web GUI 等
**我们没实现的工具与不存在的运行环境**。模型因此说「这个会话没有 bash 工具」「我有 web_search」，行为被污染。

## 二、做法（照上游 `dsh-system-prompt` 的 assemble 规则）

1. 新增资源 `core/prompt/src/main/resources/prompt/0.2.2-rc.1/sections.json`：
   把 `system.txt` 的 18 个段落还原成 `{name, order, requires(工具名|null), platform(any|android|desktop), text}`，
   并补一段 Android 专用的 `tool:bash`（order 1000，文本逐字来自 `dsh-tool-bash/lib/index.js` 的 section 注册）。
2. `PromptPack.systemFor(model, provider, tools, platform)`：
   - 过滤 `platform` 与 `requires`（工具不在当前注册表就整段丢弃）；
   - 按 `order` 升序、同 order 按 `name` 码元序；
   - `{{model}}` / `{{provider}}` 插值；
   - 空段丢弃，`join("\n\n")`，无结尾换行（与上游 `renderPrompt()` 一致）。
3. `AppViewModel.buildRequest` 改用 `systemFor(...)`，tools 用 `androidApiTools()` 同一份名字集合。

## 三、验证（可重复）

`core/prompt` 新增 JVM 测试 `SystemAssemblyTest`：

- `desktopSnapshotRoundTrips`：用 sections.json 按 **desktop + 全部 32 工具** 拼回来，必须与 `system.txt` **逐字节相同**；
- `androidSystemDropsUnimplementedTools`：Android 工具集拼出的 system 里不能出现 web/goal/workflow/subagent/桌面 GUI 段；
- `personaUsesRuntimeModel`：`{{model}}` 正确插值。

结果：`:core:prompt:test` BUILD SUCCESSFUL（3 项全过）。
真机：问「你当前有哪些工具」，模型准确回答 `read/write/edit/glob/grep/bash/todo_write` 7 个（见 `docs/shots/m4-tools-list.png`）。

## 四、遗留

1. 段落文本里仍有工具配置数字（read=2000 行、glob=100、grep=250）是硬编码在文本里的，当前与默认 caps 一致；
   等做设置项时再参数化。
2. 运行时上下文（cwd/时间/沙箱/平台）按文档是**独立 user 消息**（docs/port/02 §2.5），本轮未做；
   下一轮补 `Current runtime context...` 那条。
3. `tool:schedule` / `tool:apply_patch` 段在 0.2.2 新增，我们没实现对应工具，暂不打包。
