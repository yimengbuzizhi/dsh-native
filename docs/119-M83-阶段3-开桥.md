## 一、开了哪两个原语

### 1. OCR（`ctx.whale.ocr(path)`）
- 引擎：**ML Kit 中文 + 拉丁**，本来就在 APK 里（屏幕圈选 OCR `OcrEngine` 用的同一套）。
- 权限门：`device`（危险能力，插件页逐项确认）；图片路径再过 `fs` 授权
  （`fs:workspace` 只能读工作区里的图）。
- 宿主实现：`AndroidPluginHostBridge.ocrRecognize`（>2000px 先缩放防 OOM）；core 侧只在
  `PluginSandbox.ocr()` 做权限 + 路径校验，转发绝对路径。
- 返回：`{ ok, text, chars, image }`。

### 2. zstd 压缩/解压（`ctx.whale.zstd({mode, path, out?, level?})`）
- 库：`com.github.luben:zstd-jni`，本来就在 APK 里（会话存储用），这次开给插件。
- 权限门：`fs`（`fs:workspace` / `fs:any`）；输入/输出路径都走 `PluginSandbox.fsFile` 的
  canonical 越界检查；输入输出同一文件会被拒绝。
- 宿主实现：`AndroidPluginHostBridge.zstd`，流式 `ZstdInputStream` / `ZstdOutputStream`（不需要预知原文大小）。
- 返回：`{ ok, mode, in, out, outPath, ms }`。

## 三、限制 / 说明

- OCR 走 ML Kit 同步等待（插件 JS 线程），大图已缩放；非常慢的图会让该次工具调用变长（工具超时仍生效）。
- zstd 走 App 进程内存流式处理；超大文件（>几百 MB）不在本阶段支持范围。
- 这两个原语是「宿主能力」而非 JS 库：插件不需要自带 .so，也不会因为 ABI 缺失失效。
