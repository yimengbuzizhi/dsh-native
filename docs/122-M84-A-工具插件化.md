## 一、做了什么

`BuiltinPlugins.all` 从 2 条扩到 **13 条**（12 个工具组 + 1 个记忆库页面）：

| 内置插件 id | 名称 | 工具（关掉后 `tools[]` 少这些） |
| --- | --- | --- |
| `builtin.fs` | 文件读写 | read, read_image, write, edit, glob, grep (6) |
| `builtin.shell` | 命令与目录 | bash, working_directory (2) |
| `builtin.jobs` | 后台任务 | job_output, job_list, job_kill (3) |
| `builtin.web` | 联网 | web_fetch, web_search (2) |
| `builtin.agent` | 子代理 | subagent, subagent_fork, list_agents, send_message, interrupt_agent (5) |
| `builtin.schedule` | 定时提醒 | schedule_create/list/update/delete (4) |
| `builtin.goal` | 目标 | get_goal, create_goal, update_goal (3) |
| `builtin.plan` | 计划模式 | exit_plan_mode (1) |
| `builtin.interaction` | 交互 | ask_user_question, present (2) |
| `builtin.todo` | 待办事项 | todo_write (1) |
| `builtin.skill` | 技能 | skill (1) |
| `builtin.workflow` | 工作流与工作区依赖 | workflow, load_workspace_dependencies (2) |
| `builtin.memory` | 记忆库 | （页面：Memory） |

32 个内置工具全部覆盖，**每个工具恰好归属一组**（`BuiltinPlugins.duplicateTools()` 返回空）。

请求侧没有改代码路径：`offeredToolNames()`（`AppViewModel`）本来就是
`registry.names.filter { builtinStore.toolEnabled(it) }`，而请求构造里
`tools = offeredToolNames()`（聊天与子代理两处）——所以插件页的开关直接决定 `tools[]`。

**A2 已把实例注册也交给插件分组**：`core:tools/BuiltinToolCatalog.kt` 按同样的 12 个 id
提供工具实例；`DefaultTools.kt` 已删除。`AppViewModel.syncBuiltinTools()` 在启动和每次开关时：
开着的组 `registry.register(...)`，关掉的组 `registry.unregister(...)`——
关掉后 `registry.names` 里也没有这些工具，不只是请求侧过滤。
`core:tools` 新增 `BuiltinToolCatalogTest`（32 个、无重复、12 个稳定 id），
`AgentToolsTest`/`ScheduleToolsTest` 改从 catalog 取名。

## 四、限制 / 未做

- **工具仍是 Kotlin 类**，不是 JS 插件：A2 只是把「实例归属 + 注册/注销」交给内置插件组；
  内置插件还不能自带 `dsh.client` 或 JS 实现（那是 `docs/115 §E`）。
- 关组会 `unregister`：如果恰好在工具执行中关掉该组，执行中的调用拿的是已取出的实例，不受影响；
  但同一轮后续再调该工具会得到 `unknown tool`。正常使用不会在 turn 中开关。
- 逐组对拍用 `offeredToolNames()`/`registry.names()` 落盘；**没有为每组都抓真实 HTTP 请求体**——
  真实请求的 123→122 差异已在阶段 2 用 `todo_write` 验过（`docs/118`）。
- 页面插件化（B）仍未做：只有 Memory 一个页面是内置插件；`Screen`/`SubScreen` 枚举还在。
