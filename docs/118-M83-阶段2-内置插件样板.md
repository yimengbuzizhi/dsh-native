## 一、做了什么

### 1. 内置插件登记（`app/.../data/BuiltinPlugins.kt`，新文件）
- `BuiltinPlugin(id, name, description, tools, screens, defaultEnabled)`：
  一个「内置插件」可以贡献**工具名**和/或**一级页面名**（`Screen.name`）。
- `BuiltinPluginStore`：开关存 `dsh` prefs 的 `builtin_plugins_disabled`（关掉的 id 集合），重启保持。
  和导入插件的 `files/plugins.json` 分开：内置插件没有目录、没有权限确认。
- 本阶段样板两条：
  - `builtin.todo` → 贡献 `todo_write` 工具；
  - `builtin.memory` → 贡献 `Memory` 页面。

### 2. 开关生效点
- **工具**：`AppViewModel.offeredToolNames()` 过滤掉被关掉的内置工具 → 不进请求 `tools[]`
  （`toolCount` 也跟着变）；模型看不到就调不到。
- **页面**：`go()` / `goFromChat()` 进页前检查 `vm.builtinScreenEnabled(name)`；
  `App.kt` 里恢复出来的旧路由落在被关页面会退回聊天；
  设置页「功能与工具」里记忆库入口按开关隐藏；聊天页记忆入口同样加守卫。
- **插件页**：「内置插件」区从静态 3 行改为真开关（待办事项 / 记忆库），
  下面仍保留 聊天 / 会话 / 设置与主题 三条「核心，不可关」。

## 三、说明 / 限制

- 这一层的「插件化」是**登记 + 可开关**：工具仍是 Kotlin 实现、页面仍是 Compose 路由，
  关掉只是不让它进模型工具表 / 不出现入口。真正搬到 JS 插件（`docs/115 §A/B`）时，
  沿用同一套 `builtin.*` id 与开关语义即可平滑迁移（`BuiltinPlugins.byId`）。
- 关掉工具后，历史请求里已经有它的 `tool_use` 也没关系：没有新请求带 schema，模型不会再调；
  本轮里如果模型正好在关掉的瞬间调用，注册表仍能执行（不影响正确性）。
- 目前只样板了 1 工具 + 1 页面；其余 31 个工具 / 19 个页面列在 `docs/115 §A/B`，按同模式继续搬。
