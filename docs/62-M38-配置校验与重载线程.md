## 一、一句话结果

- `PluginSchema.validate` 新增：
  - **string `pattern`**：按 JSON Schema 语义做「包含匹配」，不匹配报「xx 不匹配格式：<正则>」；
  - **array `minItems` / `maxItems`**：报「xx 至少 N 项 / 最多 N 项」；
  - **坏正则（如 `(`）直接忽略**，不因为 schema 写错拒掉合法值；
- 插件详情 → 配置 → 字符串项编辑弹窗：显示「格式：<正则>」和长度提示，保存前先挡一次
  （和数字项的范围提示一致；宿主 `validate` 仍是最后一道）；
- **插件重新加载改到 IO 线程**（UI 的「重新加载」和调试通道都一样）：重载要起 QuickJS 跑试运行
  （最长 12 秒），以前在 `viewModelScope.launch` 的 Main 上跑，会卡界面；
- 单测：`:core:plugins` 74 → **75 条**全过（新增 pattern/数组长度 1 条，覆盖坏正则忽略）。

## 二、实现

| 层 | 文件 | 改动 |
|---|---|---|
| `:core:plugins` | `PluginSchema.kt` | `validateValue`：string 加 `pattern`（`Regex.containsMatchIn`，编译失败忽略）；array 加 `minItems`/`maxItems` |
| App | `PluginsScreen.kt` | `ConfigEditDialog` 的字符串分支：显示 `格式：…` / 长度提示，保存前校验 pattern/长度，错误红字 |
| App | `AppViewModel.kt` | `reloadPlugin` 与调试通道 `dsh_plugin_reload`：`withContext(Dispatchers.IO) { pluginStore.reload(...) }` |

为什么 pattern 用「包含匹配」而不是整串匹配：JSON Schema 的 `pattern` 本来就是 `RegExp.test` 语义；
要整串匹配，schema 作者自己写 `^…$`（fixture 就是这么写的）。
为什么坏正则忽略而不是报错：schema 是插件作者写的，宿主只负责「明显不对的值」，不把一个写坏的
schema 变成「所有值都不合法」。真要提示，留给插件页试运行的警告去说。

## 五、边界（诚实清单）

- `pattern` 用 Kotlin/JVM 正则：ECMA 里少数写法（如 `\p{Script=…}`、命名分组语法）可能有差异；
  常见 `^[A-Z]{2}-\d{3}$` 这种没问题；
- **数组仍然在「JSON 文本框」里编辑**（没有逐项编辑器），所以 `minItems`/`maxItems` 只在保存时挡；
- pattern/长度提示只加在**字符串单项编辑弹窗**；列表页不显示格式；
- `uniqueItems`、`format`（email/uri 等）仍未做；
- **没有 UI 截图**：配置弹窗的「格式：…」提示只有编译保证，解锁后要和配置区截图一起补；
- 重载移出主线程是行为修复，不影响功能；QuickJS 仍是「每次重载一个新实例」。
