# 123 · M84-B：页面插件化——22 个页面由内置插件提供、逐页可关

> 2026-11-13 19:1x。目标来自 `docs/115 §B`：11 个一级页 + 9 个二级页（外加 M83 的「远程 DSH」、
> 本批补成整页的「关于」）→ **删除 `Screen` / `SubScreen` 枚举，页面由插件清单提供**；
> 关掉某页入口消失、直接路由被拦回；导航/转场不退化。
> 证据：`docs/m84b-check.json`（真机 142/142 PASS）、`docs/shots/123-01…123-20`。

## 一、做了什么

### 1. 枚举删除，页面清单接管路由

- 删除 `ui/App.kt` 里的 `enum class Screen` 与 `enum class SubScreen`。
- 新增 `data/BuiltinPageIds.kt`：22 个稳定路由 id（沿用旧枚举常量名，旧路由快照/旧验收命令不用改）。
- 新增 `ui/pages/BuiltinPages.kt`：`BuiltinPage(id/title/icon/level)` 目录 + `byId/find`；
  页面归属插件从 `BuiltinPlugins.screens` 反查（`pluginId == null` = 宿主核心页）。
- `App.kt` 的路由状态仍是字符串 id（`NavRoute(page, sub)`），`when (page?.id)` 查内容；
  `go()/goFromChat()/openSub()` 统一检查 `vm.builtinScreenEnabled(id)`，调试通道也走同一入口。
- `AnimatedContent` 的转场、`depth`、`pageFromChat`/`navForward`、系统返回键语义全部保留（M79）。

### 2. 22 个页面 + 22 个内置插件

`BuiltinPlugins.all` 从 13 条扩到 **22 条**（12 个工具组 + 10 个页面组），新增 `kind` 区分，
插件页分成「工具插件 / 页面插件」两段展示（页面组数量在标题里现算，不写死）。

| 内置插件 | 类型 | 提供的页面 |
| --- | --- | --- |
| `builtin.fs` | 工具 | Workspace（工作区） |
| `builtin.shell` | 工具 | Terminal（终端） |
| `builtin.jobs` | 工具 | Jobs（任务） |
| `builtin.agent` | 工具 | Agents（子代理） |
| `builtin.skill` | 工具 | Skills（技能） |
| `builtin.memory` | 页面 | Memory（记忆库） |
| `builtin.page.sessions` | 页面 | Sessions（会话列表） |
| `builtin.page.workspaces` | 页面 | Workspaces（工作区管理） |
| `builtin.page.device` | 页面 | VirtualScreen / Accessibility / Permissions |
| `builtin.page.packages` | 页面 | Packages（包管理） |
| `builtin.page.model` | 页面 | ModelConfig（模型配置） |
| `builtin.page.assistant` | 页面 | Assistant / Behavior |
| `builtin.page.data` | 页面 | Backup / DataMigration / Privacy |
| `builtin.page.remote` | 页面 | RemoteDsh（远程 DSH） |
| `builtin.page.about` | 页面 | About（关于，本批从弹窗改成整页） |

**核心页**（`pluginId == null`，没有开关）：`Plugins`（插件管理）、`Settings`（设置）。
理由：`docs/115` 终点①「所有插件关掉后 App 还能打开到插件管理」——这两个入口必须一直在。
聊天是抽屉/落地页，不是 `Screen`，不受影响。

22 个页面 = 11 一级（Sessions/Workspace/Agents/Jobs/Terminal/VirtualScreen/Accessibility/Plugins/Packages/Memory/Settings）
+ 11 二级（ModelConfig/Assistant/Behavior/Backup/DataMigration/Skills/Workspaces/Permissions/Privacy/RemoteDsh/About）。

### 3. 入口过滤（不是只拦路由）

- **设置页**：每一行都按 `screenEnabled(pageId)` 过滤；一个分组里的入口全关掉时整张卡片不显示
  （不留空壳）。`功能与工具` 里补了一个原先没有入口的「技能」行（`onOpenSkills` 之前是死参数）。
- **抽屉**：会话页关掉时，「会话」标题右侧的「全部会话」图标隐藏；底部「设置 / 插件」是核心页。
- **聊天页**：工作区图标、输入条设置里的记忆库组、模型配置入口、工具卡的「查看后台任务」链接
  都按对应页面插件开关隐藏。
- **路由**：`go()/goFromChat()/openSub()` + `LaunchedEffect(screenName/subScreenName)` 双层拦截；
  `--es dsh_open_screen <被关页面>` 也进不去。

### 4. 一个真 bug：开关改了入口不刷新

验收时发现：停留在设置页，用调试/将来的页内开关关掉页面插件，设置页不重组（`screenEnabled`
只读了 SharedPreferences，不是 Compose 快照）。已在 `AppViewModel.builtinScreenEnabled()` 里
读一次 `builtinPluginsUi.size` 建立快照依赖：开关状态一变，设置页/抽屉/聊天入口立即重组。
截图 `123-12`（关设备页后设置页立即只剩非设备入口）即修复后表现。

## 二、验收通道（仅 debug 包）

`MainActivity` 新增/调整（同进程 `am start -f 0x20000000` 走 `onNewIntent`，不冷启）：

```
--es dsh_dump_pages /data/user/0/xin.dshaa.nativeapp/files/pages-<n>.json
--es dsh_open_screen <页面 id|标题|idScreen|chat|home>   # 页面路由；chat/home 回聊天
--es dsh_builtin_off/on/reset ...                         # 沿用 M84-A
```

`dsh_open_screen` 不再触发 `recreate()`（从 `DEBUG_EXTRAS` 移除），直接在 VM 里请求路由；
`App.kt` 在路由变化时打 `DshPage` 日志：`route page=Settings sub=ModelConfig`，
关掉的页面不会产生日志 —— 验收脚本以此判断「被拦回」。

`dsh_dump_pages` 落盘：
`{pages:[{id,title,level,plugin,core,enabled}], unknown:[], duplicates:[], catalogMatch:true,
unowned:["Plugins","Settings"], disabled:[]}`。
`catalogMatch` = 目录 22 个 id 与 `BuiltinPageIds.all` 完全一致；`unowned` 只能有两个核心页。

## 三、真机验收（OPPO A55 5G，720×1600，Android 13）

脚本 `tools/m84b-page-check.py` 自动跑完 15 个提供页面的插件（6 个工具组 + 9 个页面组），
每一步都落 `docs/m84b-check.json`。**142/142 PASS**：

| 检查 | 结果 |
| --- | --- |
| 基线页面清单 | 22 页；`unknown=[]`；`duplicates=[]`；`catalogMatch=true`；`unowned=[Plugins, Settings]` |
| 每个插件关掉后 | `disabled=[该 id]`；它提供的页面全部 `enabled=false`；其它页不变 |
| 设置页入口 | 逐个滚到底扫描，该插件提供的**每一行入口文字都消失** |
| 直接路由 | 回聊天 → 清 logcat → `dsh_open_screen <页>` → **没有该页的 `DshPage` 路由日志** |
| 打开插件后 | 页面 `enabled=true`；逐页打开，路由日志落在 `page=<id>` / `page=Settings sub=<id>` |
| 最终 reset | 22 页全开、`disabled=[]` |

覆盖的页面（20 个可关页全部）：Workspace、Terminal、Jobs、Agents、Skills、Memory、Sessions、
Workspaces、VirtualScreen、Accessibility、Permissions、Packages、ModelConfig、Assistant、Behavior、
Backup、DataMigration、Privacy、RemoteDsh、About。

**空壳（全部页面/工具插件关掉）**：`dsh_builtin_off` 22 个 id → dump `disabled=22`、`core=2`、`enabled=2`；
冷启动仍落到聊天，`--es dsh_open_screen Plugins` / `Settings` 正常，`Terminal` 无路由日志。

## 四、限制 / 未做

- **页面内容仍是 Kotlin/Compose**，不是 JS 插件：本批交付的是「id/标题/图标/层级/归属插件 + 开关 +
  路由查表」，`App.kt` 的内容 `when` 相当于 A2 的 `BuiltinToolCatalog`（内容登记表）。真正由插件
  自带 `dsh.client`/JS 页面替换，按 `docs/115 §E`。
- 部分页面插件是**组级**开关：`页面：设备`（3 页）、`页面：数据`（3 页）、`页面：助手与行为`（2 页）
  一次关一组；验收按「组内每一页入口都消失」确认。要一页一插件可以再拆。
- 设置页的**行标题/副标题/分组仍写在 `SettingsScreen`**（id 和 enabled 来自页面清单）；
  完全由插件清单生成设置行（含副标题/角标）未做。
- `Plugins`/`Settings` 故意不可关（空壳终点要求）；插件页/设置页之外的「核心」聊天也没有页面 id。
- 宽屏常驻抽屉（>=600dp）本批未再截图验证；转场与返回栈已验，代码未动宽屏分支。
- 未做真实 HTTP 请求/工具调用：本批只验页面路由与开关，工具侧沿用 A 的 12 组验收。
