## 一、做了什么

### 1. JS API 不再返回 unsupported

`core/plugins/PluginModule.kt` 的试运行 prelude：

```js
systemPrompt: {
  ...
  suppressRuntimeContext: function() {
    __dsh.suppressRuntimeContext = true;
    return __noop;
  }
}
```

- 调用一次就置位，重复调用无害；
- 试运行结果 `__dsh` 新增 `suppressRuntimeContext` 字段，`parseDryRun` 解析成
  `PluginDryRun.suppressRuntimeContext`；
- 旧插件/旧试运行结果没有该字段 → 按 `false` 读（有单测锁）。

### 2. 记录与持久化

- `PluginRecord.suppressRuntimeContext` 进 `plugins.json`（只写 true，节省空间）；
- 安装（`PluginStore.install`）、重载（`PluginReload.apply`）、热重载（`PluginStore.reload`）
  三条路径都带上这个字段，不会因为重载丢标记；
- 插件页能力清单 `prompt.suppressRuntimeContext` 从「未实现」改为「已实现」，
  `PluginCapabilities.VERSION` 从 `m83.2` → `m84.1`（真机 21/26 → 22/26）。

### 3. 宿主侧消费

`AppViewModel.runtimeContextText()`：

- 任一**启用中**插件 `suppressRuntimeContext == true` → 宿主的 runtime context 快照
  （`Current runtime context…` / cwd / 文件策略 / 审批策略 / 子代理深度说明）整段不注入；
- 插件自己的 `ctx.systemPrompt.context` 是另一类贡献，**仍照常注入**（在快照末尾）；
- 两者都没有时返回空串，请求里不会出现空的 user 消息（与原来「插件 context 为空不追加」一致）。

注意：手机端没有常驻 JS 运行时，标记是 **apply 时快照**；JS 在运行期动态开关不会立刻生效，
需要重载插件。这与 `ctx.systemPrompt.context` 的既有语义一致。

## 二、真机验收（OPPO A55 5G）

演示插件 `suppress-runtime-demo`（`--es dsh_plugin_zip` 导入，1 个工具 + 1 个 context）：

```js
export function apply(ctx) {
  ctx.systemPrompt.suppressRuntimeContext();
  ctx.systemPrompt.context({ name: 'suppress-demo-context', order: 10,
    text: 'SUPPRESS_DEMO_PLUGIN_CONTEXT（插件自己的 context 仍在）' });
  ctx.tools.register({ name: 'suppress_demo_ping', ... });
}
```

同一 debug 供应商（`debug.echo`）冷启各抓一次请求体：

| 抓包 | runtime context | 插件 context | `suppress_demo_ping` | `tools` |
| --- | --- | --- | --- | --- |
| 插件关（`m84e1-before.json`） | **有** | 无 | 不在 | **126** |
| 插件开（`m84e1-after.json`） | **无** | **有** | **在** | **127** |

- 插件页开关 ON/OFF 立即生效（截图 `127-01`：`suppress-runtime-demo` 已启用、1 个工具已接入）；
- 能力清单显示 `m84.1 · 22/26 已实现`，`抑制运行时上下文` 一条为「已实现」并带说明（截图 `127-02`）；
- `plugins.json` 记录里可见 `"suppressRuntimeContext":true`（重载/重启后仍生效）。

## 三、限制 / 未做

- **只有 apply 时快照**：没有常驻 JS 运行时，插件不能在轮次之间动态开关抑制；改状态要重载插件。
- 抑制的是**宿主那段** runtime context；插件自己的 `systemPrompt.context` 不受影响（这是 DSH 的语义拆分）。
- 只做了这一个原语。E 其余项仍未实现：
  - `ctx.llm.register`（自定义供应商 stream 回调需要持久 JS 运行时 + 事件回传协议）；
  - `ctx.ui.registerRoute/registerView`（宿主页面路由/视图注册）；
  - `ctx.sessionProjections.register`（每事件回调）；
  - Node 内置模块子集已有基础（path/fs/url/http/https/os/child_process/timers/events 等），未做社区插件矩阵验收。
- 真机演示插件留在设备上（`suppress-runtime-demo`，已停用），供 E2 继续用。
- 本批未发版。
