# 124 · M84-C1：内核服务化（一）——模型供应商与提示词可替换

> 2026-11-13 19:2x。目标来自 `docs/115 §C` 的前两项：
> 提示词 `PromptPack` 可替换（段/排序/变量/最终 transform）、模型客户端 `LlmClient/OpenAiClient`
> → `llm.register` 可加供应商，验收「换一个提示词实现抓包 system 变了；换一个供应商能真跑一轮」。
> 证据：`docs/m84c-check.json`、截图 `docs/shots/124-04-debug-turn.png`、`124-05-real-provider.png`。

## 一、做了什么

### 1. 模型供应商注册表（core:llm）

新增 `core/llm/LlmProvider.kt`：

```kotlin
interface LlmProvider {
    val id: String
    val label: String
    fun stream(request: ApiRequest, config: LlmConfig): Flow<LlmEvent>
}
object LlmProviders {
    fun register(provider: LlmProvider): LlmProvider?   // 同 id 覆盖 = 替换
    fun unregister(id: String): LlmProvider?
    fun get(id: String?): LlmProvider?
    var activeId: String?
    fun ids(): List<String>
}
```

`AppViewModel` 启动时注册两条内置通道：

| id | 实现 | 用途 |
| --- | --- | --- |
| `deepseek` | `LlmClient`（Anthropic Messages） | 默认 |
| `openai` | `OpenAiClient`（OpenAI chat/completions） | `settings.protocol == "openai"` |

请求出口统一收口到 `AppViewModel.llmStream()`：

```
debug provider（仅 debug） > LlmProviders[settings.protocol 对应的 id] > 内置客户端兜底
```

主会话 `buildEngine()`、子代理 `childEngine`、设置页「测试连接」三处全部走 `llmStream()`；
原来子代理写死 `client.stream(...)`、测试连接写死 `if (protocol)`、主会话写死 if/else 的三份分支都删了。
`TurnEngine` 只看到 `EngineDeps.stream`，换供应商不需要改引擎。

### 2. 提示词实现注册表（core:prompt）

新增 `core/prompt/PromptProvider.kt`：

```kotlin
interface PromptProvider {
    val id: String
    val label: String
    fun system(pack: PromptPack, request: PromptRequest): String
}
data class PromptRequest(model, provider, tools, platform, planMode,
                         personaPrefix, personaSuffix, extraSections, variables)
object PromptProviders { register/unregister/get/activeId/build(...) }
```

`PromptProviders.build()`：有 active 实现就调它，否则回落到 `PromptPack.systemFor(...)`（默认实现）。
`AppViewModel` 主会话与子代理的 `systemPrompt` 都改成 `PromptProviders.build(...)`；
默认实现的参数与原来逐一对应（`planMode` / 角色卡 / 插件段 / 插件变量），请求字节不变。

### 3. 验收通道（仅 debug）

`MainActivity` / `AppViewModel` 新增：

```
--es dsh_llm_provider debug.echo|off
--es dsh_prompt_override <标记>|off
--es dsh_dump_providers <绝对路径>
```

- `DebugEchoLlmProvider`（id `debug.echo`）：不联网，按 `LlmEvent` 协议吐一轮
  `MessageStart / BlockStart / TextDelta / BlockStop / MessageDelta(12) / MessageStop`，
  走完整 TurnEngine 路径（不是绕过引擎直接改 UI）。
- `DebugPromptProvider`（id `debug.prompt`）：先跑默认 `PromptPack.systemFor(...)`，末尾追加标记。
- `dsh_dump_providers` 落盘 `{"llm":[ids],"llmActive":"","prompt":[ids],"promptActive":""}`。
- `off` 清掉调试实现、恢复默认；provider/prompt 值写进 prefs，冷启动也能恢复（仅 debug）。

## 二、真机验收（OPPO A55 5G）

### 1. 提示词替换：抓包 system 确实变了（只多了标记）

同一进程冷启动，带：
`--es dsh_llm_provider debug.echo --es dsh_prompt_override M84C_PROMPT_MARKER
--es dsh_dump_request <files>/request-c1b.json --es dsh_send ping`

落盘的请求：

| 项 | 默认（off） | 替换（debug.prompt） |
| --- | --- | --- |
| `system` 长度 | **5147** | **5167** |
| 差值 | — | **20**（`M84C_PROMPT_MARKER` 18 + 两个换行） |
| `system` 里标记位置 | 无 | 5149（末尾） |
| `model` / `messages` / `tools` | deepseek-flash / 1 / 126 | 同左 |

即：默认拼装逐字未变，`PromptProvider` 的 transform 只在末尾追加。
（`request-real.json` 是恢复默认后真实请求的抓包，`system_len=5147`、无标记。）

### 2. 供应商替换：debug 供应商真跑完整一轮

- `dsh_llm_provider debug.echo` → 发 `ping`：
  聊天页出现用户 `ping`、助手 **「来自 debug 供应商的一轮（M84-C 验收）」**、用量 **0 in / 12 out**，
  会话落盘、轮次结束、状态条复位（截图 `124-04`）。
- 该轮同时抓到了请求体（system/126 tools/1 message）——证明请求仍由 TurnEngine 组装，
  只是 `stream` 换成了注册表里的 `debug.echo`。
- 注册表 dump（替换时）：
  `{"llm":["debug.echo","deepseek","openai"],"llmActive":"debug.echo","prompt":["debug.prompt"],"promptActive":"debug.prompt"}`
- `--es dsh_llm_provider off --es dsh_prompt_override off` 后：
  `{"llm":[…同上…],"llmActive":"","prompt":[],"promptActive":""}`（恢复默认，prompt 实现已注销）。

### 3. 默认路径没退化：真实 DeepSeek 跑一轮

`off` 之后冷启动发 `ping`（不指定调试 provider）：真实 API 返回完整回答
（思考 391 字 + 正文，**19131 in / 197 out**），截图 `124-05`。说明注册表兜底路径正常。

## 三、限制 / 未做

- **还没有 UI 选择供应商**：目前只注册 `deepseek` / `openai` 两条 + debug 覆盖；设置页模型配置里
  没有「供应商通道」下拉。要做用户可用的第三方供应商，需要「配置 + 注册 + 选择」三件套（下一步）。
- **JS 插件的 `ctx.llm.register` 仍未实现**（`PluginServices` 里标记 `implemented=false`）：
  本批只完成内核注册表与宿主替换；插件侧 API 按 `docs/115 §E` 接。
- **提示词只替换 system 拼装**：runtime context、`contexts`（user 快照）、命令/技能注入仍走原路径；
  「最终 transform」目前只能包默认实现（DebugPromptProvider 就是这么做的），没有单独 `transform` 钩子。
- **TurnEngine 的 step/工具前后钩子、SessionRepository 可替换尚未做**（C2）：
  本批只以 `stream`/`systemPrompt` 两个函数作为引擎边界完成替换，引擎内部循环还没有钩子。
- 真实供应商只验了默认 DeepSeek 一轮；OpenAI 协议通道未在本批重验（A2 之前的旧路径，改动只是收口）。
- 调试 provider/prompt 只在 debug 包注册；release 里 `DebugProviders.install(..., debug=false)` 直接返回。
