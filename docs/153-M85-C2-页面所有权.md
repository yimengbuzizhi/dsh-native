# 153 · M85-C2：页面所有权迁进 native UI 插件（宿主不再有页面清单）

> 2026-11-14 00:2x。设计基线 `docs/144` §5/§8 + 2026-11-13 23:4x 澄清；
> 上一片 `docs/152`（C1：`shell/v1` 契约 + 内置界面插件）。这一片做 `docs/152` §3 的第 1 条：
> **22 页的清单 + 渲染 dispatch 从宿主搬进 `builtin.shell.native`，宿主只认契约**。
> 真机：OPPO A55 5G（PEMM00 / 720×1600 / Android 13），无线调试 `192.0.2.10:45111`。

---

## 1. 这一片做了什么

### 1.1 页面清单与渲染 dispatch 归壳

搬走（宿主 → 壳）：

| 之前 | 现在 |
|---|---|
| `ui/pages/BuiltinPages.kt`（22 页标题/图标/层级 + 归属插件 + 校验） | `ui/shell/native/pages/NativePages.kt`（`NativePage` + `NativePages`，标题/图标/层级；22 行内容原样） |
| `NativeShellRoot.kt` 里 `AnimatedContent` 内的 `when (page?.id)` 大块（约 300 行页面渲染） | `ui/shell/native/pages/NativePageDispatch.kt`（`NativePageDispatch(vm, pageId, subId, nav)`） |
| 页面里的路由状态setter（`screenName`/`subScreenName`/`navForward`）直接散落在每个页面 lambda | `NativeNav`（`openDrawer`/`toChat`/`go`/`goFromChat`/`openSub`/`closeSub`/`backFromPage`/`settingsScroll`/`wideLayout`），路由状态仍只在 `NativeShellContent` 里 |

`NativeShellContent` 现在只留：路由快照 `NavRoute`、抽屉、转场动画、返回键、调试通道、
宽屏常驻抽屉；页面内容一律交给 `NativePageDispatch`。

### 1.2 `page/v1` 雏形：壳声明页面，宿主拿元数据

`ui/shell/NativeShell.kt`（`shell/v1` 契约）新增：

```kotlin
interface NativeShell {
    val id: String
    val label: String
    /** 壳声明的页面（只有 id/标题/层级；图标和渲染留在壳里）。 */
    val pages: List<ShellPage>
    /** `dsh_open_screen` 的宽松匹配由壳解释。 */
    fun findPage(requested: String): ShellPage?
    @Composable fun Root(vm: AppViewModel)
}
```

- `PageLevel` / `ShellPage` / `ShellPageRegistry` 在 **`ui/shell/ShellPages.kt`**：
  registry 只做 `declared()`（来自 `NativeShells.pages()`）、`unknownPluginScreens()`、
  `duplicatePluginScreens()`、`catalogMatch()`、`unownedPages()`——**不渲染、不路由**；
- `BuiltinNativeShell.pages = NativePages.declarations`（22 条），`findPage` 转 `NativePages.find`；
- `NativeShells.pages()` / `NativeShells.findPage()` 是宿主的唯一入口。

### 1.3 宿主删私有页面引用

- `AppViewModel.applyDebugPages`（`--es dsh_dump_pages`）改为查 `ShellPageRegistry`：
  页面标题/层级来自壳声明，归属插件仍查 `BuiltinPlugins.screens`（插件元数据留在宿主）；
- 全仓扫描：`ui/App.kt` / `MainActivity.kt` / `AppViewModel.kt` 都不再出现
  `ui.pages` / `BuiltinPages`（只剩 `data/BuiltinPageIds.kt` 的注释里提到历史路径）；
- `data/BuiltinPageIds.kt` 保留为**稳定 id 词表**（内置插件 `screens` 归属、路由快照、
  `dsh_open_screen` 共用），不再承担「页面清单」职责。

### 1.4 壳 id 统一：`dsh_shell=builtin.shell.native` 合法

- `resolveShellTarget` 把 `builtin.shell.native`（大小写不敏感）和 `native` 一样解析成
  native 后端；`dumpShells` 新增 `native{id,label,enabled,pages,selected,safeMode}`；
- 因此「同槽位可换」的 id 语义从 C2 起统一：默认界面 = `builtin.shell.native`，
  可选壳 = `插件id#壳id`，两者都写同一个 `dsh_shell`。

## 3. 明确没做 / 下一片

1. **页面级可换（page/v1 完整版）**：现在 `ShellPageRegistry` 只汇总**壳**声明的页面；
   M84-G 的整页插件（`vm.pluginPageFor`，`page:true`，id 同名替换）仍由壳在 dispatch 里优先判断。
   下一片把两者并进同一张注册表（插件也能声明 id/标题/层级并覆盖内置页）。
2. **物理模块化（C3+）**：`ui/chat`、`ui/settings`、`ui/plugins` 等仍是宿主 Gradle 模块里的
   `app` 源码；拆 `ui:native-shell` 的前提是 **`NativeShellHost` 门面**（settings/chat/sessions/
   workspace/plugins/page 注册/导航），目前页面仍直接拿 `AppViewModel`。
3. **宿主最后一处具体 UI 引用**：`ui/App.kt` 在「选了 Surface 壳但还没走引导页」时直接画
   `ui.onboarding.OnboardingScreen`（C1 遗留，按 `docs/152` §3 属于 C3 的 onboarding 组）；
   native 壳内引导页已在壳里。
4. **M84-B 142/142 等价回归**：C 收口前必须跑（`docs/141`/`docs/142`）；**本片已跑 142/142**
   （见 §2 #11，`docs/m84b-check-m85c2.json`），后续每次改壳/页面再重跑。
5. `data/BuiltinPageIds.kt` 仍是宿主 id 词表（内置插件归属用）；page/v1 收口时再决定
   是否并入注册表。
