# 79 · 悬浮球改成「后台自动出现」+ 工具箱整页下线

> 2026-11-09 00:5x～01:0x｜用户真机反馈（原话，节选）：
> 「这个悬浮窗的逻辑有点小问题啊，我说的不是虚拟屏的悬浮窗，是那个光团悬浮窗，它是在打开应用后
> 自动产生的，而且关闭之后根本不知道从哪里打开……特别麻烦，在那个工具箱悬浮球里面开启那个东西
> 太麻烦了，我今天改成这样子，就是应用不在前台就自动开启那个东西，开启那个悬浮球，这个工具箱
> 直接删掉吧，我觉得里面重要的有一个权利与能力，那个单独页面的那个入口就放在功能与工具那块
> 替代那个工具箱」
>
> 结论：悬浮球改为「应用不在前台自动出现、回到前台自动收起」，工具箱页删除，「权限与能力」入口
> 收进 设置 →「功能与工具」。真机回归通过。本轮是第四十九棒，m54。

## 一、用户要的两件事

| # | 需求 | 验收标准 |
|---|---|---|
| 1 | 悬浮球不再手动开：**应用不在前台就自动出现** | App 在前台时屏幕上看不到光团；按 Home / 切到别的 App 后光团自动出现；回到鲸歌自动消失 |
| 2 | **删掉工具箱页**，把「权限与能力」（单独页面）入口放到 设置 →「功能与工具」，替代原「工具箱」行 | 设置里找不到「工具箱」；「功能与工具」组最后一行是「权限与能力」，点开就是权限页 |

## 二、现状与问题

- 悬浮球 `FloatingBallService` 只有两个入口：debug 通道 `--ez dsh_floating true` 和
  **工具箱页 →「悬浮球」卡片 →「开启」**。用户从长按菜单点了「关闭悬浮球」之后，
  要重新打开必须：设置 → 功能与工具 → 工具箱 → 悬浮球 → 开启，路径深且不直观。
- 悬浮球服务是 `START_STICKY`，开过之后进程活着就一直有，看起来像「打开应用后自动产生」，
  但其实前台也一直挂着，挡视线。
- 工具箱页里真正独有、用户认可的内容只有一个「权限与能力（单独页面）」按钮；设备状态卡和
  工具清单在权限页 / 插件页都有替代，功能入口也已经在「功能与工具」组里。

## 三、改动

| 文件 | 改动 |
|---|---|
| `app/build.gradle.kts` | 加 `androidx.lifecycle:lifecycle-process:2.8.6`（判断整个应用前后台，而不是单个 Activity） |
| `DshApplication.kt` | 观察 `ProcessLifecycleOwner`：`ON_START` → `hideWhenForeground()`；`ON_STOP` → `showWhenBackground()`。用 Process 生命周期而不是 MainActivity，避免位置附件那种透明 Activity 把「退后台」误判成一次前后台切换 |
| `MainActivity.kt` | 新增 `onStart()`：立即 `hideWhenForeground()`。`ProcessLifecycleOwner` 的 `ON_START` 有约 700ms 延迟，这里再收一次，避免从悬浮球点回 App 时那一瞬间的重叠 |
| `FloatingBallService.kt` | 新增静态 `running`（`onCreate` show 成功后置 true、`onDestroy` 置 false）；新增 `hideWhenForeground(context)`（无条件 `stopService`，能拦住还在启动途中的服务）和 `showWhenBackground(context)`（无悬浮窗权限静默跳过；`runCatching` 兜底 Android 12+ 后台启动 FGS 的限制，`SYSTEM_ALERT_WINDOW` 是官方豁免） |
| `ui/toolbox/ToolboxScreen.kt` | **整文件删除**（设备能力卡 / 功能入口 / 悬浮球开关 / 工具清单） |
| `ui/App.kt` | `Screen.Toolbox` 枚举、路由分支、import 全删；虚拟屏/无障碍页的 `onBack` 从 `go(Screen.Toolbox)` 改成 `go(Screen.Settings)` |
| `ui/settings/SettingsScreen.kt` | 「功能与工具」组：原「工具箱」行 → 「权限与能力」行（icon Security，副标题 Shizuku/无障碍/悬浮窗/通知/存储，`onOpenPermissions`）；「数据和权限」组里重复的「权限与能力」行删除，入口只保留一处 |
| `ui/onboarding/OnboardingScreen.kt` | 文案「设置 → 数据和权限 → 权限与能力」→「设置 → 功能与工具 → 权限与能力」；「抽屉 → 功能 → 工具箱」→「设置 → 功能与工具」 |
| `FloatingBallService.kt` / `FloatingWindowManager.kt` / `FloatingChatWindow.kt` / `FloatingOrb.kt` | **删除长按快捷菜单**（用户第二轮要求：「把长按悬浮球的功能给删掉吧，那里面的功能点按里面的功能都有，而且突兀了」）：`showQuickMenu`/`hideQuickMenu`、`Callback.onBallLongPress`、`FloatingOrb.onLongPress` 全部移除，长按光团不再弹菜单；通知文案「点球展开对话，长按出菜单」→「点球展开对话」 |

行为约定（写在这里免得下棒误解）：

- **前台收起、后台出现**是唯一自动路径。App 在前台时 `onStart` 一定会把服务停掉，
  所以「打开应用后光团还在」不会发生。
- 长按光团**没有菜单**（2026-11-09 起）。所有功能都在点按展开的 WINDOW 里，长按只当普通按压
  （`detectTapGestures` 只挂 `onTap`，拖动仍然可用）。
- 没有「显示在其他应用上层」权限时，`showWhenBackground` 静默不启动（不弹 Toast、不引导），
  入口在 设置 → 功能与工具 → 权限与能力 里（悬浮窗一行可以授权）。

## 五、已知限制 / 待定

1. **「彻底关掉悬浮球」没有开关**。现在没有长按菜单，光团只随前后台出现/消失；想临时不让它
   出现只能杀进程或开发调试。如果用户希望某个开关能让它永久不出现，下一棒在
   设置 →「功能与工具」或「显示与行为」里加一个 `floating_auto` 开关即可（默认开）。
2. 每次退后台都会拉起一次前台服务，通知栏会出现「鲸歌悬浮窗」通知（低优先级、不响）。
   这是前台服务的系统要求；如果用户嫌烦，可以把通知也做成静默/最小化。
3. 没有悬浮窗权限时不出现光团、也不提示；授权入口在权限与能力页。
4. 上一棒遗留、本轮仍未单独复现：**关掉虚拟屏预览（×）再让 AI 重开** 的 SPS/PPS 补发路径
   （`docs/78` §五）。与本轮悬浮球改动无关。
5. 工具箱页删除后，`Screen.entries` 少了 `Toolbox`；`--es dsh_open_screen toolbox` 不再匹配，
   调试时请直接 `--es dsh_open_screen settings`。
6. 长按菜单删除后，`ChatMirror.openApp(context, screen)` 的快捷入口只剩 WINDOW 顶部按钮；
   通知的 PendingIntent 仍能直接打开 App。
