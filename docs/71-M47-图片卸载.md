### 3.1 预算算法（逐字抄，含一个反直觉的 `>`）

```
lengths = 请求里每个未卸载 image 的 base64 字符数（最老在前）
excessCount = max(0, 张数 - maxImages)
excessBytes = max(0, 总字节 - maxBytes)
removeCount = excessCount == 0 ? 0 : ceil(excessCount / 20) * 20
removeBytes = excessBytes == 0 ? 0 : ceil(excessBytes / 10MiB) * 10MiB
逐张累加，直到 count >= removeCount 且字节目标达成：
  byteQuantum == 1 ? removedBytes >= removeBytes : removedBytes > removeBytes
```

`>` 是上游原样（`offloadedImagePrefixCount()` 第 197 行）：量子 >1 时按「严格超过」判，
所以会多发一张。原生单测锁了三种情形（量子 1 / 64 / 恰好等于预算）。

### 3.2 事件与重发

```
DshCompact: image-offload: request images exceed budget; offload=1
DshCompact: image-offload: offloaded 1 image(s) from 1 message(s) seq=5 retry=1
```

- 失败事件：`LlmEvent.Failed(message=…, code="IMAGE_OFFLOAD_REQUIRED", status=400, offloadImages=n)`；
  没有真实网络往返（原生在本地就能算出预算超了）；
- 事件：`{"type":"image/offload","seq":5,"data":{"targets":[{"seq":3,"imageIndexes":[0]}]}}`
  —— 不带 `surfaceOp`，原 user/message 的 image 块一个字节不改；
- 重发：同一个 step、同一个 assistant 气泡（`restartAttempt()`），不新开 step、不写
  `llm/retry`；`MAX_RETRIES=40` 只是防呆（每轮至少少一张图，正常 1–2 轮）；
- 没有可卸的图 / 会话写入失败 / 重试预算用完：保留原始错误，按普通请求失败收口。

### 3.3 永久性与修剪的相互作用

- 投影：`surfaceOf` 在事件顺序里给当前会话面的 image 标 `offloaded`；冷启重开会话仍从
  `image/offload` 事件重放，所以请求体一直是占位文本；
- 修剪：`pruneToolResults()` 用的是投影后的 UI 消息，`appendToolResultPruned()` 用
  `block.raw` 原样写回 —— 于是 `offloaded:true` 跟着新的 `tool/result` 落盘；
  回放时旧事件先标记、替换消息本身已带标记，不会丢（单测 `imageOffloadSurvivesToolResultPruneReplacement`）；
- 占位文本里的只读路径 = App 附件存储的归一化副本
  `files/attachments/v1/objects/<xx>/<sha256>`；模型仍可用 `read_image` 重新读它（会形成一次
  **新的**出现位置，不恢复旧标记，与上游「offloaded images never return automatically」一致）。

## 四、与上游的差别（全部有意，写在这里避免下轮重复研究）

1. **触发点在引擎而不是适配器**：原生没有 Files 上传通道，图片按 base64 直传；引擎在
   `buildRequest()` 之后按同一组默认预算算一遍，合成同形失败。少一次真实网络往返，
   但「每次卸载对应一次失败」的语义保留（`llm.request` 里仍能看到超预算的那一份）；
2. **预算默认值只搬了内联分支**：上游 DeepSeek Messages 还有 Files（raw）分支（128 MiB /
   64 MiB 量子）；原生只用 base64，所以取 `maxInlineRequestImageBytes=20 MiB` 与
   `inlineImageOffloadByteQuantum=10 MiB`；
3. **没有 `compaction/summary-error` 分支**：摘要请求若图片超预算会先记
   `compaction/end{error}`；主请求下一次触发卸载后，摘要请求自然读不到被卸的图。
   单独给摘要请求做「卸载 → 重试」留到下一轮（上游 README 把这条列在同一个执行器里）；
4. **数量量子可被调试通道改掉**：`dsh_image_budget_bytes` 只改字节预算，`countQuantum` 固定 1，
   方便锁屏验收；生产不设置这个 pref，走 20 张量子；
5. **附件路径暴露**：占位文本带 App 私有目录绝对路径（`/data/user/0/…/files/attachments/…`）。
   上游也带归一化副本路径；工具在 App 进程里能读，`run-as` 之外读不到；
6. **UI 没有「已卸载」占位卡**：聊天页仍显示缩略图（消息事件没改），只有请求体换成占位文本。
   上游投影后 UI 会显示占位；原生要做的话是下一步的 UI 活（等解锁一起截图）。
