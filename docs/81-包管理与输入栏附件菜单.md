## 一、包管理（`ui/packages/PackagesScreen.kt` 重写）

结构对照 Operit `ui/features/packages/screens/PackageManagerScreen.kt`：

| Operit | 鲸歌 |
|---|---|
| 顶部 TabRow（插件 / 包 / 技能 / MCP，48dp，图标+文字） | TabRow（插件 / 技能 / MCP；「包」= ToolPkg 脚本，鲸歌没有对应数据层，先不摆空 Tab） |
| TabContent：`LazyColumn` + 行内图标/名称/描述/开关 | 同结构；插件行显示版本、工具数、已接入数、试运行报错 |
| `EmptyState`：Info 48dp + bodyLarge 一句话 | 同（`EmptyState`） |
| 右下角 FAB 导入（`+`） | 同；插件选 zip、技能选 SKILL.md、MCP 选 json |
| 详情弹层（PackageDetailsDialog） | 插件复用 `PluginDetailDialog`；技能/MCP 用同样的字段式 AlertDialog |
| SnackbarHost 反馈 | 同；导入成功/失败都走 Snackbar |

数据层没动：
- 插件：`PluginStore`（QuickJS zip，`files/plugins/<id>/` + `files/plugins.json`）；
- 技能：`FileSystemSkills`（四个根、SKILL.md）；
- MCP：`McpConfigStore`（`dsh_mcp` SharedPreferences，配置管理）。

### 新增导入

- **插件**：SAF 选 zip → `AppViewModel.importPlugin(uri)`（现有链路），列表和 Snackbar 立刻更新。
- **技能**：`AppViewModel.importSkill(uri)`：读 SKILL.md → `SkillFrontmatter` 校验
  name/description/name 语法 → 写 `files/skills/<name>.md` → `refreshSkills()`。
  同名 `.md` 覆盖并提示；已有同名目录技能则拒绝，避免和目录型技能抢名字。
- **MCP**：`McpConfigStore.importJson`，支持 `{"mcpServers":{…}}` 和直接 map。

### 为什么没有「包」Tab

Operit 的 PACKAGES 是 ToolPkg（`.toolpkg` / JS + METADATA + Operit 运行时）脚本包；
鲸歌当前插件是另一套数据格式（`apply(ctx)` + QuickJS）。直接摆一个空 Tab 只会让用户
以为坏了，所以这一版先把三类真实数据摆出来；ToolPkg 兼容层/内置包目录单独做（见待办）。

## 二、输入栏附件菜单（`ChatComposer.kt`）

顺序和文案照 Operit `AttachmentSelectorPopupPanel`：

1. 照片 — 相册多选；
2. 拍照 — 系统相机；
3. 记忆 — **鲸歌还没有记忆库**，先把当前会话最近 40 条消息压成 `memory-*.txt` 附件
   （上限 24k 字符），让模型能看到之前聊过什么；等记忆库落地再换成 Operit 的记忆文件夹；
4. 文件 — `*/*` 任意后缀；文本/代码/日志进待发附件，图片走图片管线；
5. 屏幕内容 — 现有无障碍截图；
6. 当前通知 — `AttachmentCapture.attachNotifications`；没有通知使用权先弹系统设置；
7. 当前位置 — `LocationCapture.start`（透明 Activity 授权 + 取一次位置）；
8. 包 — **不是跳包管理**：照 Operit `PackageSelectorDialog` 弹出「选择包」，
   列出插件 / 技能 / MCP，选中后把该包的使用说明（插件工具+schema、SKILL.md 全文、
   MCP 配置 JSON）作为文本附件引用给 AI；插件会先按 Operit 的行为自动启用。

## 四、已知边界（下一批）

- Operit 自带包（`assets/packages/*.js`：time / duckduckgo / crossref / code_runner /
  workflow / system_tools …）还没搬：需要先做 ToolPkg 兼容层（`exports.*` + `Tools.*` /
  `OkHttp` / `Files` / `System` 桥），或者逐个改写成鲸歌 `apply(ctx)` 插件。
- MCP 仍然只做配置管理与导入，没有真正启动 stdio/HTTP 会话、拉工具列表。
- 技能只能导入单个 SKILL.md，不支持 Operit 的 zip / GitHub repo 导入。
- 文件附件仍是「文本可读，PDF/Word/压缩包提示不支持」；用户要的「所有文件都能引」
  需要通用文件块/解析器，单独立项。
