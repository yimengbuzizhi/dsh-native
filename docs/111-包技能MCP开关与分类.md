## 二、包（内置 Operit 包）改成开关

**改法**：
- `OperitPackageRow` 右侧的「安装 / 已安装」按钮 → **Switch**：开 = 没装过就先安装再启用；关 = 只 `setEnabled(false)`，
  不删文件（下回打开还是原来的权限/配置）。
- 状态文案从「已安装」改成 **已启用 / 已关闭 / 未启用**。
- 列表排序：**已安装/启用的排最前**，其余保持内置顺序（`sortedByDescending { installed }`）。
- 点行：装过的包直接进**插件详情**（授权/配置在那里）；没装过的才看内置包介绍。
- 详情弹层底部原来把「已启用 + 开关 + 插件详情」挤成一排（用户：很突兀），改成纯文字：
  顶部状态行显示 `已启用 · 版本 · 可用`，底部只留一个文字按钮（未装 = 「启用」，已装 = 「插件详情」）。

**真机证据**：`114-02`（包 tab：开关 + 已启用/未启用 + 已启用的排在前面）、
`114-10`（排序后列表）、`114-11`（点已启用的包 → 插件详情，顶部 `1.0.0 · DSH · 已启用` 是文字）、
`114-24`（关掉「增强文件工具」→ 变灰、显示「已关闭」、Switch 关）。

**数据层**：沿用 `PluginStore.setEnabled(id, enabled)`；关掉的插件不再注册工具（`syncPluginTools()`）。

## 三、技能：开关 + 垃圾桶

**改法**：
- `SkillSummary` 增加 `enabled`；关掉的名字存 `shared_prefs/dsh.xml` 的 `skills_disabled`（**只存被关的**，
  默认空 = 全部启用；以后新增技能自动是开的）。
- 关掉的技能**仍留在列表里**（开关是关的），否则关掉后就再也找不到、打不开了；
  但 `FileSystemSkills.load/loadForUser` 拒绝加载、技能目录（`skill-catalog`）过滤掉、斜杠命令与
  聊天页「选择包」里也不出现。
- 行右侧加 **Switch**（像 MCP）；自己导入的技能再加**小垃圾桶**，点开二次确认（`114-25`）。
- **内置技能 `dsh-plugin-adapter` 不给垃圾桶**（`BundledSkills.isBundled`）：删了下次启动还会被
  `ensureInstalled` 装回来，留着按钮只会让人以为删掉了。
- 排序：内置技能排最前，其余按名字。

**真机证据**：`114-06`（内置无垃圾桶、demo-skill 有）、`114-23`（关掉 demo-skill：开关变灰、
仍留在列表、prefs 落 `demo-skill`）、`114-25`（删除二次确认）。

## 四、聊天页「选择包」分类

原来一个平铺列表（插件/技能/MCP 混排）。现在按 `PackageKind` 分段，加小标题 **包 / 技能 / MCP**，
每组内保持原顺序；搜索仍跨组过滤（`114-20`，之前那次 `114-18` 只截到加载中的一帧，标题没出来）。

设备上实际效果：包 → 22 个插件；技能 → 2 个（demo-skill / dsh-plugin-adapter）；MCP → 2 个。

## 五、限制 / 没做的

1. 包开关「开」一个**没装过**的包 = 走原安装链路（解压 + 试运行），有几秒耗时，期间开关不可点；
   失败时沿用 `pluginNotice` 提示。
2. 关掉的包仍占磁盘（不删目录）；要彻底删仍走插件详情的「删除」。
3. 内置技能的「关」只影响发现/加载，不删文件；`files/skills` 里被手删后下次启动会重新装回。
4. 设置里的独立「技能」页（`SubScreen.Skills`）这次没加开关，只改了包管理的「技能」tab；
   用户说的是「包里面」，先按这个范围做。
5. 技能列表里删 demo-skill 时我误触过两次垃圾桶（坐标挨着开关），文件已按原内容重建，最终状态两条都在。
