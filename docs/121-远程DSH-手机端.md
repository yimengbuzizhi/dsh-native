## 一、这一批做了什么

### 1. 小助手：cookie 名不再靠猜（修掉 `http 401`）

阶段 4 起步时 `/api/health` 返回 `{"ok":true,"dsh":"http 401"}`，因为默认 cookie 名 `dsh-browser-session` 不对。
从 DSH 0.2.2-rc.1 的 `client-connection/browser-session` 实现里核对了算法，`helper.mjs` 现在自己算：

- authority：HTTP 用 `url.host`（如 `127.0.0.1:63167`），HTTPS 用 `url.origin`；
- cookie 名：`dsh-auth-` + `base64url(sha256(authority))`；
- cookie 值：`v1.<base64url(JSON{version:1,authority,issuedAt,expiresAt})>.<base64url(HMAC-SHA256(secretBytes, body))>`；
- secret：`~/.dsh/.credentials.yaml` 的 `client-connection/browser-session.payload.secret`（32 字节 base64url），
  **只在助手进程内存里用**，不落盘、不打印、不传给手机；
- 每次请求现签、1 小时有效（DSH 默认上限 30 天），重签即可。

同一版还补了：

- **WebSocket 升级透传**：`/api/dsh/api/remote.mux` 的 upgrade 头重写后把 TCP 双向转发（手机讲 DSH 的流协议）；
- 转发时删掉手机的 `Authorization` / `Origin` / `Sec-Fetch-Site`，Host 改成 DSH 自己的 authority；
- `/api/health` 除了探首页，再打一次 `session/list`，返回 `{ok,dsh,api}`：
  `dsh:"reachable"` + `api:"ok"` 才是真的通；
- `?token=` 只给手机↔助手用，转发前从 query 里去掉，不带给 DSH；
- `POST /api/debug/drop-ws`（带令牌）：主动掐掉所有已升级的 WebSocket，用来验证手机端断线提示 + 自动重连
  （不碰 DSH，也不影响 HTTP）。

本机结果：`/api/health` → `{"ok":true,"dsh":"reachable","api":"ok","dshUrl":"http://127.0.0.1:63167"}`。

### 2. 手机端：设置 → 远程 DSH

- **连接页**：地址、令牌（密码框）、测试连接、连接/断开、状态条、错误提示；
  `测试连接` 会额外打一次 `session/list` 验证令牌（`/api/health` 本身免令牌，不能证明令牌对）。
- **远程会话列表**：`session/list` → 标题 / cwd / 最后活动 / 模型 / 运行中圆点；
  刷新、新建（`session/create`）——新会话 cwd 由 DSH 默认值决定，手机暂不能选目录。
- **远程聊天**（复用鲸歌自己的页面，不是 WebView）：
  - 用户 / 助手正文、思考折叠（「思考 N 字」）、工具卡（点击展开参数/结果）、工具失败红字；
  - 发消息：`session/prompt`（`mode:"queue"`，`requestId` 客户端生成，`clientTimeZone` 本机时区）；
  - 流式：`session/follow`（`assistantStream:true`）→ 助手 token 增量 + durable 事件；
  - 停止：`session/cancel`；
  - 问题卡：`ask_user_question` 的 `tool/call` 参数渲染为选项卡，点选项调 `userQuestions/answer`
    （DSH 返回 `true` 才算回答成功；返回 `false` 显示「这个问题已经结束」）。
- **断线/重连**：WS 断开 → 顶部黄条「连接断了，正在重连…」，退避 1/2/4/8/8/8s 共 6 次；
  失败后保留「重连」按钮，点它立即重订阅；重连成功用 snapshot 覆盖历史并清掉黄条。
- **按需连接**：进连接页才建 HTTP；打开会话才建 WS；返回列表 / 点「断开」就关 WS 和客户端，不后台常驻。
- **前台服务**：远程 turn 开始借 `TurnKeepAliveService`（复用同一通知渠道 `dsh-turn`，ID 4101），
  turn 结束 / 停止 / 断开即释放；本地 turn 与远程 turn 用两个计数器记账，谁还在跑都不误停。

## 二、手机依赖的 DSH 协议（都在助手后面）

一元调用（所有会话/消息/工具操作）：

```
POST http://<助手>/api/dsh/api/<endpoint>
Authorization: Bearer <短码>
{"type":"client-request","rpcId":"<uuid>","method":"<endpoint>","payload":{"args":{…}}}

→ {"type":"server-response","rpcId":"…","result":{"ok":true,"value":…}}
                       或 {"ok":false,"error":{"code","message","details"}}
```

会话事件流：

```
WS ws://<助手>/api/dsh/api/remote.mux
发：{"type":"open","streamId":"…","endpoint":"session/follow","payload":{"args":{"request":{…}}}}
    {"type":"item","streamId":"…","value":…} / {"type":"end"} / {"type":"cancel"}
收：{"type":"item","streamId":"…","value":{"type":"snapshot"|"event"|"assistant-stream",…}}
    {"type":"end","streamId":"…"} / {"type":"error","streamId":"…","error":{…}}
```

用到的 endpoint：

| endpoint | 用途 |
| --- | --- |
| `session/list` | 会话列表（标题/cwd/运行中/模型） |
| `session/create` | 新建会话 |
| `session/follow` | snapshot + durable 事件 + assistant-stream（聊天页唯一数据源） |
| `session/prompt` | 发消息 |
| `session/cancel` | 停止当前 turn |
| `userQuestions/answer` | 回答 `ask_user_question`（返回 boolean） |
| `session/rename` | 验收时把测试会话改名（应用未用） |

事件映射：`user/message`（只看 `source.kind=="user"`）、`assistant/message`（text/reasoning 块）、
`tool/call`、`tool/result`、`turn/start`、`turn/end`；`assistant-stream` 只拼 `text-delta` / `reasoning-delta`。

## 四、限制与未验（如实）

1. **局域网 / Tailscale 未真机验**：本批用 `adb reverse` 到 `127.0.0.1:8137`；Windows 防火墙没为 8137 放行，
   所以 `192.168.1.29:8137` / `100.105.232.55:8137` 两条路径未从手机验证。部署契约里已写放行/用 Tailscale。
2. **扫码未做**：连接页只有手填地址+令牌，没有相机扫码（决策里提到扫码；ML Kit 条码依赖未加）。
3. **权限审批（approval intent）未映射**：`ask_user_question` 只做了问题卡；工具审批 / 计划审批 / 权限确认
   仍要在电脑上点。`userQuestions` 的 live claim（web UI 那套 `attachWait`）未实现。
4. **问题回答的「成功路径」未验**：本次 DSH 对 `userQuestions/answer` 返回 `false`（问题已不在 continued 状态），
   应用如实显示「问题已结束」；真正 accepted=true 的链路未在真机验。
5. **自动重连**：WS 被助手主动掐断（`drop-ws`）后 1.16s 自动重连成功（`122-36`，logcat `follow failure` → 新 `snapshot`）；
   **真实切 WiFi→5G / 断网后恢复未验**（本批没有做手机网络切换实验）。
6. **一次瞬时 401**：18:37 有一次 `session/prompt` 返回 401（提示「令牌不对（助手拒绝）」），
   同一地址/令牌立刻重发就成功；同一时刻电脑上 `/api/health`、`session/list` 都正常。根因未定位（记为已知问题）。
7. **分页**：`session/list` 一次返回全部（115 条），列表只画前 80 条；没有分页/搜索。
8. **断开 ≠ 取消远端 turn**：点「断开」只停止跟随，电脑上的 turn 还会继续跑（符合「DSH 是后端」的语义）。
9. **新会话 cwd**：`session/create` 不传 cwd，落 DSH 默认目录（本机是 `C:\Users\user\.dsh\profiles\desktop`）。
10. **验收用的 Ping 会话**：留在电脑 DSH 上，已改名为「远程 DSH 验收（可删）」，用户可自行删除。

## 五、怎么用

电脑（Node ≥ 18）：

```
cd D:\dsh\native
node tools/dsh-remote/helper.mjs --port 8137 --dsh http://127.0.0.1:63167
```

手机：设置 → 功能与工具 → **远程 DSH** → 填助手打印的地址 + 令牌 → 测试连接 → 连接 → 点会话进聊天。
外网/异地：手机和电脑登录同一个 Tailscale，填 `http://100.x.x.x:8137`；不要把 8137 直接映射到公网。
