## 一、这一轮的目标

上一轮把插件工具接进了对话，但插件里的 `node:fs` / `http` / `child_process` 还是空实现
（读文件返回空串、网络是宽松代理），所以真正能跑的只有纯计算工具。这一轮按 `docs/04 §七`
把「插件能真正干活」落地，并且**先限权再放能力**：

```
manifest permissions（申请）
  → 导入时自动允许 fs:workspace / ui，其余挂起
  → 插件页逐项确认（红框 + 原始权限字符串）
  → 执行时 PluginSandbox 按授权表现查
  → fs 限工作区、net 限域名、shell 限已确认
```

设备从 01:20 到 01:51 一直是锁屏（`mDreamingLockscreen=true`），**本轮仍然没有 UI 截图**，
所有运行证据来自 adb；UI 的权限列表/红框确认只做了代码与编译验证，用户解锁后要补截图（§六）。

## 二、实现

### 1. 权限模型（`core:plugins/PluginPermissions.kt`）

- 认的写法（大小写不敏感，规范化后持久化）：

  | 原始写法 | 规范写法 | 类别 | 默认 |
  |---|---|---|---|
  | `fs` / `fs:read` / `fs:workspace` | `fs:workspace` | 工作区文件 | **自动允许** |
  | `fs:any` / `fs:*` | `fs:any` | 任意 App 可访问路径 | 需确认 |
  | `net:<host>` | `net:<host>` | 该域名 + 子域名，仅 https | 需确认 |
  | `net:any` / `net:*` | `net:any` | 任意 https 域名 | 需确认 |
  | `shell` / `shell:exec` / `exec` | `shell` | App 身份 shell | 需确认 |
  | `ui` / `notify` / `device` | 同名 | 本版未实现 | 不授予（界面明说） |
  | 其他 | 原文 | `UNKNOWN` | 不认、不授予 |

- **不猜**：`net:https://host/path`、`net:host:443`、`net:user@host` 一律当 `UNKNOWN`，
  避免「按主机授权」被理解成整条 URL 而放大范围。裸域名只允许字母数字/`.`/`-`。
- `sanitizeGrants`：授权表只保留「清单里申请过 + 已实现」的项；`fs:any` 隐含 `fs:workspace`。
  手改 `files/plugins.json` 塞清单外权限不会生效（有单测）。
- `netAllows`：`net:api.example.com` 覆盖 `api.example.com` 与 `*.api.example.com`，
  **不**覆盖 `example.com`、`api.example.com.evil.net`。
- `isLoopbackOrLocal`：`localhost` / `127.0.0.0/8` / `::1` / `0.0.0.0` / `169.254/16` 任何权限都拒绝。
- `isBroadStorageRoot`：识别 `/sdcard`、`/storage/emulated/0` 这类「整块存储」工作区，
  插件页会额外警告（见 §2.5）。

### 2. 路径守卫（`core:plugins/PluginPathGuard.kt`）

复用 `core:tools` 的 canonical 包含检查思路（宁抄勿研），并补了两处 Android 上必须的细节：

1. **逐段展开软链接**（NIO `Files.isSymbolicLink` + `readSymbolicLink`，最多 16 层）：
   `canonicalFile` 在部分平台/目标不存在时不会展开中间软链接，工作区里放一个
   `escape -> /外面` 就能绕过；单测里在 Windows 上真建软链接验证会被拒。
2. **最深的已存在祖先**再 canonical 化：写新文件时目标还不存在，先 canonical 已存在的父目录。
3. **Android 存储别名归一**：`/sdcard`、`/mnt/sdcard`、`/storage/self/primary` →
   `/storage/emulated/0`，避免用户从文件管理器复制的路径被误判越界；前缀整段匹配，
   不会误伤 `/sdcard2`。

### 3. 宿主沙箱（`core:plugins/PluginSandbox.kt`）

JS 侧不直接碰 IO：所有能力调用先到 Kotlin，**权限/路径/域名/上限都在这里判**（JS 侧不重复实现安全判断）。

| 能力 | 方法 | 行为 |
|---|---|---|
| 文件 | `fs.read/write/exists/list/stat/mkdir/remove/rename/copy` | 按 `fs:workspace`/`fs:any` 解析路径；文本读写；单次读写 ≤4MB、复制 ≤32MB |
| 网络 | `net.fetch` | 仅 https；每跳重定向重新查域名；禁 userinfo；循环/链路本地始终拒；连接 10s / 读 20s；响应 ≤2MB |
| shell | `shell.exec` | 必须已确认 `shell`；`/system/bin/sh -c`；cwd = 工作区；15s 默认超时；stdout/stderr 各 ≤64KB；并发读防管道堵死 |

- 结果统一 `{ok:true,…}` / `{ok:false,error,code}`；越权是 `PERMISSION_DENIED`，路径越界是 `PATH_DENIED`。
- **不是内核沙箱**：拦的是能力调用，不是内存/CPU 隔离；死循环靠宿主超时中断。

### 4. QuickJS 宿主桥（`core:plugins/PluginModule.kt` 的 `HOST_BRIDGE`）

在原有 `PRELUDE` 之后追加一段桥（不改试运行老逻辑），覆盖：

- `node:fs` / `fs`：`readFileSync/writeFileSync/appendFileSync/existsSync/readdirSync/statSync/
  lstatSync/mkdirSync/rmSync/unlinkSync/rmdirSync/renameSync/copyFileSync` + `promises.*`；
- `ctx.http`：`get/post/put/patch/delete/request` → `__dshCallAsync("net.fetch")`；
- 全局 `fetch(url, init)` → 返回 `{ok,status,headers,text(),json()}`；
- `node:https` / `node:http` 的 `get/request`：最小回调式实现（body 一次给完），
  **http:// URL 仍会被宿主拒绝**（只允许 https）；
- `node:child_process`：`execSync` / `exec`（异步回调），`spawn` 明确报不支持；
- `process.cwd()`（= 工作区）、`console.*`（进 logcat，单条截断 2000 字）、`ctx.fs` / `ctx.shell`。

**踩坑（写下来省下一棒）**：`__dshCallAsync` 的 payload 到 JS 时**已经是对象**（C 侧做过
`JSON.parse`），第一版又 `JSON.parse(raw)` 了一次，真机报 `unexpected token: 'object'`，
网络明明 200 却拿不到 body。现在用 `__dshParseHost` 兼容对象/字符串两种。

### 5. App 接线

- `PluginRecord` 新增 `permissions` / `grantedPermissions`（写进 `files/plugins.json`，
  读盘时重新过 `sanitizeGrants`）。`PluginManifest` 解析 `permissions`（顶层，兼容 `dsh.permissions`）。
- `PluginStore`：
  - 导入时 `autoGrants` 只自动给 `fs:workspace`（`ui` 本版未实现，不会自动给）；
  - `grant(id, raw)`：只允许清单里申请过、已实现、且危险的能力；
  - `grantAll(id)`：调试通道用（锁屏无 UI 时一次授完）。
- `PluginToolRuntime`：
  - `refresh(records, workspace)`：绑定里带权限表与工作区根，**切换工作区会重算**；
  - 每次执行新建 `PluginSandbox`；`JsHost.callSync` 走沙箱，`callAsync` 丢到 daemon 线程池
    再回灌 QuickJS；`log` 方法转到 logcat；超时看门狗不变。
- 调试通道（仅 debug）新增 `--es dsh_plugin_grant <插件id|all>`。
  **注意**：调试 extras 只在 `AppViewModel.init` 读一次，`am start` 到已运行实例会
  `recreate` 但 ViewModel 保留 → **每次调试调用之间要 `am force-stop`**，否则命令被静默吞掉
  （本轮踩过一次）。

### 6. 插件页 UI

- 卡片：`权限 N` chip；有未确认的危险权限时 `需授权 N`（warn 色）。
- 详情：逐项列权限（标题 + 原始字符串 + 状态：已允许 / 需要你确认 / 本版还没实现）；
  危险且未授权项右侧「确认启用」→ **红框 + 原始权限字符串 + 一句话解释 + 确认授权**
  （docs/04 §七「危险能力永远不能静默获得」）。
- 详情弹层改成按 `id` 从最新 `plugins` 取记录：授权/重载后状态立刻翻，不拿旧 record。
- 页脚改成真实边界；当工作区是共享存储根且存在声明 `fs:workspace` 的插件时，
  额外显示 warn 提示：「fs:workspace 等于整块手机存储，想要更严就切工作区」。
- 设计取舍（留一句理由）：`fs:workspace` 仍按 docs/04 默认允许——它与内置文件工具的根一致，
  是「工作区」这个产品边界；但把「工作区=整块存储」的风险在插件页写清楚，不假装它是个小目录。

## 五、边界（别在群里夸口）

- **不是安全沙箱**：QuickJS 与 App 同进程；拦的是能力调用。恶意插件仍可能吃 CPU（超时中断兜底）。
- **fs 只支持文本**：没有 `Buffer`，二进制文件读出来是替换字符；`readFileSync` 的 encoding 参数被忽略。
- **`node:http` 实际上只允许 https**（宿主策略），不是完整 Node 兼容层；`spawn` 不支持。
- **shell 不是 root**，也**没有逐条命令确认**：确认的是插件级 `shell` 权限（每次安装/授权一次）；
  授权后插件可以在工具调用里执行任意命令。文档和 UI 都写明了。
- **DNS rebinding 没防**：域名白名单在 URL 层校验，解析到内网 IP 的情况没有二次检查。
- **重新加载不会重读权限声明**：`reload` 只重跑试运行，权限以导入时清单为准；改权限要重新导入。
- **fs:workspace 的边界 = 当前工作区**；工作区设成 `/sdcard` 时它等于整块存储（插件页已警告，
  但没有强制改默认——docs/04 定的是工作区默认允许）。
- `ui` / `notify` / `device` 权限只展示、不生效（本版没有对应实现），不会假装支持。
