# 66 · M42：时间上下文（time-context 逐字移植）

日期：2026-11-08 04:10–04:4x（第三十六棒，接 M41）
基线：`116717f` + M42

> 模型不知道「今天几号、现在几点、上一轮到现在过了多久」，问「今天」「现在」「多久没说话」只能瞎猜。
> 上游是 `@deepseek-ai/dsh-time-context`（0.2.x 的 `agent/pre-step` 插件，不是 system 段）：
> 每个 step 起点**追加一条 user 消息**，带时间戳、browser 时区、距上一条模型可见消息/上次注入的间隔。
> 这一轮按 `docs/port/02 §2.6` 的逐字模板移植，1:1 对着 `dsh-time-context/lib/index.js`
> （本机 `D:\dsh021\node_modules\@deepseek-ai\dsh-time-context\lib\index.js`，0.2.1-rc.2）抄。
> **设备整夜锁屏**（04:2x `mDreamingLockscreen=true`），没有 UI 截图；本轮用「请求体 dump + 会话文件
> + logcat 不崩」证明链路，UI 折叠条等解锁后补拍。

## 一、一句话结果

- 每个 step 起点（含第 2 步、goal 轮、通知唤醒轮）：满足节流就落一条
  `source.kind:"time-context"`、`form:"snapshot"`、`sections[0].name:"time-context"` 的 user 消息；
- 正文逐字：

  ```
  Time sampled while preparing turn {turn}, step {step}: {YYYY-MM-DDTHH:MM:SS±HH:MM}[{IANA}]
  Browser time zone for this request: {tz}. Interpret otherwise-unqualified dates and times in this zone.
  Elapsed since the preceding {model-visible message|step context}: {10m 3s|unavailable}
  ```
- 节流：`lastInjectionTime`（跨轮全局）+ 默认 600000 ms（10 分钟）；0 = 不节流；
- 基线：step 1 = **上一轮**最后一条模型可见消息；step ≥ 2 = **本轮**上一次注入；
  两者为 null 写 `unavailable`（首轮必然，本轮第一次注入在 step≥2 时也必然）；
- 对话里折叠成一行「时间上下文 · HH:mm:ss」，点开展开原文（对应桌面 `ContextInjectionRow` 的 snapshot）；
- 设置 → 显示与行为 → 「时间上下文」开关，默认开；
- 单测 **+13 条**（`TimeContextTest`），全量 **412 条 / 58 类 0 失败 0 错误**；
- 真机（PLT120）：请求体 dump 里逐字出现、会话文件里 `source` 与桌面**同形**、
  10 分钟内第二轮不注入、旧会话新轮 elapsed=`1h 25m 17s`、关开关后不再注入、`logcat -b crash` 空。

## 八、边界（诚实清单）

1. **没有 UI 截图**：折叠条「时间上下文 · HH:mm:ss」和展开原文只有编译 + 代码复用现成行样式保证，
   锁屏期间没有真机点过；设置里的开关也只验证了「prefs=false → 不注入」这条链路，没点过开关本身。
2. **step 1 的基线是本实现按上游语义补的**：上游 pre-step 时本轮用户消息还没进投影，
   native 引擎是先落 user/message 再注入，所以 `decide()` 在 step 1 只折**本轮之前**的事件；
   单测锁了这条（`stepOneIgnoresCurrentTurnUserMessage`），否则首轮会写 `0s` 而不是 `unavailable`。
3. **browser 时区只有 resolved**：桌面从每条用户消息的 `clientTimeZone` 推，可能 mixed/unavailable；
   Android 是单一客户端、系统时区恒可用，直接报设备时区（`Asia/Shanghai` 实测）。
   桌面那条 `unavailable` 文案保留了实现与单测，线上不会走到。
4. **间隔固定 10 分钟**：没有做「设置里改 refreshIntervalMs」；上游是插件配置项，native 暂用默认值。
5. **时间戳/时长格式是逐字移植**，但 `Intl` 的本地化数字在 Kotlin 侧用 `Locale.ROOT` 固定 ASCII；
   中文系统上桌面也是 ASCII（`en-US` formatter），一致。
6. **只在 step 起点注入**：一轮里没有工具调用的单步轮不会在中途补时间；与上游一致。
7. **子代理也注入**（同一份 `timeContextConfig()`）：上游 time-context 对每个 agent 都生效；
   子代理面板里看不到折叠条（只读回放用同一个 `projectSession`，按 sourceKind 渲染，理论上有）。
8. **旧会话里已有的 time-context 消息**（从桌面导入的 v4 会话）现在会显示成折叠条，
   以前是整段用户气泡；这是有意的（与桌面 context row 对齐）。
9. `/help`、`/model` 等命令不触发注入（不建会话、不发请求），与上游一致。
10. **投影是现折的，没有缓存**：每个 step 扫一遍 `session.events`（O(事件数)，桌面是 projection 缓存）。
    实测 2000 事件的会话单次 <1ms；等 `session-projection` 缓存（docs/06 B 组）做出来再挂上去。
