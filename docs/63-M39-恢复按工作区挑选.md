## 一、一句话结果

- 恢复确认弹窗：会话按工作区分组，一行一个工作区（路径 + 会话数 + 大小 + 旧版只读数），
  复选框默认全选；「已选 x / y 条」实时更新；
- 一个工作区都没选时「恢复」按钮禁用（插件/附件/设置仍可以靠全选走）；
- 恢复时只把**勾选工作区**里的会话交给 `restoreSessions`，未选的不碰、不报错，
  结果卡写「会话 N（跳过 M，未选 K）」；
- 插件 / 附件 / 设置**不受勾选影响**（勾选只管会话）；
- 调试通道新增 `--es dsh_backup_workspaces <slug1,slug2>`（子串匹配，锁屏验收用）；
- 单测：`:core:backup` 9 → **10 条**全过。

真机（PLT120，锁屏调试通道）：

## 二、规则

| 情况 | 行为 |
|---|---|
| 备份里只有 1 个工作区 | 不显示勾选列表，行为与 M36 完全一样（全恢复） |
| 多个工作区 | 显示列表，默认全选；可逐个取消/勾选 |
| 全部勾选 | 传 `onlySessionIds=null` → 走老路径，语义不变 |
| 部分勾选 | 只恢复选中工作区的会话；其余计入 `deselected`，不算跳过/失败 |
| 一个都没选 | 「恢复」按钮禁用（避免手滑把会话全跳过） |
| 同 id 已存在 | 仍跳过（不变的恢复语义） |
| 原 cwd 不可用 | 仍只在**真正恢复出来**的会话上映射（M36 规则不变） |
| 插件/附件/设置 | 不看勾选，照常按备份恢复 |

为什么按工作区而不是逐条会话：manifest 里没有会话标题（标题是事件帧里的 `session/title`，
导出时为 283 条会话全量解压拿标题代价太大），逐条列表只能显示 UUID。
工作区是用户能认出来的粒度，也正好对应 `sessions/<workspace>/<id>/` 的目录布局。

## 三、实现

| 层 | 文件 | 改动 |
|---|---|---|
| `:core:backup` | `NativeBackup.kt` | `RestoreReport.deselected`；`restoreSessions(zip, root, onlySessionIds: Set<String>? = null)`：未选中的已知 id 直接跳过并计数，manifest 里没有的 id 仍按原逻辑校验 |
| App | `BackupManager.kt` | `restore(..., onlySessionIds: Set<String>?)` 透传 |
| App | `BackupScreen.kt` | 恢复确认弹窗按工作区分组勾选（`RestoreWorkspace`）、结果卡显示「未选 N」、`startRestore(file, onlySessionIds)` |
| App | `MainActivity.kt` / `AppViewModel.kt` | 调试通道 `dsh_backup_workspaces`（子串匹配），日志加 `deselected=` / `only=` |

界面标签：会话 `cwd` 非空就用原路径（M36 备份都有），老备份没有 cwd 时把 slug 还原成大致路径
（`--storage-emulated-0--` → `/storage/emulated/0`，`----`/`--default--` → 「默认工作区」）。

## 七、边界（诚实清单）

- **只能按工作区勾选**，不能逐条勾选会话（manifest 没有标题，逐条只有 UUID）；
- 勾选只影响会话；想「只恢复插件不恢复会话」目前得全选后靠同 id 跳过，没有单独开关；
- 老备份没有 `cwd` 时标签是 slug 还原出来的大致路径，可能和真实路径不完全一致（仅显示用）；
- 恢复完的 `deselected` 只统计 manifest 里的会话；zip 里多出来的未知会话仍按原逻辑处理；
- **没有 UI 截图**：勾选列表、结果卡的「未选 N」都只有编译保证，解锁后补；
- 「恢复」按钮在没有会话、但有插件/设置的备份里仍可用（`groups.isEmpty()`）。
