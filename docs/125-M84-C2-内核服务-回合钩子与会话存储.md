# 125 · M84-C2：内核服务化（二）——回合钩子与会话存储可替换

> 2026-11-13 19:3x。目标来自 `docs/115 §C` 剩下的两项：
> 回合循环 `TurnEngine` 加 step / 工具前后 / 停止 / 错误重试钩子；会话存储 `SessionRepository`
> 抽成可替换接口（默认文件实现 + 注入点），验收「换一个存储实现能跑 create/list/open、换一个钩子能记录 step」。
> 证据：`docs/m84c2-check.json`、`docs/m84c2-hook.txt`、截图 `docs/shots/125-01…125-11`。

## 一、做了什么

### 1. 回合引擎钩子（core:engine）

新增 `core/engine/EngineHooks.kt`，`EngineDeps` 末尾加 `hooks: EngineHooks = EngineHooks()`（默认全 no-op）：

```kotlin
class EngineHooks(
    val onStepStart: (EngineStepPoint) -> Unit = {},
    val onStepEnd: (EngineStepPoint) -> Unit = {},
    val onToolStart: (ToolCall) -> Unit = {},
    val onToolEnd: (ToolCall, ToolResult) -> Unit = { _, _ -> },
    val onStop: (EngineStop) -> Unit = {},
    val onError: (EngineFailure) -> Unit = {},
    val onRetry: (EngineRetry) -> Unit = {},
)
```

`TurnEngine` 里的触发点（只观察，不返回任何值）：

| 钩子 | 触发点 | 说明 |
| --- | --- | --- |
| `onStepStart` | 注入消息落完、本 step 请求组装前 | 与落库的 turn/step 编号一致 |
| `onStepEnd` | 每次 `step/end` 之前 | 正常收口、无工具收口、失败、取消四条路径都有 |
| `onToolStart` | 审批通过、`registry.execute` 之前 | 拒绝路径不触发（没执行） |
| `onToolEnd` | `registry.execute` 返回后 | 带 `ToolResult`（含 isError） |
| `onStop` | 取消路径收口前 | `reason=user`（按了停止）/ `cancelled`（切会话等） |
| `onError` | 收到 `LlmEvent.Failed` 时 | 带 code/status，每次失败尝试一次 |
| `onRetry` | 压缩重发 / 图片卸载 / 摘要图片卸载 | `kind` + `attempt/max` |

约束（写进代码注释）：

- 钩子异常被 `TurnEngine.fire()` 的 `runCatching` 吞掉，只记一条 `engine-hook failed` 日志——观察者不能弄断一轮；
- 全部同步回调、不 suspend；需要异步能力的钩子自己起协程；
- 不改事件顺序/文案/落库时机：`TurnEngineTest` 原 40 个用例不改断言全过（新增 4 个钩子用例）。

### 2. 会话存储可替换（core:session）

新增 `core/session/SessionStore.kt`：

```kotlin
interface SessionStore {
    val id: String
    val root: File
    fun list(): List<SessionSummary>
    fun load(id: String): SessionSession?
    fun create(cwd, model, agentPreset, parentSession, isSeeded, origin, delegationDepth): SessionSession
    fun findFile(id): File?
    fun trash(id): Boolean
    fun trashWorkspace(cwd): Boolean
    fun listTrash(): List<TrashedSession>
    fun restoreTrashed(dirName): Boolean
    fun purgeTrashed(dirName): Boolean
    fun purgeAllTrash(): Int
    fun purge(id): Boolean
    fun rename(id, title): Boolean
    fun fork(id, throughSeq, cleanTurnBoundary, title): SessionSession?
}
```

- `FileSessionRepository`：默认实现，逐方法转发给原 `SessionRepository`，**目录布局 / zstd 帧 / 回收站 / 摘要缓存一个字节都没动**；
- `MemorySessionStore`：`id = "memory"`，会话表/回收站/分支都在内存；`MemorySession` 覆盖
  `SessionSession.persist()` 为空实现，`appendRaw` 的 seq/events 语义不变（引擎/GoalStore 无感），
  所以「事件字节」也不再写死文件；
- `SessionStores` 注册表：内置 `file` + `memory`，同 id 注册 = 覆盖，未知 id 回落 `file`（App 启动不因调试值残留而挂）；
- `AppViewModel` 不再 new `SessionRepository`，改为
  `SessionStores.create(filesDir/sessions, debug 包可指定 id)`；`sessionsDir` 等 20 处 `repo.*` 调用原样通过接口。

`SessionRepository.TrashedSession` 提到顶层（`core.session.TrashedSession`）——它现在是接口契约的一部分，
文件实现与内存实现返回同一种条目；`SessionsScreen` / `AppViewModel` 的引用同步更新。

### 3. debug 验收通道（仅 debug 包）

| 通道 | 作用 |
| --- | --- |
| `--es dsh_session_store memory\|off` | 冷启时切换会话存储实现（release 永远 file；VM 构造时读） |
| `--es dsh_dump_sessions <绝对路径>` | 落盘 `{store, root, registered, active ids, activeCount, trash, diskCount}` |
| `--es dsh_llm_provider debug.tool` | 新增确定性「会调工具」假供应商：第一步吐 `bash {"command":"echo hi"}` 的 tool_use，第二步收到 tool_result 后吐最终文本 |

`DebugTurnHook`（app，`BuildConfig.DEBUG` 才挂真钩子）把七类钩子写到 logcat tag **`DshTurnHook`**；
主会话与子代理的 `EngineDeps` 都挂同一份。`debug.tool` 走完整 TurnEngine + 真工具表 + 真审批。

## 二、真机验收（OPPO A55 5G）

### 1. 钩子顺序：一轮两步、带真工具

冷启动：`--es dsh_llm_provider debug.tool --es dsh_send tool`，logcat（`docs/m84c2-hook.txt`）：

```
19:37:30.825 I DshTurnHook: step-start turn=1 step=1
19:37:30.989 I DshTurnHook: tool-start name=bash id=debug-tool-call-1
19:37:31.021 I DshTurnHook: tool-end name=bash id=debug-tool-call-1 error=false chars=3
19:37:31.026 I DshTurnHook: step-end turn=1 step=1
19:37:31.060 I DshTurnHook: step-start turn=1 step=2
19:37:31.122 I DshTurnHook: step-end turn=1 step=2
```

- 顺序 = `step 起 → 工具起 → 工具止 → step 止 → 下一步 step 起/止`，与事件顺序一致；
- 工具卡展开：`bash echo hi`、参数 `{"command":"echo hi"}`、结果 `hi`（`chars=3`，含换行），
  截图 `125-01`（整页）/ `125-02`（展开工具卡）；
- 该轮是 `0 in / 8 out`，走 debug 供应商；请求仍由 TurnEngine 组装（不是绕过引擎直接写 UI）。

### 2. 存储切换：同一个 App，内存实现真跑一轮

| 步骤 | `store` | `activeCount` | `diskCount` |
| --- | --- | --- | --- |
| 默认（file，存储验收开始时） | `file` | **77** | **77** |
| 冷启 `dsh_session_store memory` + 发一条 | `memory` | **1** | **77** |
| 杀掉进程再冷启（memory 仍是选中实现） | `memory` | **0** | **77** |
| `dsh_session_store off` 冷启恢复 | `file` | **77** | **77** |
| 最后重跑钩子验收（又建一条 file 会话） | `file` | **78** | **78** |

- 内存实现里新建的会话 id `fe10c5c7-…`：聊天页正常收到 debug 供应商的回复（`125-03`），
  列表/打开路径都走 `SessionStore`；重启后 active 归零而磁盘仍有 77 条——两套存储真的分开了；
- 切回 `file` 后磁盘 77 条原样回来（`dsh_session_store` 只影响 debug 选择，release 忽略该键）；
- dump 文件：`docs/m84c2-store-file.json`、`m84c2-store-memory.json`、`m84c2-store-memory-restart.json`；
  `registered=["file","memory"]`。

## 三、限制 / 未做

- **`SessionSession` 仍是具体类**：`load/create/fork` 返回它，文件实现的事件编码/落盘在它里面；
  内存实现靠覆盖 `persist()` 做到「事件不落盘」。把会话对象也抽成接口需要改 TurnEngine/GoalStore 的
  全部签名，归 D/E 阶段，不在本批硬拆。
- **备份/导入仍直接 new `SessionRepository`**（`BackupManager`）：它按目录布局读写，与 App 当前选中的
  store 无关；切到 memory 时备份导出的仍是磁盘文件（debug 验收场景可接受），后续接 store 再统一。
- **没有供应商选择 UI**（C3 可选）：设置页模型配置仍是协议隐含 `deepseek`/`openai`，UI 下拉未做。
- **钩子只有宿主侧 Kotlin**：JS 插件的 `ctx.engine.hook` / `ctx.llm.register` 归 §E 的外部插件 API；
  本批只证明内核有稳定的钩子边界。
- 钩子同步、无 suspend；`onToolEnd` 只在真正执行后触发（审批拒绝路径不触发，需要时再加 `onToolDenied`）。
- 本批未发版。
