## 1. 这一片做了什么

### 1.1 引导页进 `shell/v1` 契约

```kotlin
interface NativeShell {
    ...
    /** M85-C3：Surface 壳没有引导页，宿主挂载可选壳前向壳要这一步。 */
    @Composable fun Onboarding(onDone: () -> Unit)
}
```

- `BuiltinNativeShell.Onboarding` = 原来的 `OnboardingScreen(onDone = ...)`，实现留在壳里；
- `BuiltinNativeShell.Root` 自己也不再直接调页面，改成 `if (!vm.onboardingDone) Onboarding {...}`
  （同一份实现，两处入口）；
- `ui/App.kt`（Surface 壳路径）：`nativeShell?.Onboarding(onDone = { vm.completeOnboarding() }) ?: SafeModeScreen(vm)`。

### 1.2 宿主 import 扫描（C 目标验收口径）

| 宿主文件 | 现在 import/引用的 `ui.*` | 说明 |
|---|---|---|
| `ui/App.kt` | `ui.shell.NativeShells`、`ui.shell.SafeModeScreen`、`ui.surface.PluginShellScreen` | 契约 + 宿主安全模式 + Surface 渲染器（壳宿主，属于宿主骨架） |
| `MainActivity.kt` | `ui.DshApp` | 只启应用入口 |
| `chat/AppViewModel.kt` | `ui.shell.ShellPageRegistry`、`ui.shell.NativeShells` | 只有 `shell/v1` 契约 + 页面注册表 |
| 22 个页面组件 | 无 `AppViewModel`/无壳依赖 | 只接数据 + 回调 lambda |

**结论：宿主侧不再有「具体页面」引用**（`OnboardingScreen`、`ChatScreen`、`BuiltinPages` 等都不在宿主文件里）。
