# 05 · 插件兼容与 AI 安装（简化版）

> 2026-11-06 修订：用户明确 **「没必要为它单独做工具，能用就行」**。
> 本文取代上一版（PortKit / 七步流水线 / 独立 Skill）——**不为插件移植做专用工具链**。

---

## 一、只保留三样必需的东西

| # | 东西 | 为什么必须有 | 谁做 |
|---|---|---|---|
| 1 | **兼容运行时** | 让 DSH 插件能直接跑（`import` 不用全改） | 宿主代码（`@deepseek-ai/*` 与 `node:*` 子集） |
| 2 | **插件目录 + 加载/报错/启用禁用** | 装进来的插件得能跑、坏了能看见 | 插件页的普通功能 |
| 3 | **AI 用现成能力改造** | 读文件、改文件、看报错、再改 | Agent 已有的 fs 工具，不加新工具 |

就这三样。没有 PortKit、没有七步流水线、没有单独的移植工具、没有单独的 Skill 文件。

---

## 二、实际流程（用户视角）

```
用户把插件放到手机里（压缩包/文件夹/贴代码）
   ↓
对 AI 说：「把这个插件装进来」
   ↓
AI 自己：读文件 → 改 import / 换 API → 写进插件目录 → 让你点「安装」
   ↓
插件页：点「启用」→ 有错就显示错误 → AI 读错误继续改
   ↓
能用就算完
```

设备上不需要 Node，也不需要"干跑工具"——**插件页加载一次就是干跑**，报错信息直接给 AI 看，它自己修。

---

## 三、兼容运行时（唯一需要认真做的）

插件里这些 import 由宿主提供，插件代码不用改：

| import | 宿主提供 |
|---|---|
| `@deepseek-ai/cordis` | `ctx`、`inject`、`apply` |
| `@deepseek-ai/dsh-tools` | `defineTool()` |
| `@deepseek-ai/schemastery` | `z.object/string/boolean/...` 子集 |
| `node:fs` / `node:path` / `node:os` | 映射到宿主 fs（受权限约束） |
| `node:child_process` | 映射到 shell（受权限约束） |

覆盖不到的部分（UI 插件、深度钩子、没打包的 npm 依赖），AI 改或明说"不支持"。

---

## 四、「完美」怎么保证（不靠工具，靠三条）

1. **兼容层尽量原样**：能不改就不改，行为自然一致；
2. **插件页报错可见**：加载失败、工具注册失败、schema 不对，都显示原文，AI 能读到；
3. **可回滚**：保留原包和改后的版本，坏了退回上一版。

桌面上的 Node 对拍（原版跑一遍、移植版跑一遍比输出）**只在开发期做**，不产品化。

---

## 五、工作量

| 项 | 工期 |
|---|---|
| 兼容运行时（cordis / defineTool / schemastery / fs / path / child_process 子集） | 3–4 周 |
| 插件目录、清单、加载报错、启用禁用、回滚 | 1 周 |
| **合计** | **4–5 周** |

原方案（PortKit + 流水线 + Skill）是 8–12 周，砍掉后省 **4–7 周**。

---

## 六、边界（写进插件文档，别让用户误会）

- 没有市场、没有一键装；
- 插件必须是**自包含的打包 JS**（设备上没有 npm）；
- 不保证所有 DSH 插件都能装，UI 类插件基本要重写；
- AI 改完必须用户点确认才生效。
