> 2026-11-07｜基线 `ea1a1da`。上一篇 `18-M4` 是 system 动态拼装，本篇是工具层。

## 一、做完的

| 工具 | 行为 | 验证 |
|---|---|---|
| `working_directory` | 无参 → 返回当前目录；有 `cd` → 校验目录存在并切换。`ToolContext.cwd` 可变，**相对路径按 cwd 解析，逃逸检查仍以 workspace 为根**；bash 默认 workdir 也跟 cwd | 真机：模型先调它，再 `bash ls -la`（`docs/shots/m4-ask-answered.png`） |
| `web_fetch` | GET http(s)，15s 连接/30s 读超时，HTML→纯文本（去 script/style/标签、解实体、压空白），>30k 截断 | 真机抓 example.com 并总结（`m4-web-fetch.png`） |
| `ask_user_question` | 解析 `questions[]`（id/question/header/options/multi_select），通过 `ToolContext.askUser` 挂起等 UI；答案格式化成 `User answers:` 文本回给模型 | 真机弹选择卡 → 选「继续做代码」→ 提交 → 模型继续执行（`m4-ask-user.png`、`m4-ask-answered.png`） |

工具总数 7 → **10**（read/write/edit/glob/grep/bash/working_directory/web_fetch/ask_user_question/todo_write）。

## 二、实现要点

1. **`ToolContext` 增加 3 个字段**：`cwd`（可变，`working_directory` 改）、`askUser`（suspend 回调）。
   `resolvePath()` 改为「相对 cwd 解析 + 以 workspace 为根做逃逸检查」。
2. **提问通道**：`ask_user_question` 工具本身不碰 UI，只调 `ctx.askUser(questions)`；
   `AppViewModel.askUser()` 设置 `ChatSessionState.pendingQuestions` 并 `await` 一个 `CompletableDeferred`；
   ChatScreen 的 `AskUserDialog`（单选/多选 + 自定义回答 + 跳过）提交后 complete。
3. **审批策略**：`working_directory` / `web_fetch` / `ask_user_question` 归入只读直通（不弹审批）。
4. **Markdown 链接**：`[label](url)` 用 Compose 1.7 的 `LinkAnnotation.Url` 渲染成主色可点文本
   （`m4-markdown-link.png`）。
