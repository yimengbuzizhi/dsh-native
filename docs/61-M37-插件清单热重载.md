# 61 · M37：插件清单热重载（manifest.json / package.json）

日期：2026-11-08 03:28–03:36（第三十三棒）
基线：`77434ad` + 本轮

> 补 `docs/56 §四` 的缺口：M32 让 `manifest.json` 的 `config.schema/default` 生效，但
> **schema 只在安装时读一次**；之后改清单必须重装（会丢 `installedAt` 和已授权限）。
> 这一轮把「重新加载」改成**每次重读清单**：name / version / description / main /
> configSchema / configDefaults / permissions 全部跟磁盘上的清单走，用户配置按新 schema 裁剪。
> 设备整夜锁屏（`mDreamingLockscreen=true`），**本轮仍没有 UI 截图**；功能用单测 + 调试通道真机验证。

---

## 一、一句话结果

- 插件页点「重新加载」（或调试通道 `dsh_plugin_reload`）时，先重读
  `files/plugins/<id>/package.json`（优先）或 `manifest.json`，再跑一次试运行；
- **跟着清单变**：`name / version / description / main / format / permissions /
  configSchema / configDefaults`；
- **永远不动**：`id / path / enabled / installedAt / grantedPermissions` 的已有授权
  （只按新清单过滤，撤销的权限立刻失效；新增的自动允许权限会补授）；
- 用户配置按新 schema **只保留认识的顶层键**，结果消息会说清「配置里已不支持的键已移除：…」，
  版本变化也会写「版本 0.1.0 → 0.2.0」；
- 清单 id 改了 → **拒绝重载**（目录和授权挂在旧 id 上，要换 id 就重新导入）；
- 清单 JSON 坏了 → 拒绝重载，记录里留下「清单读取失败：…」，插件页可见；
- 单测：`:core:plugins` 66 → **74 条**全过（新增 `PluginReloadTest` 6 + `PluginPackageTest` 2）。

真机（PLT120，锁屏调试通道）：

```

03:32:40 call    config={"city":"Beijing","limit":3}
```

## 二、合并规则

| 字段 | 来源 | 说明 |
|---|---|---|
| `id` | **不动** | 目录名、工具归属、授权表都以它为键；清单 id 不一致直接拒绝 |
| `path` / `enabled` / `installedAt` | **不动** | 重载不改变安装关系和时间 |
| `name` / `version` / `description` / `main` / `format` | 新清单 | `main` 变了就试运行新入口（真机验过 `index.js` → `index2.js`） |
| `permissions` | 新清单 | 规范化后的原文列表整体替换 |
| `grantedPermissions` | 旧授权 × 新清单 | 撤销的权限失效；`fs:workspace`/`ui` 这类自动允许项按安装时规则补授；新增危险权限**不**自动授 |
| `configSchema` | 导出 `Config` → 清单 `config.schema` → 旧 schema | 插件这次没导出 Config 时，清单 schema 优先于旧快照 |
| `configDefaults` | 新 schema + 新清单 `config.default` | 深合并顺序与 M32 一致：清单默认 → 用户配置 → schema 剩余默认 |
| `config`（用户值） | 旧值按新 schema prune | 只裁**顶层**键；同名键保留 |
| `tools` / `toolSchemas` / `toolDescriptions` / `imports` | 本次试运行 | 和原「重新加载」一致 |
| `error` / `configError` | 本次试运行 | 失败时写入，成功后清空 |

为什么保留 `enabled`：重载是「改完文件验证一下」，不是重新安装；用户停用的插件不该因为
点了一下重载就自己启用。

为什么 id 不一致要拒绝：`plugins.json`、授权表、工具名和目录都按 id 关联；静默改 id 会让
旧记录变成孤儿。错误文案直接告诉用户「要换 id 请重新导入」。

## 三、实现

| 层 | 文件 | 职责 |
|---|---|---|
| `:core:plugins` | `PluginModel.kt` | 新增 `ManifestRead`（Ok / Missing / Failed） |
| `:core:plugins` | `PluginPackage.kt` | 抽出 `manifestFrom`（安装/热重载共用同一套解析）；新增 `readManifest(dir)`、`parseManifestText(text, format)` |
| `:core:plugins` | `PluginReload.kt`（新） | `apply(record, manifest, run)`：按 §二 合并出新记录 |
| `:core:plugins` | `PluginSchema.kt` | 新增 `prune(schemaText, configText)`（原 `PluginStore.pruneConfig` 上移，安装/重载共用） |
| App | `PluginStore.kt` | `reload(id)`：重读清单 → id 守卫 → main 守卫 → 试运行（默认值用新清单）→ `PluginReload.apply`；结果消息带版本变化/被移除的配置键 |

**宁抄勿研**：清单解析不写第二套，直接复用安装流程的 `manifestFrom`——安装时怎么认
`name/id/main/permissions/config`，热重载就怎么认，避免「装的时候能过、重载的时候不认」。
重载仍然只跑一次 QuickJS（`dryRunForConfig` 的两遍试运行和安装时一样）。

## 四、单测

`PluginReloadTest`（6 条）：

1. 新清单的 name/version/description/main/format 替换，id/path/enabled/installedAt 不变；
2. 新 schema 裁掉旧配置键、保留同名键，默认值按「清单默认 > schema 默认」重算；

## 六、边界（别在群里夸口）

- **不能改 id**：清单 id 变了会被拒绝（要换 id 只能重新导入）；
- 清单里没有 config、插件也不导出 Config 时**沿用旧 schema**（不主动清用户配置）；
- 配置 prune 只裁**顶层**键；嵌套对象里 schema 不再认识的键仍然保留（下一轮可做递归 prune）；
- 插件页按钮还叫「重新加载」，但行为已经变成「清单 + 脚本」；UI 文案/提示等解锁后随截图一起看；
- DSH `package.json` 的 `config` 字段仍未接（只有 `manifest.json` 的 `config` 和插件导出的 `Config`）；
- 本轮**没有 UI 截图**（设备整夜锁屏），`reload` 的界面只能等解锁后补；
- 重载仍是同步跑 QuickJS（最长 12 秒），和旧行为一致；真机锁屏时用调试通道，不影响。
