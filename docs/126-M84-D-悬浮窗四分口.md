# 126 · M84-D：悬浮窗四分口——球 / 气泡 / 面板 / 全屏页

> 2026-11-13 19:4x。目标来自 `docs/115 §D`：球、气泡、面板、全屏页各是一个插口，
> 显示时机、点击、内容都是钩子；验收「装个插件给球加红点、换气泡样式；关掉恢复」。
> 证据：`docs/m84d-check.json`、`docs/m84d-floating.txt`、截图 `docs/shots/126-01…126-07b`。

## 一、做了什么

### 1. 四个插口 + 插件注册表（`device/floating/FloatingSlots.kt`）

```kotlin
enum class FloatingSlot { BALL, BUBBLE, PANEL, FULLSCREEN }

interface FloatingSlotPlugin {
    val id: String
    fun ballBadge(): FloatingBadge? = null          // 球角标（红点/未读数）
    fun bubbleStyle(): BubbleStyle? = null          // 气泡底色/字色/圆角
    fun bubbleText(defaultText: String): String?    // 气泡正文覆盖
    fun banner(slot: FloatingSlot): String?         // 面板/全屏页横幅（内容）
    fun visible(slot: FloatingSlot): Boolean = true // 显示时机
    fun onClick(slot: FloatingSlot): Boolean = false // 点击拦截（true = 消费）
    fun onShow(slot: FloatingSlot) = Unit           // 插口显示
}
object FloatingSlots { register / unregister / ballBadge() / bubbleStyle() / … }
```

- 注册表是进程内单例，悬浮窗服务与 App 共用；`FloatingSlots.revision` 是 Compose 快照，
  开关插件后悬浮窗界面立即重组。
- 所有查询都 `runCatching` 包住：插件抛异常 = 当没有该插口，不会弄断悬浮窗。
- 内置示例 `FloatingDemoPlugin`（id `demo.floating`），归属内置插件
  `builtin.floating.demo`（默认关）；插件页新增「悬浮窗插件」段，开关 = 注册/注销。

### 2. 接到现有 6 个模式上（`FloatingChatWindow.kt`）

| 插口 | 模式 | 钩子落点 |
| --- | --- | --- |
| 球 | `BALL` / `VOICE_BALL` | 角标内容 `ballBadge()`；`onTap` 先问 `handleClick(BALL)`，没消费才走默认展开 |
| 气泡 | `RESULT_DISPLAY` | 样式 `bubbleStyle()`、正文 `bubbleText()`；流式结束后是否自动弹由 `visible(BUBBLE)` 决定；点击先问 `handleClick(BUBBLE)` |
| 面板 | `WINDOW` | 顶部内容横幅 `banner(PANEL)`；模式显示时 `onShow(PANEL)` |
| 全屏页 | `FULLSCREEN` | 顶部内容横幅 `banner(FULLSCREEN)`；`onShow(FULLSCREEN)` |

`SCREEN_OCR` 是圈选工具页，不属于四分口（`toSlot()` 返回 null）。

### 3. 示例插件（`FloatingDemoPlugin`）

- 球：红色角标「1」；
- 气泡：粉底（`0xFFFFE4EC`）+ 深红字（`0xFF7A1734`）+ 18dp 圆角，正文前缀 `【demo.floating】`；
- 面板/全屏页：各一条白色横幅；
- `onClick` / `onShow` 写 logcat tag `DshFloatingSlot`，证明点击与显示时机的钩子真的被调用（不拦截默认动作）。

同时修了内置插件开关一个真 bug：`BuiltinPluginStore.isEnabled` 按 `id in 关掉集合` 判断默认关的插件，
但 `setEnabled(true)` 只会 remove，导致「默认关」的插件永远打不开。现在默认关的插件改成
「集合里有 id = 显式打开」，默认开的语义不变。

## 二、真机验收（OPPO A55 5G）

### 1. 插件页开关

- 插件页「内置插件 **23** · 本地 28」；滚到底新增「**悬浮窗插件（1）**」段，
  行「悬浮窗插口（示例）· 球红点『1』+ 粉底气泡 + 面板/全屏页横幅」（截图 `126-01`，开关 ON）。
- UI 点开关 → logcat：`unregistered demo.floating` / `sync demo=false plugins=[]`，
  开关变灰（截图 `126-06`）；打开 → `registered` / `sync demo=true plugins=[demo.floating]`。

### 2. 球插口：红点

- 插件开：退到桌面 → 球出现在右侧，右上角红色角标「1」（`126-02`，局部 `126-02b`）。
- 插件关：同一位置恢复默认球，无角标（`126-07`，局部 `126-07b`）。

### 3. 气泡插口：样式 + 正文 + 显示时机

- 冷启 `--es dsh_llm_provider debug.slow --es dsh_send bubble`（2.5 秒后收口），
  启动后立刻回桌面：流式结束时球在 `BALL` → 自动弹气泡（`visible(BUBBLE)` 放行）。
- 气泡为粉底深红字、18dp 圆角、正文前缀 `【demo.floating】`，
  内容「慢速回复：悬浮窗气泡插口验收（M84-D）」（截图 `126-03`）。
- 3 秒后自动回球（原有行为未变）；logcat：`show slot=BALL → show slot=BUBBLE → show slot=BALL`。

### 4. 面板 / 全屏页插口：内容横幅 + 显示钩子

- 点球：先 `click slot=BALL plugin=demo.floating (default action kept)`，再 `show slot=PANEL`；
  面板顶部出现「悬浮窗插件 demo：面板插口（内容来自 FloatingSlots）」（`126-04`）。
- 面板标题栏全屏按钮 → `show slot=FULLSCREEN`，顶部横幅「悬浮窗插件 demo：全屏页插口」（`126-05`）。
- 关掉插件后四个插口不再有角标/横幅/自定义气泡（`126-06`、`126-07`）。

## 三、限制 / 未做

- 现在是**宿主内 Kotlin 插件**（内置示例 + 插件页开关）；JS 插件注册同一接口（`ctx.floating.*`）
  归 `docs/115 §E`。D 只完成「插口存在、可替换、可关」，还没有第三方插件可用的 JS API。
- 四分口只覆盖外观/内容/显示/点击钩子：球的拖动与手势、面板内的输入/工具卡、全屏页的语音
  仍是宿主实现；要整体替换需要把四个模式的渲染也做成插槽（下一步）。
- 面板/全屏横幅目前叠在内容顶部（会盖住标题栏下沿一点）；只是内容插口的演示，
  不是最终布局（用户可后续改 `FloatingChatWindow` 的 banner 容器）。
- 本轮没发版；设备上 `builtin.floating.demo` 已关（默认关），悬浮窗服务已停。
