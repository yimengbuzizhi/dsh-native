## 三、关键工程决策（已拍板，别重开）

1. **协议按 Anthropic Messages 写**，`stream`/`thinking.type`/`type` 这类「值等于默认值」的字段必须显式序列化
   （`encodeDefaults = true`）。曾因省掉 `stream` 导致服务端返回非流式 JSON、表现成「空回复」。
2. **zstd 双依赖**：`core:session` 用普通 jar（JVM 对拍/单测）；`:app` 排除该 jar、改用 `zstd-jni@aar`
   提供 `.so`。两者版本必须锁 1.5.6-8。
3. **版本不写死**：提示词/工具按版本目录打包；`upstream.toml` 是唯一版本源（跟进机制见 `docs/12-上游跟进机制.md`）。
4. **调试通道**（仅 debug 包）：
   - `am start ... --es dsh_account_token <token>` 导入 DeepSeek 账号令牌（provider=account）
   - `--es dsh_send "text"` 启动即新建会话并发送（绕过 IME，用于自动验收）
   - 令牌可从本机桌面版 DSH 读取：`node D:\dsh\native\.upstream\get-token.cjs`（该目录不入库）
5. **模型默认 `deepseek-flash`**（上游 0.2.2 的模型目录：deepseek-flash / deepseek-v4-pro，上下文 1M，
   `max_tokens` 默认 256000），不是 deepseek-chat。

## 四、已知问题 / 技术债（按优先级）

1. **多轮缺 thinking 回传**：目前历史只回 text，没有回 `thinking` 块 + `signature`。对 reasoner/长会话可能影响
   质量或触发 400；契约 #1 要求逐字节一致，必须补。
2. **system 提示词是桌面快照**：包含 32 个工具的描述，但我们还没发 tools；需要按 `docs/port/02` §3
   的 19 段规则做**动态拼装**（含 cwd/时间/工具段），并补运行时上下文 user 消息。
3. **没有工具循环**（M2）：`tools` 未发送、无 tool_use/tool_result、无审批。
4. **会话列表全量解压**：41 条大会话时列表会慢，需要「只读首帧取 header + 读尾部取标题/摘要」。
5. **Markdown 未渲染**：聊天正文是纯 Text；M2 接 Operit 的流式渲染器。
6. **设置页文案**：Base URL 副标题还写着 OpenAI；API Key / 账号通道要做出二选一与状态显示。
7. **没写单测/对拍**：门 2 对拍台尚未开工；`core:session` 的 v4 读取需要 fixture 测试。
8. **cwd 是 App 私有长路径**，生成的 workspace 目录名很长（`--data-user-0-...--`）；迁移/导出前要定一个稳定的
   工作区根（例如 `/workspace`，实际映射 filesDir）。
9. 其它：无会话删除/回收站、无标题 LLM 生成、无附件、无主题切换、无图标（Manifest 还没挂 launcher icon）。
