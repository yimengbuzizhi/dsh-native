## 一、请求金标准（契约 #1 回归）

1. 调试通道 `--es dsh_dump_request <绝对路径>`：下一次 `buildRequest()` 生成后把 **请求体原样** 写入该文件（仅 debug 包）。
2. 真机抓了一份 account 通道的请求，存为 `core/protocol/src/test/resources/request-golden.json`（10.5KB）。
3. `RequestGoldenTest`（`:core:protocol:test`）三条断言：
   - 反序列化再序列化 **逐字节相同**（守住 encodeDefaults / explicitNulls / 键序）；
   - 顶层键序 = model → stream → messages → max_tokens → thinking → output_config → system → tools；
   - stream=true、thinking.type=enabled、system/tools 非空。
   结果：3/3 通过。

换上游版本时的流程：重新抓一份 → 替换 fixture → 跑测试；差异就是契约 #1 的变更点。

## 二、停止（中断）修复

- 之前 `stop()` 只置 `streaming=false`，**半截回复不会落库**（取消时 `lastAssistantText` 还是上一轮的值）。
  现在运行中维护 `liveText/liveReasoning/liveSignature`，取消时按实际内容写 assistant/message + endStep + endTurn("aborted")。
- 只输出到思考就被停止的情况也会落库（否则这一轮在会话里凭空消失）。
- `stop()` 同时把最后一条 assistant 消息的 `streaming` 置 false，思考块不会一直显示"思考中"。
- 真机验证：2000 字长文生成中停止 → 状态条消失、发送键恢复、思考块定格在 3246 字（`docs/shots/m4-stop.png`）。

## 三、会话管理

- 长按会话行 → 重命名 / 删除；删除是**移动到 `sessions/.trash/`（不真删）**，列表与 `findFile` 都跳过 `.trash`。
- 列表按天分组（今天 / 昨天 / 本周 / 日期）。
- 真机验证：10 条 → 删除 1 条 → 9 条，`.trash` 里出现对应目录。
