## 一、上下文面板「对话消息」不统计

### 旧实现（HEAD `50c584a`）
- 三段里的系统/工具是字符估算（`estimateTokens`），对话 = `lastPromptTokens − 系统 − 工具`、`coerceAtLeast(0)`。
- 缺陷是**减法项**：估算只要偏高，对话就被压成 0；估算口径（系统/工具）和真实 prompt tokens 不是一回事。

### 旧包复现情况（如实记录）
- **没有**在旧 APK 上截到「对话消息 = 0」：本机当前插件集下（121 个工具）用旧公式在真实请求上复算
  `18,852 − 1,304 − 15,673 = 1,875`，不是 0。用户看到 0 的场景应是估算更高（插件更多 / 系统提示词更长 /
  刚压缩过），本机没造出同样条件。**「旧包复现 0」= 未复现**；缺陷机理（减法 + 钳 0）已由代码与复算确认。
- 复算用的真实请求：`--es dsh_dump_request …/files/req-m83-1.json`，`system` 5,147 字符、`tools` 121 个 /
  66,799 字符、`messages` 1,544 字符；同一轮 `usage` 显示 `18852 in`。

### 新实现
- `AppViewModel.recordPromptBreakdown(state, request)`：在 `onRequest`（请求真正发出前）用**这一份请求体**
  现算三段字符并折算 token：
  - 系统 = `request.system`；
  - 工具 = 每个 tool 的 `name + description + input_schema.toString()`；
  - 对话 = `request.messages` 里 text/thinking/tool_use/tool_result 的文本（图片按块，不把 base64 字符数当 token）。
- 面板（`ChatComposer.ContextPanel`）把三段按真实 `usage.prompt_tokens` **等比校准**后显示，三段相加 = 已用：
  `scale = used / (系统 + 工具 + 对话)`，对话 = `used − 校准后系统 − 校准后工具`（此时不再依赖估算是否偏高）。
- 面板底部说明改成「三段都按最近一次请求体现算，再按真实 prompt tokens 等比校准」。

### 真机证据
| 时刻 | 真实 usage | 面板三段 | 截图 |
| --- | --- | --- | --- |
| 发 1 条消息后（session `Reply`） | `18851 in / 269 out` | 1.4K / 17.0K / **464**，合计 ~18.9K | `118-02-context-panel.png` |
| 同会话再发 1 条（ping-three） | `19068 in / 105 out` | 1.4K / 16.9K / **732**，合计 ~19.1K | `118-06-panel-after2.png` |

- 对话消息 **> 0**（464 → 732），随对话增长（prompt +216，对话 +268）**PASS**。
- 三段合计与「已用」一致（~19.03K vs 19.1K，差在四舍五入）**PASS**。
- 三段与真实 usage 的误差来源：字符折算 vs 真实分词、图片按块、消息结构开销；总量以真实 `prompt_tokens` 为准。

## 二、平板常驻侧边栏四角/边缘白色空白

### 复现（旧包，`118-07` 之前）
- `wm size 1440x2560; wm density 320`（≈720×1280dp，`screenWidthDp ≥ 600` 走宽屏常驻抽屉）。
- 浅色主题下看不出；**深色主题**下侧边栏右上、右下角各一块 **#FAFAFA 白色缺口**：
  像素 `(600,4)`、`(605,10)`、`(600,h-4)` 都是 `(250,250,250)`（截图 `117-05-tablet-dark.png`）。
- 根因：`PermanentNavigationDrawer` 内部再套一层 `PermanentDrawerSheet`（Material3 默认
  `surfaceContainerLow` 容器色 + 圆角），圆角外的区域既不属于抽屉也不属于正文，露出的是这层默认容器色/窗口底色。

### 修法
- `App.kt` 宽屏分支不再用 `PermanentNavigationDrawer`，改成普通 `Row`：
  `Box(304dp, fillMaxHeight) { DshDrawer(permanent = true) }` + `1dp` 分隔线（`c.line`）+ 正文。
- `DshDrawer` 新增 `permanent` 参数：`true` 时不套 `ModalDrawerSheet`，直接一块直角、铺满高度的 `c.surface` 面板；
  窄屏 `false` 保持原 Modal 抽屉（圆角、滑出）。

### 真机证据
- 同尺寸（1440×2560 @320，深色）复测：`(600,4)`、`(605,10)`、`(600,h-4)` 都是 `(19,26,38)`（= `c.surface` #131A26），
  分隔线 `(608..609)` = `(36,49,73)` = `c.line` → **无白角 PASS**（截图 `118-07-tablet-dark-after.png`）。
- 浅色平板（修复前）对照 `117-01-tablet-before.png`。
- 验完已 `wm size reset; wm density reset`，竖屏手机截图 `118-13-drawer-phone.png` 正常。

## 四、模型 pill 太长挤发送钮

### 根因
- 控件行没有权重约束：pill `widthIn(max=190dp)` 固定，右侧圆环/齿轮/加号/发送都是固定宽；
  360dp 手机上总宽超出后，Compose 让**行里靠后的无权重子项**（发送钮）先被压小。

### 修法（`ChatComposer`）
- 控件行包一层 `BoxWithConstraints`：先算 `pillMax = maxWidth − 176dp`（右侧固定控件 ≈ 圆环 48 + 36 + 36 + 44 + 间距 10，
  留 2dp 余量），pill 只吃剩余宽度（`widthIn(max=pillMax)`，文本 `weight(1f, fill=false)` + 省略号）；
  发送钮仍是固定 `44dp` 的 `SendOrb`，不参与任何权重/压缩。
- 顺带把 pill 左右内边距 10→9dp、箭头 16→15dp，360dp 手机上默认模型 `deepseek-flash` 仍能完整显示。

### 真机证据
- 默认模型：`118-05-ping3-sent.png`（pill 完整显示 `deepseek-flash`，发送钮正常）。
- 长模型名：`/model deepseek-v3.2-reasoner-experimental-preview` 切过去（`118-11-long-model-pill.png`）：
  pill 显示 `deepseek-v3....` 省略号，圆环/齿轮/加号/发送钮尺寸与位置不变；
  局部对照 `118-15-pill-compare.png`（上=短名，下=长名，右侧四个控件逐像素一致）**PASS**。
- 验完已 `/model deepseek-flash` 还原（顶栏与 pill 都回到 `deepseek-flash`）。

## 六、阶段 4（远程 DSH）已定决策——**先记下，阶段 4 再执行**

> 2026-11-13 18:0x 用户明确拍板，实现时必须按这套来，不要回头改成「WebView 打开 DSH 网页」。

1. **不用 WebView 打开 DSH 网页**：远程连接用鲸歌自己的页面；DSH 只当后端，会话 / 消息 / 工具 / 审批
   都映射到现有原生页面（会话列表、聊天页、工具卡、审批弹层）。
2. **不改电脑上的 DSH**：不装插件、不改代码/配置。PC 侧只放一个**独立的小助手**（单独进程/脚本）。
3. **小助手**：读 `~/.dsh/.credentials.yaml` 里的 `client-connection` / `browser-session.secret`，
   自己签 cookie → 在局域网 / Tailscale 上开一个带 token 的转发 → 显示二维码 / 短码。
   **secret 只在电脑本机**，不传给手机、不进仓库。
4. **连接方式像无线调试**：按需连、不常驻；跑任务时要有前台服务 + 常驻通知（复用 `TurnKeepAliveService`），
   任务结束或断开就退出。
5. **手机端连接页**：地址 / 令牌 / 扫码、测试连接、连接状态、断开、断了提示重连。
6. **部署交给用户的 AI**：写一份「给 AI 的部署契约」，用户把链接丢给自己电脑上的 AI 就能配好。
7. 终局目标看 `docs/HANDOFF.md` 顶部 + `docs/115`；M83 做完继续往下，不停。
8. 交接：做不完/上下文不够时用内置 `handoff_topic`（`permission: danger-full-access`，brief 自包含，
   先更新 HANDOFF 顶部），不要再用 PowerShell 脚本。
