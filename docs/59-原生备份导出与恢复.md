## 二、备份格式 v1

```
manifest.json                                  # 类型/版本/计数/每会话 sha256
settings.json                                  # 按类型分组，见下
sessions/<workspace-slug>/<id>/session.v4.jsonl.zstd
sessions/<workspace-slug>/<id>/imported.json   # 仅旧版只读会话
plugins/plugins.json                           # path 已替换成插件 id（不含本机绝对路径）
plugins/<id>/...                               # 插件包原文件
attachments/objects/xx/<sha256>                # 内容寻址附件（可选）
```

`manifest.json` 关键字段：

```json
{"type":"dsh.native.backup","version":1,"createdAt":1794078542610,
 "appVersion":"0.2.0-m1",
 "includes":{"settings":true,"plugins":true,"attachments":true,"credentials":false},
 "sessions":[{"id":"…","workspace":"----","legacy":true,"bytes":1452,"sha256":"…"}],
 "plugins":[{"id":"dsh-plugin-zconfig","name":"…","version":"0.1.0","enabled":true,"bytes":1026}],
 "counts":{"sessions":283,"plugins":1,"settingsKeys":19,"attachmentsFiles":7,"totalBytes":8094562},
 "warnings":[]}
```

`settings.json` 按 `SharedPreferences` 的类型分组（Int 不能恢复成 Long，否则 `getInt` 会崩）：

```json
{"strings":{"model":"deepseek-flash","theme_mode":"system"},
 "booleans":{"expand_thinking":true},
 "ints":{"max_tokens":256000},
 "longs":{},
 "floats":{"temperature":0.7},
 "stringSets":{"recent_models":["deepseek-flash"]}}
```

目录布局沿用 v4：`<root>/<workspace-slug>/<id>/session.v4.jsonl.zstd`，恢复就是把原文件搬回去，
所以**不需要迁移链**，也不改会话内容。

## 三、安全与恢复语义

| 规则 | 做法 |
|---|---|
| 密钥不进包 | 导出前过滤 `api_key` / `account_token`；`debug_*` 调试键也不导；manifest 标 `credentials:false` |
| 内部路径不进包 | `plugins.json` 的 `path` 写成插件 id；恢复时用当前 `files/plugins/<id>` 重写 |
| 不覆盖现有数据 | 同 id 会话跳过；已存在插件目录跳过；已存在附件跳过；清单记录只补缺 |
| 完整性 | 每个会话在 manifest 里带 sha256，恢复时逐文件校验；不对就失败并清理暂存目录 |
| 路径守卫 | zip entry 只接受规范相对路径；`..`、绝对路径、反斜杠一律拒绝 |
| 大小上限 | 单会话 512MB / 单据插件文件 64MB / 单附件 256MB |
| 只读边界 | 旧版导入会话的 `imported.json` 一起备份/恢复 → 恢复后仍只读 |

**这是明文 zip**：里面有完整对话，用户分享/上传前要自己注意；App 不做加密（用户没要求，先不发明）。

## 四、实现

| 层 | 文件 | 职责 |
|---|---|---|
| `:core:backup`（新，JVM） | `NativeBackup.kt` | 导出 / `inspect` / 恢复会话 / 恢复插件 / 恢复附件 / 读设置；路径守卫 + sha256 |
| `:core:plugins` | `PluginModel.kt` | `PluginRegistryFile.mergeFromRegistryJson(text, pathFor)`：只补缺、重写路径 |
| App | `data/BackupManager.kt` | 目录/设置快照（按类型、过滤密钥）；恢复顺序：会话→插件→附件→设置 |
| App | `ui/settings/BackupScreen.kt` | 本机数据统计、导出（SAF `CreateDocument`）、恢复（`OpenDocument` + 确认弹窗）、结果卡 |
| 导航 | `ui/App.kt` / `SettingsScreen.kt` | `SubScreen.Backup`；入口「备份与恢复」，chip「不含密钥」 |
| 调试通道 | `MainActivity` / `AppViewModel` | `--es dsh_backup_export <路径>` / `--es dsh_backup_import <路径>` |

恢复顺序刻意是「会话 → 插件 → 附件 → 设置」：设置放最后，前面失败也不会先把界面设置改掉。

## 七、边界（诚实清单）

1. **恢复设置后要重启**：`SettingsStore` 在 ViewModel 构造时读一次 prefs，备份页恢复后只写盘；
   页面有「立即重启生效」按钮。没重启时其他页仍显示旧值。
2. **跨设备工作区路径**：会话按 `header.cwd` 原样恢复；如果新设备上没有这个目录，聊天能看，
   工具写入会失败。还没做「恢复到当前工作区」的映射。
3. **旧版备份设置不导**：旧版 `DSH备份-*.zip` 里的 `settings.yaml` / `.credentials.yaml` 仍然不导入；
   旧版导入的会话仍然只读（docs/23 的边界不变）。
4. **明文 zip**：没有密码/加密；包含完整对话与附件。
5. **没有断点/增量**：每次全量；大附件多时导出会慢（一次 IO 线程，页面只有转圈）。
6. **UI 没截图**：设备锁屏；备份页/设置入口只编译 + 调试通道验证。解锁后第一件事补截图
   （备份页空态、导出完成、恢复确认弹窗、恢复完成）。
7. **manifest 没有消息数/标题**：避免导出时全量解压；页面统计用本机 `SessionRepository.list()`。
