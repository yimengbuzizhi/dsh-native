# 166 · M85-E：存储/提示词/模型契约化（storage/v1 + prompt/v1 + model/v1）

> 2026-11-14 09:0x。按 `docs/144` §3/§7/§8 做 **M85-E**：把会话存储、系统提示词、模型通道
> 从「宿主写死」变成三个**可停用 / 可同 id 覆盖 / 不享受宿主特权**的插件角色。
> 真机：OPPO A55 5G（PEMM00 / 720×1600 / Android 13）；本批未发布（0.3.2 / versionCode 5）。
> 演示插件：`docs/m85e-readonly-storage/`（只读导出存储）、`docs/m85e-mark-prompt/`（同 id 提示词）、
> `docs/m85e-model-override/`（同 id 模型覆盖）。

---

## 1. 结论

1. **默认存储 = 内置插件 `builtin.storage.jsonl`**：现有 `FileSessionRepository` 原样登记成插件
   （沿用 `files/sessions/` 的 JSONL + zstd 帧，磁盘布局/回收站/分支一个字节没改）；
   关掉 = **存储安全提示**（会话列表为空、发送被拦），可一键恢复。
2. **存储可换（v1 只读）**：第三方插件用 `ctx.storage.register({id,label,readOnly,list,load})`
   声明导出器；选中/同 id 接管后，会话列表与打开由插件提供，打开的是**只读会话**；
   写入路径 v1 不开放，停用即回内置可写实现，原文件不受影响。
3. **默认提示词 = 内置插件 `builtin.prompt.dsh`**：现有 `PromptPack` 原样跑（段/order/变量/
   角色卡/插件段/抑制运行时上下文全部与 M84 一致）；第三方 `ctx.systemPrompt.register` 拿到
   内置结果作为 `base` 改写，同 id 接管；关掉 = **提示词安全提示**（发送被拦）。
4. **模型通道 = 内置插件 `builtin.model.deepseek` / `builtin.model.openai`**：现有
   `LlmClient` / `OpenAiClient` 登记成插件；第三方 `ctx.llm.register` 声明同 id 即覆盖；
   选中通道被停用/不存在时**如实报错**（`LlmEvent.Failed`），不悄悄换回内置供应商。
5. **M84-B 142/142 PASS**（M85-E 最终 APK，`docs/m84b-check-m85e-final.json`）。

## 2. 实现

### 2.1 storage/v1

- `:core:session` 新增 `StorageContract.kt`（纯 Kotlin）：`storage/v1`、`builtin.storage.jsonl`、
  `StorageCandidate`（storageId/pluginId/builtin/enabled/permitted/readOnly）、
  `ResolvedStorage`、`StorageResolution`，选择规则 `StorageRouting.resolve`：
  | `dsh_storage` | 解析 |
  |---|---|
  | 空 / `builtin.storage.jsonl` | 默认角色：同 id 第三方优先，否则内置 JSONL |
  | `native` | 强制内置实现（不给同 id 接管） |
  | `插件id` / `插件id#存储id` / 存储 id | 精确选择 |
  | 未安装 / 停用 / 缺 `storage` 授权 | `Unavailable(reason)`（安全提示，不回退） |
  | 同 id 覆盖插件停用 | 回退内置实现（覆盖后回退原实现，不丢数据） |
- 单测 `StorageRoutingTest` **10/10**。
- `SessionStore` 增加 `readOnly`（默认 false）；`MemorySessionStore`/`FileSessionRepository` 不变。
- `:core:plugins`：`ctx.storage.register`（只读 list/load）→ 常驻 dispatch `storage.list` /
  `storage.load`；`PluginStorage` 元数据进 `plugins.json`（readOnly 强制 true）；新权限
  `storage`（导入即允许、选中才生效）。
- 宿主 `app/data/RoutingSessionStore.kt`：可换绑的路由壳（内置 file / 插件只读 / 不可用），
  默认仍是原 `FileSessionRepository`；`PluginSessionStore.kt`：把插件返回的会话摘要 / 原始
  JSONL 文档解成只读 `SessionSession`；写路径明确失败。
- 只读导出器的宿主原语：`ctx.storage.exportList()` / `ctx.storage.exportLoad(id)`——只读
  **内置**会话，不递归活动存储；需要 `storage` 授权。演示插件用它给标题/预览加 `[导出] `，
  证明列表/打开确实经过插件。
- 调试通道：`--es dsh_storage <id|native>`、`--es dsh_roles_list <路径>`。

### 2.2 prompt/v1

- `:core:prompt` 新增 `PromptContract.kt`：`prompt/v1`、`builtin.prompt.dsh`、
  `PromptCandidate`/`ResolvedPrompt`/`PromptResolution`、`PromptRouting.resolve`
  （默认/同 id/native 强制/停用/缺授权/覆盖回退）；单测 `PromptRoutingTest` **9/9**。
- `:core:plugins`：`ctx.systemPrompt.register({id,label,assemble})`；常驻 dispatch
  `prompt.assemble({base,model,provider,tools,planMode,personaPrefix,personaSuffix,variables})`；
  `PluginPrompt` 进 `plugins.json`；新权限 `prompt`（导入即允许、选中才生效）。
- 宿主 `buildSystemPrompt`：内置/调试实现仍走原 `PromptProviders.build`（M84-E1/E2 的插件段、
  变量、`suppressRuntimeContext` 全部不变）；第三方把内置结果当 base 改写；插件运行失败
  → **回退 base + 横幅提示**（不让插件 bug 打挂整轮）；停用内置且无替代 → 发送被拦。
- 调试通道：`--es dsh_prompt <id|native>`；请求体 dump（`--es dsh_dump_request`）可直接看到
  插件追加的标记。

### 2.3 model/v1

- `:core:llm` 新增 `ModelContract.kt`：`model/v1`、内置插件 id `builtin.model.deepseek/openai`、
  `ModelCandidate`/`ResolvedModel`/`ModelResolution`、`ModelRouting.resolve`：
  - `llmProviderId` 空 → 按协议兜底（openai → openai，其余 → deepseek）；
  - 同 id 第三方优先；内置插件停用/通道不存在 → `Unavailable(reason)`；
  - 内置插件 id（`builtin.model.*`）映射到 provider id；
  - 单测 `ModelRoutingTest` **7/7**。
- 宿主：`registerBuiltinProviders` 按内置模型插件开关注册；`syncPluginLlmProviders` 先收回
  内置两条通道再按开关重注册，插件 provider 后注册（同 id 覆盖）；`llmStream` 用
  `ModelRouting` 解析，选不中时返回 `LlmEvent.Failed(code=MODEL_UNAVAILABLE)`（如实报错）。
- debug 供应商（`debug.echo` 等）仍优先且不参与角色解析（M84-C 验收通道不变）。
- 调试通道：`--es dsh_model <provider id|off>`（off = 跟随协议）、`--es dsh_roles_list`。

### 2.4 UI

- 插件页新增「存储插件 / 提示词插件 / 模型插件」三组（`RoleTargetUi`）：显示内置/第三方、
  使用中/选择/不可用原因、只读标记，点行切换；一键恢复内置存储/提示词/跟随协议。
- 聊天页：存储/提示词安全横幅（各自「恢复内置」按钮）；只读存储会话底部说明改为
  「存储插件会话 · 只读」（不再误显示成旧版导入副本）。
- `RoleTargetUi`/`RoleSafetyNotice` 在 `ui:shell-api`，`NativeShellHost` 增加三角色读数与操作。

## 6. 没做 / 限制（不许当成已完成）

1. **第三方存储 v1 只读**：只开放 `storage.list/load`，不开放新建/写入/回收站/分支；
   完整可写 storage/v1（SQLite/远端/加密）留给后续版本，接口已按契约留位。
2. **投影 checkpoint 仍是宿主缓存**（`files/projection-checkpoints.json`）：只读存储插件打开
   的会话不会再产生新事件，因此不会写新 checkpoint；把 checkpoint 完全下放给 storage 插件
   不在本批（docs/144 §7 的「随 storage 契约走」只完成默认实现沿用原文件）。
3. **提示词插件失败会回退内置拼装**并亮提示（不让插件 bug 打挂整轮）；这是运行期容错，
   不是「选不中悄悄回退」——选不中（停用/缺授权）在发送前就被拦。
4. **模型角色没有新增权限**：沿用 M84 的 `ctx.llm.register`；第三方 provider 仍需用户
   在模型配置/插件页显式选中，停用后如实报错。
5. **JS agent 的 `ctx.storage.append` / `ctx.llm.stream` 仍未开放**（M85-D 的 UNSUPPORTED
   保持原样）；本批只做「角色契约化」，没有重写回合里的存储/模型原语。
6. **同 id 覆盖只验证 storage/prompt/model 三个角色**；native 实现仍不做 DEX 动态加载。
7. 未发布；发布树/tag/Release 一律未动。
