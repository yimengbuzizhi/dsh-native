## 一、做了什么

| 位置 | 变更 |
|---|---|
| `PluginModule` PRELUDE | `ctx.on(event, handler)` 把 handler 存进 `__dshEventHandlers[event]`（每事件最多 32 个），订阅名照旧进 `__dsh.subscriptions`；`ctx.effect(fn)` 把 fn 返回的 cleanup 存进 `__dshCleanups`。 |
| `PluginModule.RESIDENT_DISPATCH` | 新 `__dshEmitEvent`：一条会话事件先做投影 fold，再按 `event.type` 调 handler；同时支持 DSH 的通用 `session/event` 和 `*`。新 `shutdown` 方法：停用/重载前跑所有 cleanup。返回值新增 `handled`。 |
| `PluginModule.residentScript` | 启动返回值新增 `subscriptions` / `cleanups`，供宿主判断这个插件需不需要常驻。 |
| `PluginResidentRuntime` | 起常驻 runtime 的条件从「有投影」扩到 **有投影 / 有事件订阅 / 有清理器**；`stop()` 先 `dispatch('shutdown')`（3s 超时）再关 runtime；dump 增加每个插件的 subscriptions/cleanups；每次事件带 `handled>0` 时打 logcat。 |
| `AppViewModel.dumpProjections` | 改成 IO 协程 + `awaitSettled()`（最多等 3s），避免「刚启用就 dump」把常驻运行时误读成不存在。 |
| 插件详情 UI | `ctx.effect` / 事件订阅两段文案改成真实语义（不再写「没有常驻运行时，不回调」）。 |

### 事件协议（宿主 → 插件）

```text
__dshDispatch('session.event', {
  sessionId, header,
  event: { type, seq, time, data, surfaceOp? }
})
→ { ok, keys, values: [...], errors: [...], handled: N }
```

- 投影 fold 先跑，再跑订阅者；同一条会话事件一次 dispatch 完成（一次 JNI 往返）；
- handler 参数：`(event, { name, sessionId, header })`；
- handler 可以返回 Promise：宿主**不等**它，异常写进插件的 `errors`（下一次 dispatch 的返回里能看到）；
- `ctx.on('session/event', fn)` 收所有会话事件；`ctx.on('*', fn)` 同样收全部；
- `__dshDispatch('shutdown', '{}')` → `{ ok, cleaned: N, errors: [...] }`，cleanup 返回 Promise 同样不阻塞。

## 三、限制（照实说）

1. **只有会话事件进 `ctx.on`**：宿主事件总线目前只投递会话日志事件（`request/header`、`turn/*`、
   `step/*`、`message`、`tool/*`、`session/*` …）。别的宿主事件（设置变更、悬浮窗、网络）没有接。
2. **订阅者的返回值没有人用**：`handled` 只表示调了几个 handler；async handler 的异常只进插件错误列表，
   不会中断轮次。
3. **cleanup 只在停用/重载/删除时跑**：进程被杀不会跑（Android 上没有可靠的析构时机）；`ctx.effect`
   仍是「注册 cleanup」的语义，不是通用生命周期钩子。
4. **handler 计数是 runtime 生命周期级**：不是会话级（演示插件打印的 `#1` 每次 App 重启从 1 开始）。
5. **顺序**：同一条事件里投影 fold 先于订阅者；不同插件之间是各自的 runtime，互不影响也不保证顺序。
6. 未做：`llm.register` 的 `stream` 回调、`ui.registerView`、独立插件页进抽屉、投影 checkpoint、
   `operit-extended-http` 15s、M84-B 142 项重跑；本批未发版。
