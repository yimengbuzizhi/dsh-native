# 136 · M84-K 插件整页进抽屉（独立插件页入口）

> 2026-11-13 21:2x（Asia/Shanghai）｜开发版仍是 **0.3.2 / versionCode 5**，本批未发布。
> 补 `docs/132`（G）的限制：「独立插件页只从插件详情 Activity 打开，没进抽屉/设置」。

---

## 一、做了什么

| 位置 | 变更 |
|---|---|
| `AppViewModel.pluginPageEntries()` | 列出「启用 + 有 `dsh.client` + `page:true`」的插件路由；**排除 id 与宿主内置页同名的**（那些已经从内置页入口打开插件页，重复列会出现两个入口）；同 route id 去重。 |
| `AppViewModel.openPluginPageEntry()` | 用 `PluginPageActivity.open(context, record, routeId)` 打开插件自己的整页（和插件详情「以整页打开」同一条链路）。 |
| `DshDrawer` | 会话列表下方、底部动作条上方新增「插件页面」段：每行 = 插件页标题 + 插件名，点击打开；最多列 6 个；`pluginPages`/`onOpenPluginPage` 默认空（不影响其他入口）。 |
| `App.kt` | 把 `vm.pluginPageEntries()` 映射成 `PluginPageShortcut` 传给抽屉；点击先 `closeDrawer()` 再打开 Activity。 |

没有新页面、没有改路由表：仍然只有「页面路由元数据来自插件清单」这一份真相。

## 二、真机验收（OPPO A55 5G，PEMM00，Android 13）

用已有演示插件 `m84e2-demo`（注册了 `page:true` 的 `/m84e2`，另外还把 `About` 整页替换成插件页）。

| # | 操作 | 证据 |
|---|---|---|
| 1 | 启用 `m84e2-demo` → 点左上角菜单开抽屉 | 会话列表下方出现「插件页面」段：**E2 演示页 / m84e2-demo**；抽屉里工具数 129（`136-01.png`）；被替换的「关于」页**没有**重复列出 |
| 2 | 点「E2 演示页」 | `mCurrentFocus=Window{… xin.dshaa.nativeapp/xin.dshaa.nativeapp.pluginui.PluginPageActivity}`；页面顶部「E2 演示页 / 插件页面 · m84e2-demo」，内容 `M84-E2 · dsh.client`、`这是 m84e2-demo 自己的页面`、`route /m84e2 · 宿主不重画`（`136-02.png`） |
| 3 | 返回 → 停用 `m84e2-demo` → 再开抽屉 | 「插件页面」段消失，工具数回到 128（插件工具被收回）（`136-03.png`） |

设备已恢复：`m84e2-demo` **停用**（与进入本片前一致）、无障碍 Bound、`dsh_llm_provider` off。

## 三、限制

1. **入口只在抽屉**：设置页没有另一份插件页入口；抽屉最多显示 6 个，更多的仍要去插件页点「以整页打开」。
2. **只收 `page:true`**：普通 `registerRoute`（非整页、打开插件窗口）不进抽屉。
3. **同名替换不重复列**：和内置页同 id 的页（About 等）通过内置入口打开插件页；抽屉不会再多一行。
4. 抽屉重排后会话列表少一行左右的可见高度（固定高度抽屉，最多少 6 行插件入口）。
5. 未做：`ui.registerView`、插件模型的工具回合/逐 token 流、投影 checkpoint、`operit-extended-http` 15s、
   M84-B 142 项重跑；本片改动了抽屉与 App 壳，按纪律应重跑 M84-B 页面回归（未跑，记入 HANDOFF）。
6. 本批未发版。
