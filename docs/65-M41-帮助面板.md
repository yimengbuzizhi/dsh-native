# 65 · M41：`/help` 命令帮助面板

日期：2026-11-08 04:02–04:2x（第三十五棒，接 M40）
基线：`70ff04c` + M41

> 补 `docs/06`「命令面板」的最后一块发现性问题：以前只有输入 `/` 才会弹出命令菜单，
> 想不起命令名 / 参数写法时没有入口。这一轮加 `/help`：不带参数列出全部宿主命令（点一行把用法
> 插进输入框），带参数直接在 notice 里给单条用法和说明。
> **上游 `/help` 没有随启动器发布**（`.upstream` 只有 launcher，没有包源码），文案按客户端习惯自己写；
> 命令表仍与 `/` 菜单、派发共用 `DSH_COMMANDS`，所以不会出现「帮助里有、点了却没反应」。
> **设备整夜锁屏**（04:0x `mDreamingLockscreen=true`），面板没有截图，只有「请求被 Compose 消费」
> 的日志与不崩溃证据；样子等解锁后补拍。

## 一、一句话结果

- `/help` → 打开「命令」底部面板：`plan` / `model` / `permission` / `help` 四条，
  每条一行完整用法（`/model [名字]`）+ 说明；**点一行把 `/name ` 插到光标处**，
  不覆盖已有草稿，焦点还给输入框；
- `/help plan` → notice：`/plan [off|消息]：进入或退出计划模式：模型先出方案，批准后再执行`；
- `/help nope` → notice：`没有这个命令：/nope。输入 /help 查看全部命令`，不改任何设置；
- 三条路径都**不建会话文件、不写 command 事件、不产生模型消息**（与 `/model`、`/permission` 一致）；
- 命令表新增 `CommandChoice.insertText()`：带参数的命令补一个尾随空格，光标落在参数位；
- 单测：`:core:input` 18 → **19 条**；全量 15 模块 **399 条 0 失败 0 错误**（57 个测试类）。

真机（PLT120，锁屏调试通道，04:05 包）：

## 二、规则

| 输入 | 结果 |
|---|---|
| `/help` | 打开命令帮助面板（4 条，当前 `DSH_COMMANDS` 全量） |
| 点面板里一行 | 在光标处插入 `/plan ` / `/model ` / `/permission ` / `/help `，关闭面板，输入框取回焦点 |
| `/help plan` | notice 给这一条的用法 + 说明；不弹面板 |
| `/help /plan` | 同上（参数容忍一个前导 `/`） |
| `/help nope` | 拒绝：「没有这个命令：/nope。输入 /help 查看全部命令」 |
| `/help 名字 有 空格` | 查不到 → 拒绝（不静默降级） |
| 只读会话 / 旧版导入副本 | `submit()` 之前就拦掉，命令不执行 |
| 与 `/model`、`/permission` 同 | 不建会话、不写日志事件（只改客户端/面板） |

为什么不建会话：帮助面板纯客户端 UI，上游也不会有「看一眼帮助就多一个会话」的行为；
`/plan` 仍照旧建会话并写 `command/run`（它真的作用于 agent）。

## 三、实现

| 层 | 文件 | 改动 |
|---|---|---|
| `:core:input` | `CommandCatalog.kt` | 新增 `/help [命令名]` 条目；`CommandChoice.insertText()`（无参数只放名字，有参数补空格） |
| `:core:input` | `CommandCatalogTest.kt` | 目录断言改为 4 条；新增 `helpInsertTextLeavesCursorAfterCommand`：插入文本必须仍能被 `parseCommandLine` 解析 |
| App | `ChatSessionState.kt` | `CommandSheet.HELP`（第三个一次性面板信号） |
| App | `AppViewModel.kt` | `submit()` 派发 `help`；`executeHelpCommand()`（面板 / 单条 / 未知）；`DshCmd` 日志 |
| App | `ChatComposer.kt` | `helpSheet` 状态；`LaunchedEffect` 的 `HELP` 分支；「命令」面板（`heightIn(max=380)+verticalScroll`，命令变多也不截断）；`insertCommandText()` 按 `selection.end` 插入并把焦点还给输入框 |

面板骨架复用 M40 的 `ModalSheet`（Operit agent popup 同层，22dp 圆角底部卡片），
行样式与 `/model` 的「最近使用」一致（`clip(12dp)` + 点击整行）。插入位置做了越界收敛：
面板打开时输入框失焦，`TextFieldValue.selection` 可能指向旧文本的末尾。

## 八、边界（诚实清单）

- **没有 UI 截图**：锁屏未解，帮助面板的样子（行距、长说明折行）只有编译 + `sheet: HELP consumed`
  日志保证；「点一行插入」这条交互**没有真机点过**，只有单测覆盖插入文本、Compose 代码复用现成行样式；
- 帮助面板只列**宿主命令**，不列技能：技能来自工作区、数量可变，仍走「设置 → 技能」和 `/` 菜单；
  `/help <技能名>` 现在会报「没有这个命令」（以后可接技能帮助）；
- 上游 `/help` 文案/行为没抄到（启动器不含包源码），**不是逐字移植**，与客户端习惯对齐；
- 插入是「光标处插入」，输入框里已有草稿时会接在后面而不是替换（有意，避免吃掉用户写了一半的话）；
- 面板行点击后不自动发命令，只填输入框——参数还得用户自己补（`/help` 的定位就是「想起来怎么写」）；
- 名字叫 `help` 的技能会被宿主命令遮蔽（目前没有这样的技能）。
