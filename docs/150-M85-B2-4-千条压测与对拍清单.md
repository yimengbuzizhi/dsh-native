## 1. 1000 条消息压测

构造了一个**合成会话**并真机打开（不动用户已有会话）：

- 生成器：`tools/gen-m85b2-1000-session.py`（v4 JSONL + 每行独立 zstd frame，与 app 存储格式一致）
- 会话 id：`9c9fa399-8630-4752-8ce4-36686e35e58f`，标题「M85B2 1000 条压测」
- **3103 个事件 / 1000 条可见消息**（500 轮 × user+assistant）+ 50 个 bash 工具卡
- 原始 JSONL ≈ 1.11 MB，压缩后 ≈ 558 KB
- 每轮 assistant 正文含 Markdown 列表 + 3 段长文本（约 300 字符/段），用来压 Markdown 测量
- 安装：`run-as` 落到 `files/sessions/<workspace-slug>/<id>/session.v4.jsonl.zstd`；
  验收后已从设备删除（避免污染用户会话列表），文件保留在 `docs/m85b2-1000-session.zstd`

真机结果：

| 场景 | 结果 | 证据 |
|---|---|---|
| Surface 壳打开 | 标题/会话条正确；直接落到第 1000 条，底部渲染正常；`shell.mount` 259ms | `docs/shots/m85b2-39-stress-shell.png` |
| Surface 壳滚动 | 4 次慢滑 + 25 次快滑从底部退到第 961 条；无 `FATAL`/`ANR`/`OutOfMemory` | `m85b2-44-stress-shell-scroll.png` |
| legacy 打开 | 同一会话同一标题/内容，底部渲染正常 | `m85b2-42-legacy-stress.png` |
| legacy 滚动 | 5 次滑动退到第 995/996 条，思考折叠/Response 头正常 | `m85b2-43-legacy-stress-scroll.png` |
| 资源 | 两壳都没有 OOM；上下文指示 2% | 截图、logcat |

已知限制：

- 这次压的是「消息多」而不是「单条超长」：单条消息的 Markdown 测量没有构造 100KB 级正文。
- 嵌套工具卡只到 50 个（每 10 轮一个），没有做「每条消息多个工具卡 × 1000」的极端组合。
- 自动滚到底依赖 `LaunchedEffect` 的布局时机；首次打开如果布局未就绪，可能停在顶部（本轮没复现，
  但逻辑上仍有窗口）。后续可改成 `LazyListState` 的首帧回调。
