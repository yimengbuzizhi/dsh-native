## 一、这一轮的目标

上一轮（docs/49）把插件页做到了「导入 → 解析 → QuickJS 试运行 → 报错可见」，但 `ToolRegistry` 是启动时
静态注册的，插件注册的工具**没有接进对话**。这一轮把这条链路打通：

```
插件页导入/启用
  → 试运行拿到每个工具的名字/说明/参数
  → 参数归一成模型 API 能接受的 JSON Schema
  → 注册进 ToolRegistry（运行时可变）
  → 下一次请求的 tools 里出现插件工具
  → 模型调用 → 每次新建 QuickJS 实例跑插件 execute → 结果作为 tool_result 回到对话
```

按 docs/49 §六.2 的建议，**先打通链路、只做无副作用/纯计算工具**；文件、网络、shell 的 shim 和
manifest 限权留到下一轮（见 §六）。

## 二、实现

### 1. `core:tools`：ToolRegistry 支持运行时注册

`ToolRegistry` 从「构造时固定列表」改成「线程安全的名字表」：

- `register(tool)`：同名（含内置工具）拒绝，返回 false——插件不能覆盖内置工具；
- `unregister(name)`：注销；
- `tools` / `names` 每次返回当前快照；`execute` 按名字现查。
- 请求体工具顺序 = 插入顺序：内置在前，插件在后（与上游 `tools` 数组追加语义一致）。

`ToolRegistryTest` 新增 1 条（注册/同名拒绝/注销）。

### 2. `core:plugins`：参数 schema + 调用脚本

试运行脚本（`PRELUDE`）现在除了记工具名/说明，还记参数：

```js
const __params = __dshSchema(def.parameters);
let __state = 'ok';
if (def.parameters === undefined || def.parameters === null) __state = 'missing';
else if (__params === null) __state = 'unsupported';
```

三种参数写法分别处理（`PluginSchema.kt`）：

| 写法 | 例子 | 处理 |
|---|---|---|
| 标准 JSON Schema | `{type:'object', properties:{…}, required:[…]}` | 原样使用 |
| **DSH / ToolPkg 简写** | `{ todos: { type:'array', required:true, … } }` | 包成 `{type:'object', properties:{…}, required:[…]}`，删掉字段上的 `required` 布尔 |
| schemastery | `parameters: z.object({…})` | 试运行拿不到 JSON（代理是函数），标记 `unsupported`，**不注入**，插件页写「参数认不出，未接入」 |

> 查了上游 `@deepseek-ai/dsh-tool-todo` 的实现：内置工具的参数用的正是第二种简写
> （`parameters: { todos: { type:'array', required:true, … } }`），所以这个归一化不是为我们自己的
> fixture 造的，真实 DSH 工具插件也能命中。

`invokeScript()` 生成「跑模块 → apply(ctx) → 调 `__dshDefs[tool].execute(args, exec)`」的脚本：

- 每次工具调用**新建一个 QuickJS 实例**，重新跑模块/`apply`，再做 execute；
- `execute` 返回 Promise 时 `Promise.resolve(...).then(...)` 等它结算（QuickJS 桥本来就等根 Promise）；
- 返回统一成 `{ok:true,text}` / `{ok:false,error}`；字符串原样、`{text:string}` 取 text、其他对象 `JSON.stringify`；
- 异常带 `name/message/stack` 原文返回，不吞。

`PluginModuleTest` 新增 4 条（参数捕获/简写归一/调用脚本/结果解析），`PluginSchemaTest` 新增 4 条；
`:core:plugins:test` 现在 **24 条全过**（Package 8 + Module 12 + Schema 4）。

### 3. `:app`：PluginToolRuntime + 每次插件变更同步

新文件 `app/.../data/PluginToolRuntime.kt`：

- `refresh(records)`：只取「已启用 + 目录里有入口 + schema 可用」的工具，按工具名去重（重名跳过并打日志）；
- `apiTools()`：转成 `ApiTool`（name/description/input_schema）；
- `toolFor(binding)`：包成 `DshTool`，`execute` 里在 IO 线程跑 QuickJS；
- **超时看门狗**：到 `ToolContext.timeoutMs` 调 `QuickJs.interrupt()`，插件写 `while(true)` 也只会得到
  「插件执行超时」，不会把一轮对话焊死；异常一律归成 `ToolResult.err`。

`AppViewModel`：

- `syncPluginTools()`：先注销上一批插件工具名，再按最新清单注册；同步 `pluginApiTools` 与
  `pluginInjected`（插件页展示「已接入 N」）；
- 冷启动 `init` 里同步一次；导入/启用/停用/重载/删除后都同步；
- 两处 `EngineDeps.apiTools` 改为「内置工具 + 插件工具」，**每次请求现取**，所以启用/停用下一轮就生效；
  子代理也共享同一份注册表（`childApproval` 仍按审批策略走）。

UI（`PluginsScreen`）：

- 卡片新增「已接入 N」chip；
- 详情里逐个工具标 `✓ 已接入` / `（插件已停用）` / `（参数认不出，未接入）`；
- 页脚文案改成真实边界：JSON Schema 或 DSH 简写会接入、schemastery 暂不注入、fs/网络仍是空实现。

调试通道（仅 debug 包）：

- `--es dsh_plugin_call <工具名> --es dsh_plugin_args_b64 <base64>`：不经过模型直接调一次插件工具
  （锁屏/无 UI 也能验宿主链路）；
- `--es dsh_plugin_args '{"…"}'` 也能用，但 adb shell 会把引号吃掉，**建议用 b64**（本轮踩过：
  `{text:hello native}` 不是合法 JSON，最后退化成 `{}`，表现为 `echo: undefined`）。

## 五、边界（别在群里夸口）

- **不是安全沙箱**：`node:fs` / `http` / `child_process` 仍是空实现（读文件返回空串、网络返回宽松代理），
  所以目前真正能跑的是纯计算/格式转换类工具。文件/网络权限等 manifest 限权那一轮，按 docs/04 §七做。
- **schemastery 参数暂不注入**：需要 schema 转换（或宿主提供最小 `z` 实现）。认不出就不接，不猜。
- **异步 `apply` 仍不等**：`apply` 返回 Promise 时试运行只提示；如果工具是在 `await` 之后才注册，
  调用时会报「插件没有注册工具 X」。DSH 内置工具都是同步注册，暂时够用。
- **重名跳过**：插件工具与内置工具/别的插件重名时，`ToolRegistry` 拒绝注册，logcat 打
  「工具名冲突，未注入」；不覆盖内置工具。
- **每次调用重跑模块**：插件初始化有副作用（写文件等）时会重复执行；等常驻运行时/沙箱那一轮再优化。
