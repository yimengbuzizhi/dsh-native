## 一、提示词注入：`ctx.systemPrompt.variable` + `{{name}}` 替换（用户点名）

**之前为什么插件人设进不了 system**：社区插件（`dsh-persona-card` / `dsh-cosplay` 等）主流写法是
`ctx.systemPrompt.variable('cosplay_active', () => …)` + 段文本 `{{cosplay_active}}`；鲸歌 shim 把
`variable` 记为 unsupported，`PromptPack` 只替换 `{{model}}/{{provider}}` → system 里只剩字面量。

本批实现（三层）：

1. **shim**（`core/plugins/.../PluginModule.kt`）：`systemPrompt.variable(name, fn)` 在 `apply` 时
   **求值一次**（手机端没有常驻 JS 运行时，和函数型 `section.text` 同一套处理）；容忍
   `variable({name, value/fn})` 对象写法；Promise 值跳过（不拿 `[object Promise]` 覆盖）；
   对象值 `JSON.stringify`。`unsupported` 里对应的条目删掉。
2. **记录持久化**（`PluginModel.kt`）：`PluginDryRun` / `PluginRecord` 新增
   `promptVariables: Map<String,String>`，`plugins.json` 里存 `promptVariables` 对象
   （`PluginStore` 安装与 `PluginReload` 重载都带上）。
3. **渲染**（`core/prompt/PromptPack.kt`）：`systemFor(..., variables)` 里用一条正则做插值：
   `{{model}}`/`{{provider}}` 由宿主给，其余查插件变量快照，**未知变量原样保留**
   （宁可让模型看到 `{{nope}}`，也不悄悄清空）。`AppViewModel.pluginPromptVariables()`
   只取启用中插件的变量（同名的后注册覆盖）。
   另外把**插件 `context` 段**也接上同一套插值：它是 user-role 快照、不走 system 拼装，
   本批之前 `插件上下文：角色={{character}}` 会原样进请求（真机 dump 发现后补的）。

**⚠ Android 专属坑（务必记住）**：占位符正则结尾的 `}}` **必须转义**。
`Regex("\\{\\{([A-Za-z0-9_.:\\-]+)}}")` 在 JVM 单测里正常，真机 ICU 正则直接抛
`PatternSyntaxException: Syntax error in regexp pattern near index 24` —— `PromptPack` 静态初始化崩溃，
App 一启动就闪退（进程死、`turn end after 1243ms`）。改成 `\\}\\}` 后正常。
**JVM 正则比 Android ICU 宽松，这类字符类别/量词结尾的问题只能真机发现。**

## 五、引用附件 / 引用包「发一大长串」（23:23 新增）

**根因**：`AppViewModel.send` 把引用内容当**额外 text 块**塞进这一轮（`"[附件: 名字]\n\n" + 全文`
或 `<attachment …/>`），聊天页把所有 TEXT 块拼起来渲染 → 整段原文铺在气泡里。
模型侧必须拿到全文（工具/上下文都靠它），所以**只改渲染**：

- `ChatScreen.UserMessage` 把 TEXT 块分成「普通文本」与「引用块」，引用块渲染成
  `QuotedAttachmentChip`：`📎 文件名 · 12.3 KB · N 行 · 点开看原文`，**默认折叠**，
  点一下展开（限高 240dp 内滚动，等宽字体）。`<attachment …/>`（按路径引用）显示
  「已复制到工作区（模型用 read 读取）」，不可展开。
- 发送时那句模型提示「（带 <attachment> 的附件已复制到工作区…）」抽成
  `chat/ATTACHMENT_REFERENCE_HINT` 常量，气泡里不再显示。
- 覆盖范围：文本附件、插件包引用（`attachPackage` → `ChatMirror.attachText`）、记忆引用，
  都走同一条 `[附件: …]` 形状。
- 调试通道 `--es dsh_attach_text <设备路径>`（新）：把设备上一个文本文件放进待发附件，
  不用 SAF 也能验这条链路。

## 七、诚实限制 / 没做的

1. **变量是 apply 时的快照**，不是每轮求值：插件在运行期改状态（`variable` 返回的闭包里读
   `ctx` 之外的东西）不会自动更新，要「重载插件」才刷新。上游是每轮渲染时求值；
   手机端没有常驻 JS 运行时，这条短期不会变。
2. **`cordis.patch.yml` 只解析「助手预设」这一件事**：不执行 `config:` 里的其它配置、不按 name
   装子插件（和 M61 的只读立场一致）；YAML 解析器是最小子集（不支持锚点/多文档/流式嵌套映射）。
3. **预设套用是复制文本**：套用后就是一份普通角色卡，和插件解耦（插件卸载后卡片还在）。
4. **宽屏断点只有 600dp**：折叠屏半折/平板横屏都吃这一条；没有做「可收起」的常驻抽屉。
5. **引用 chip 只认发送时的两种形状**（`[附件: …]` / `<attachment …/>`）：历史会话里已有的旧消息
   同样会被识别（渲染层规则），但如果是别的形状的第三方文本不会折叠。
6. **发布（F）没做**：用户要求「发布内容先给确认、token 要新的」，留给下一批。
