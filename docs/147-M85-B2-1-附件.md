## 1. 这一片做了什么

把聊天输入条的**附件**接到 Surface 壳：图片（相册）、任意文件、截图，待发列表/缩略图/移除、
历史消息里的图片都走同一套宿主原语；插件只发通用命令，不碰 Activity/文件系统。

- **宿主命令**（`SurfaceSpec.COMMANDS`）：`pickFile`（`kind=image|file|camera`）、`screenshot`、
  `removeAttachment`。和 `send/approval` 一样按白名单落到 `AppViewModel.shellCommand`。
- **选择器交接**：`ShellPickRequest` + `ShellPickKind`。`surface.command` 是同步调用，只登记请求；
  `PluginShellScreen` 用 `rememberLauncherForActivityResult` 消费一次并启动 Photo Picker /
  OpenMultipleDocuments / TakePicture（FileProvider 临时文件），防止连续点击丢请求。
- **复用 legacy 入口**：`attachImage(Uri)` / `attachFile(Uri)` / `attachPhoto(File)` /
  `attachScreenshot()` / `removePendingImage` / `removePendingFile` 一行没重写，
  图片归一化、内容寻址附件、文本内联/二进制复制工作区、无障碍截图 + Shizuku 兜底全部同一套。
- **Surface 协议（通用，不是聊天组件）**：
  - `image` 的 `src` 现在可以由 `bind` 提供（附件缩略图 `bind:item.path`）；
  - `SurfaceRow.Attachment`（kind/name/path/detail），支持 `item.name` / `item.path` / `item.detail`；
  - 消息行增加 `attachments`（历史图片，`bind:item.attachments`）；
  - state 增加 `chat.pendingImages` / `chat.pendingFiles` / `chat.attachError` / `chat.hasAttachments`，
    以及消息级 `attachments` 数组和 `item.hasAttachments`；
  - `shellSignature` 带上待发附件数量：附件从 0→1 时重算树（附件栏显隐），增删也刷新。
- **默认壳 `builtin.shell.whale` 1.1.0**：输入区上方四个入口（图片/文件/拍照/截图）、
  待发图片缩略图 + 移除、待发文件 chip + 移除、附件错误行、历史图片列表；
  只有附件没有文字也能发送（`send` 条件改为 `text || hasAttachments`）。
