## 一、一句话

## 二、单一定义在哪（加原语只改这里）

| 文件 | 作用 |
|---|---|
| `core/primitives/.../PrimitiveCatalog.kt` | 20 个原语的 id / 分组 / 说明 / 参数 JSON Schema / 风险 / 审批 / 可用性 / 跨字段校验 |
| `core/primitives/.../PrimitiveContract.kt` | `PrimitiveHost`、`PrimitiveResult`、`PrimitiveArgs.validate`、插件桥 JSON（`PrimitiveBridgeJson`） |
| `core/tools/.../primitives/PrimitiveTools.kt` | 工具面：`PrimitiveTool` 把目录投影成 `DshTool`；`PrimitiveTools.all` |
| `core/prompt/.../PromptPack.kt` | `androidApiTools()` 直接读目录生成 `ApiTool`（**不再有手写 `tools-primitives.json`**） |
| `core/plugins/.../PluginSandbox.kt` + `PluginModule.kt` | 插件面：`ctx.primitive.invoke/list` → `primitive.invoke/primitive.list` → `PluginPrimitiveBridge` |
| `app/.../chat/AppViewModel.kt` | 原生面实现：`AppPrimitiveHost`（一个 `invoke(id,args)` 分发到 App 已有实现） |

**纪律**：同一个动作不许在工具/插件/原生各写一份实现。工具面只做「目录校验 → `host.invoke`
→ 结果转写」；插件面只做「参数转发 + 错误兜底」；具体执行只在 `AppPrimitiveHost` 里。

三面共用的校验：`PrimitiveArgs.validate` 先查必填/JSON 类型/enum，再跑目录里的跨字段
`validate`（例如 `from_seq <= to_seq`、store 命名空间格式、value ≤64 KiB）。

## 四、三面接口

### 4.1 AI 工具面（模型）

- `PrimitiveTools.all` = 19 个 `PrimitiveTool`，App 启动时注册进 `ToolRegistry`。
- `PromptPack.androidApiTools()` 在 32 个上游工具 + 29 个 Android 工具之后追加这 19 个
  （`32 + 29 + 19 = 80`），schema 逐字来自目录。
- `offeredToolNames()` 按内置插件开关过滤；**子代理工具表摘掉全部原语**
  （`offeredToolNames(includePrimitives=false)`）。
- 工具结果：`summary` 给模型（列表/转写/摘要正文），`data` 里的标量进 `ToolResult.meta`；
  结构化数据留给插件/原生面。

### 4.2 插件桥面（QuickJS）

- 插件里：`ctx.primitive.invoke(id, args)` → `__dshHostJson('primitive.invoke', {id, arguments})`
  → `PluginSandbox.call` → `PluginPrimitiveBridge.invoke` → App 的 `invokePrimitiveForPlugin`。
- `ctx.primitive.list()` 返回目录（只含插件可见项）。
- 返回形状：`{ok, summary, data, code}`（失败也带 `code`：`PERMISSION_DENIED` /
  `INVALID_ARGUMENTS` / `TIMEOUT` / `PLUGIN_HOST_ERROR`…）。
- 线程：QuickJS 常驻运行时自带单线程执行器，调用在 **JS 线程同步阻塞**；App 侧用
  `runBlocking + withTimeout(120s)` 切到主/IO。**主线程调用直接拒绝**（`MAIN_THREAD`），避免死锁。
- P1 只给**常驻运行时**（`PluginResidentRuntime`）挂桥；每次调用新建 QuickJS 的插件工具路径
  （`PluginToolRuntime`）暂未挂桥，`ctx.primitive.invoke` 会收到 `UNAVAILABLE`（P2 再接）。
- 边界：插件桥当前**只读**；`pluginVisible` 是目录字段，不新增插件权限类型（不改插件体系语义）。

### 4.3 原生调用面（Kotlin）

- `PrimitiveHost.invoke(id, args): PrimitiveResult` 是唯一入口；`AppPrimitiveHost` 用 `when(id)`
  分发到 App 已有实现（`repo.fork` / `summarizeCompaction` / prefs / 导航 / 回收站 / `send()` /
  `stop()` / `ToolRegistry.execute` / SharedPreferences）。
- `PrimitiveCaller`（TOOL/PLUGIN/NATIVE）只影响额外纪律：
  - `turn.stop`：TOOL 调用直接拒绝（模型不能停自己的轮次）；PLUGIN 才能停。
  - `turn.send`：只允许前台空闲话题（避免模型给自己排队形成自循环）。
- `tool.call`：按 `ToolCall` 走 `awaitApproval` 同一条审批路径，然后 `registry.execute`；
  拒绝原语 id（递归）与 `ask_user_question/exit_plan_mode/subagent/subagent_fork/workflow`。

## 五、语义约定（P1 定稿，别在组合层重新解释）

1. **“当前话题” = 调用所属的话题**（执行中轮次的话题）。模型在一轮里先 `topic.switch`
   再 `turn.state`，返回的仍是旧话题（status=running）——这是有意的：fork/read/summarize/state
   都以“这一轮属于谁”为准；插件调用没有轮次，看到的是前台话题。
2. **`session.summarize` 只总结已完成轮次**：调用它的这一轮被排除（否则 brief 自指、把
   “去生成摘要”当成待办）。显式 `from_seq/to_seq` 也受这一条限制；没有已完成轮次时报错。
3. **`topic.switch` 是唯一“带上下文开新话题”的通道**：`brief` 作为首条 `user/message`，
   `source.kind="handoff"`；目标话题正在跑时拒绝注入。
4. **`topic.end` = 回收站**：当前轮在跑时只置 `archiveAfterTurn`，收尾后再 `repo.trash`。
5. **`turn.send/stop` 只作用于前台/最近前台**：非前台请先 `session.open`；`turn.send` 不排队。
6. **`store.*` 是 App 内命名空间键值**（`primitive_store` SharedPreferences），不写工作区；
   namespace/key 只允许 `[A-Za-z0-9_.:-]`，value ≤64 KiB。
7. **`tool.call` 不是绕过审批的后门**：外层原语审批 + 内层工具审批；结果最多 16k 字符回模型。

## 八、边界（不夸大）

1. 只有 **arm64** 真机；x86_64、低端机、后台/锁屏未验。
2. 真机只验了上面 A/B/C 三条路径；`session.open`、`turn.send/stop`、`tool.call`、`store.*`、
   `permission.set` 只有 JVM 用例，**没有真机故障注入**。
3. 插件桥只验了**常驻 QuickJS**；工具调用路径（每次新建 QuickJS）未挂桥。
4. 插件桥只读；写原语等 P4 权限模型。
5. `session.summarize` 复用 compaction 的英文 checkpoint 结构（P-1 口径），brief 是摘要而非
   人工整理的决策清单；摘要质量受模型影响。
6. `turn.state` / 默认 `session.read` 是“调用所属话题”，不是“前台话题”。
7. `ui.openContainer` 只是目录登记（P3），**没有实现**；不注册工具、不提供假成功。
8. 未动发布版、tag、Release、`native-publish`、会话格式、UI 外观、插件体系语义。

## 九、加一个原语的流程（后续照做）

1. 在 `PrimitiveCatalog.definitions` 加一条：id/说明/Schema/risk/approval/availability/
   `bridgeVisible`/跨字段校验。
2. 在 `AppPrimitiveHost.invoke` 的 `when` 加分支，执行落到 App 已有实现（**不新写业务流程**）。
3. 目录测试自动覆盖新 id；给新分支补一个 JVM 用例（参数/结果/错误文案）。
4. 若 `risk=READ` 且要开放给插件，确认 `bridgeVisible` 默认成立；否则显式 false。
5. 跑固定命令；真机验一次组合（不能只有单测就说“真机通过”）。
