## 一、助手角色卡（M71）

### 1. 做了什么

`设置 → 助手配置`（`ui/settings/AssistantScreen.kt`）从「名字 + 头像 + 简介」扩成角色卡：

| 字段 | 存哪 | 注入到哪 |
|---|---|---|
| 名字 | `assistant_name` | 人设段开头补一句 `你的名字是「…」。`（人设非空时） |
| 头像 | `filesDir/avatars/assistant_*.img` | 只做 UI（消息头/顶栏/会话列表） |
| 简介 | `assistant_desc` | 只做展示，**不进提示词** |
| 人设 | `assistant_persona` | `deployment:persona-prefix`（order 0）——**替换**上游默认的 coding agent 段 |
| 开场白 | `assistant_opening` | 空会话的问候气泡；**不写进会话历史/提示词**（不伪造 assistant 首条） |
| 系统提示词 | `assistant_system` | `deployment:persona-suffix`（order 10200）——system 全文最后一段 |

人设/系统提示词留空 = 保持上游默认（`emptyPersonaCardKeepsUpstreamSnapshot` 单测锁住逐字节一致）。
名字/头像/简介/开场白都有默认值与占位文案；三个新字段用 `SettingsTextField(singleLine = false)`，
真机点输入框能弹键盘（`dumpsys input_method mInputShown=true`），逐字落 `shared_prefs/dsh.xml`。

### 2. 段拼装：和上游 / 插件同一条路

`core/prompt/PromptPack.kt` 的 `systemFor(...)` 新增三个参数：

- `personaPrefix`：非空时替换基础段 `deployment:persona-prefix`；
- `personaSuffix`：非空时追加 `deployment:persona-suffix`（order 10200，最后一段）；
- `extraSections`：插件 `ctx.systemPrompt.section` 注册的段。

拼装规则（照 DSH `dsh-system-prompt`）：**段名唯一**，按来源顺序覆盖
（基础段 < 角色卡 < 插件段 < `plan:policy`），然后统一按 `order` 升序、同 order 按 `name` 码元序，
`{{model}}`/`{{provider}}` 插值、空段丢弃、`join("\n\n")`。

这样：
- 插件写的人设段（同名 `deployment:persona-prefix`）会**接管**角色卡，而不是拼出两段人设；
- 插件注册的普通段不再像 M57 那样「永远糊在 system 最末尾」，而是按自己的 order 插进正确位置。

`ctx.systemPrompt.context`（运行时上下文）按上游语义回到 **user-role 快照**：
`AppViewModel.runtimeContextText()` 末尾追加（order/name 排序），不再塞进 system。
`dsh_dump_request` 里能看到它落在 `messages[0]`（`Current runtime context…` 那条 user 消息）。

### 3. 单测（`core/prompt`，14 个全过）

新增 4 条：
- `personaCardReplacesDefaultPersonaPrefix`：人设替换默认段，位置在 harness identity 之后、file-reference 之前；
- `personaSuffixIsTheLastSection`：系统提示词必须是全文最后一段；
- `pluginSectionsJoinTheSameAssemblyAndOverrideBySameName`：插件段按 order 入队、同名覆盖角色卡；
- `emptyPersonaCardKeepsUpstreamSnapshot`：空角色卡 = 上游桌面快照逐字节一致。

顺带修了一条**从 M56 就挂着的旧断言**：`androidToolPackExposesTerminalSessions` 还写着
`32 + 18` 个 Android 工具，实际 `tools-android.json` 在 M56 加了 8 个记忆工具（26 个），
改成 `32 + 26`。之前只跑单模块测试没暴露。

## 二、清退三组原生替身（用户点名）

## 四、诚实限制 / 已知问题

1. **开场白只显示不进行史**：Anthropic Messages 首条必须是 user，直接塞 assistant 首条会 400；
   本次只做空会话问候气泡，模型看不到开场白。要「进上下文」得另设计（如首轮 system/context 声明）。
2. **多角色卡 / Agent 预设注册表没做**：当前是单助手一张角色卡；DSH 的 `agent-preset` 多预设切换未移植。
3. **同名段覆盖是宿主约定**：DSH 上游文档只说了排序，没有明说去重；鲸歌按「段名唯一、后注册覆盖」实现，
   以便插件人设接管角色卡。若上游实际是「同名都渲染」，这里是有意的手机端取舍（文档写清）。
4. **插件 context 的位置变了**（M57 在 system 末尾 → M71 回 user 快照）：对按旧行为写的插件无破坏，
   但 `dsh_dump_request` 的对拍口径要改成看 `messages[0]`。
5. 角色卡字段写在 `shared_prefs/dsh.xml`（和 API key 同一个文件），**导出/截图时别把整份 prefs 发出去**。
6. 验收用的测试人设（鲸歌/鲸鱼/回答尽量简短）验证完已清空，设备上角色卡恢复为空（名字仍是「鲸歌」）。
