日期：2026-11-08 05:07–05:3x（第三十九棒，接 M44）
基线：`a960876` + M45

> M44 只做了「step 起点的压力压缩」——压力值是**启发式**（4 字符 1 令牌）而且比真实值偏小，
> 真到窗口边上的请求仍然会被 provider 直接拒绝（HTTP 400）。本轮把上游

## 一、一句话结果

- `Compaction.isContextOverflow(code, message)`：逐字抄上游
  `isContextWindowExceededError()` 的五条正则 + `CONTEXT_WINDOW_EXCEEDED` code 直判；
  DeepSeek 真实回的是 `invalid_request_error` + 文案，所以走的是文案分支；
- `TurnEngine` 的模型请求放进 `while (true)` 重试环：识别溢出 → `compactOverflowingSurface()`
  （阈值不要、`retainTokens=0`、整面对讲摘要）→ 成功后**复用同一条占位消息**重发，
  不新开 step/气泡；预算 `MAX_OVERFLOW_RETRIES = 1`（上游默认）；
- 压缩没成（没有可选区间 / 摘要不比原文小 / 摘要失败）→ 保留原始错误、照旧 `turn/end{error}`；
- 调试通道 `--es dsh_overflow_once "<provider 报错文案>"`（仅 debug 包，消费一次自动清掉）：
  让下一条请求假装 400 溢出，锁屏也能验整条链路；
- 单测 **435 条 / 60 个测试类 0 失败 0 错误**（+6：`CompactionTest` 3 条识别规则、
  `TurnEngineTest` 3 条溢出/非溢出/无区间）；
- 真机（PLT120，锁屏数据通道）`0c974ab4…`：第 3 轮注入溢出 → 4.3 秒压掉 5 条 2038 令牌 →
  2.9 秒重发成功 → `turn/end{completed}`；第 4 轮请求体只剩 3 条消息（运行时上下文+checkpoint /
  上一轮回复 / 新输入），两篇长散文已不在请求里。

## 二、上游依据（宁抄勿研）

`D:\dsh021\node_modules\@deepseek-ai\`：

1. **识别**（`dsh-llm/lib/types/error.js` 第 45–69 行）：
   `STRUCTURED_CONTEXT_OVERFLOW`、`maximum|max … context length|window`、
   `TOO_LARGE_FOR_CONTEXT`、`…too long for this model`、`EXCEEDS_MODEL_CONTEXT` 五条正则，
   大小写不敏感；适配器把命中文案归一成 `CONTEXT_WINDOW_EXCEEDED`；
2. **恢复入口**（`dsh-compaction-basic/lib/index.js` 第 861–887 行）：
   `agent/request-error` 里 `failure.code !== CONTEXT_WINDOW_EXCEEDED` 直接放过；
   否则 `maxOverflowRetries`（默认 1）内做 `compactIfNeeded(agent, "context-overflow")`，
   压缩真的改写了会话面（`replaceGeneration` 增加）才返回 `{kind:"retry"}`，
   失败只警告、保留原始请求错误；
3. **最大压缩**（同文件第 927–935 行）：溢出触发**不看阈值**，先跑工具结果修剪（若装了），
   再 `selectCompactableRange(session, measurement, 0)` —— 保留预算 0，即「除了最后一条，
   全压」；最后一条留在会话面上与 checkpoint 一起重发；
4. **重试语义**（`dsh-agent-loop/lib/index.js` 第 1128–1146 行）：`action.kind === "retry"`
   时 `continue` —— 在**同一个 step 里**重新组请求、重新流式，不写新的 `step/start`；
   失败的那次尝试只落一条 `assistant/attempt`（原生没有这种事件，见 §四）。

|---|---|
| `core/engine/Compaction.kt` | `isContextOverflow()` + 五条上游正则；`CONTEXT_OVERFLOW_CODE`、`MAX_OVERFLOW_RETRIES`；类注释补 M45 |

### 3.1 识别

`code` 先直判 `CONTEXT_WINDOW_EXCEEDED`（忽略大小写），否则把 `code + " " + message`
拼成 detail 跑五条正则。**不认**「只是出现 context 这个词」——
`loaded the context window metadata`、`context: 1234 tokens used` 都算不溢出（有单测锁）。

### 3.2 压缩与重发

- 选区：`Compaction.selectRange(nodes, 0)` —— 从最后往前累计，攒够 0 就停，于是保留最后一条；
  边界不退工具结果（与上游 `toolPairingBalancedBefore` 同义）；
- 事件：`compaction/start{turn}` → 摘要 → `compaction/summary`（`shadowedRange` / `shadowedSeqs` /
  `shadowedTokenCount` / provider / model / maxTokens / usage，**没有** `sourceCommandId`）→
  `user/message`（`surfaceOp:replace`，`source.kind:"compact-checkpoint"`）→ `compaction/end{turn}`；
- 重发：压缩成功后清空这次尝试的流式累积（文本/思考/签名/工具调用/stopReason/token 计数/
  `errorText`），复用同一个 assistant 占位气泡（`assistantIndex` 重新定位到最后一条），
  再 `buildRequest(ui.messages().dropLast(1))` 发一次；
- 失败：`compaction/end{error}` 照写，原始错误重新挂回气泡、`turn/end{error}`，不重发。

### 3.3 调试通道（真机锁屏用）

```
adb shell "am start -n xin.dshaa.nativeapp/.MainActivity \
  --es dsh_open_session <id> \
  --es dsh_overflow_once 'This model has a maximum context length of 1048576 tokens, but your messages resulted in 1200000 tokens. Please reduce the length of the messages.' \
  --es dsh_send '请用两句话总结上面两篇散文共同的意象。'"
```

⚠️ 两个坑（本轮踩了）：
- **文案里不要有单引号**：`model's` 会把设备端 `sh` 的引号打断（`/system/bin/sh: no closing quote`）；
- `adb shell am start … --es k "多 词 文 案"` 在 PowerShell 里会被拆参（`pkg=model` 这种怪 intent），
  稳妥写法是**整条命令包成 adb 的一个参数**，设备侧用单引号：
  `& $adb shell "am start … --es dsh_overflow_once 'xxx' --es dsh_send 'yyy'"`。

## 四、与上游的差别（全部有意，写在这里避免下轮重复研究）

1. **重试预算按 step 计**（局部变量），上游按 agent 计、收到 `assistant/message` 或 idle 才清零。
   原生压一次若仍超，会话面已经没有可压的东西（`retainTokens=0` 也只能留最后一条），
   再重试没有收益；所以下一步的重试预算重新从 1 开始，但**同一 step 内绝不循环**；
2. **没有 `assistant/attempt` 事件**：原生 v4 事件集里没有这个类型，失败的那次尝试除了会话面
   什么都没落（也就没有「attempt 记录」）；
3. **没有工具结果修剪（`toolResultPruner`）与图片卸载**：溢出恢复也就少了一步前置瘦身；
   中文场景里工具结果通常不是主因，先不做；
4. **`compactionRetries` 循环仍然没有**：溢出压缩只压一次；
5. 识别只看 `code` 与 `message`，不看 provider 的 `type` 字段（原生 `LlmClient` 只解析
   `error.type` 当 code，没有 type 维度）。

  保留原始错误（与上游 `selectCompactableRange → null` 同义）。
