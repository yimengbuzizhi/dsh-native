## 一、一句话结果

- 新增 `/compact`：把较早的历史压成一条 `source.kind:"compact-checkpoint"` 的 user 消息
  （前言 + `<compacted-summary>` + 摘要 + 闭标签），最近一段原样保留，**不消耗模型轮次**；
- 六条日志事件与桌面逐字段同形：`command/run` → `compaction/start` → `compaction/summary` →
  替换消息（`surfaceOp:{op:"replace",startSeq,endSeq}` + `sourceEventSeqs`）→ `compaction/end` →
  `command/done`；
- 重开会话时 `surfaceOp` 生效：旧历史被顶掉，只铺 checkpoint + 保留段
  （此前原生读桌面压缩过的会话会把摘要和旧历史一起铺出来）；
- 单测 **+11 条**（`CompactionTest` 8 + `CompactionEventsTest` 3），全量 **423 条 / 60 类 0 失败 0 错误**；
- 真机（PLT120，锁屏数据通道）：两个会话真实压缩成功，会话文件字段与桌面同形，
  压缩后请求体只带 checkpoint + 保留段。

## 二、上游依据（宁抄勿研的抄法）

两台机器上的实证：

1. **桌面真实会话**（`C:\Users\user\.dsh\sessions`，65 个 v4 文件里 2 个压缩过）：
   `session-9922ad59…` seq 1439-1445、`session-b2feb17d…` seq 2492-2498 完整记录了一次 `/compact`；
2. **上游源码**（`D:\dsh021\node_modules\@deepseek-ai\`，0.2.1-rc.2）：
   `dsh-compaction-basic`（选区 + 事务 + 摘要提示词）、`dsh-command-compact`（命令文案）、
   `dsh-token-meter`（令牌启发式）、`dsh-client-ui-*`（界面文案）。

### 2.1 事件形状（照抄桌面样本）

| 事件 | data 字段 | 备注 |
|---|---|---|
| `command/run` | `commandId, name:"compact", args:"", source:{kind:"user"}` | 与 `/plan`、`/model` 同一套 |
| `compaction/start` | `compactionId, sourceCommandId, turn:null` | 手工压缩没有所属轮次 |
| `compaction/summary` | `compactionId, sourceCommandId, summary:[text], rawOutput, llmStreamCall:true, shadowedRange:{start,end}, shadowedSeqs:[…], shadowedTokenCount, provider, model, maxTokens, usage{inputTokens,outputTokens,cacheReadTokens,cacheWriteTokens,totalTokens}` | 字段**一个不多一个不少**（与桌面 JSON 键序一致） |
| `user/message`（替换消息） | `content:[前言+开标签, 摘要, 闭标签], source:{kind:"compact-checkpoint", compactionId, sourceCommandId}, role:"user", id` + 根上 `surfaceOp:{op:"replace",startSeq,endSeq}`、`sourceEventSeqs:[startSeq, summarySeq, …shadowedSeqs]` | 三段 text，块 0 固定 321 字符（300 前言 + `\n\n` + 19 字符开标签） |
| `compaction/end` | `compactionId, sourceCommandId, turn:null`（失败加 `error`） | 失败也必须关一次，不能留孤儿 start |
| `command/done` | `commandId, kind:"success"/"error", text, sourceEventSeq:summarySeq` | 成功文案 `Compacted N history items (~T tokens).` |

selection 的 `shadowedSeqs` 只含**模型可见**消息（`user/message`、`assistant/message`、`tool/result`），
`shadowedRange` 是首尾 seq 的闭区间（中间可以隔着 `step/*` 等日志事件）。

### 2.2 选区算法（`selectCompactableRange()`，lib/index.js 第 410-433 行）

```
从最新往回累计每条消息的启发式令牌价，攒够 retainTokens 就停（keepFromIdx = 停下的那条）
边界若落在工具结果上就继续往回退（工具调用与结果必须同侧）
keepFromIdx 退到第一条 ⇒ 没有可压缩区间（null）
被压缩区间 = [0, keepFromIdx-1]
```

### 2.3 令牌启发式（`dsh-token-meter`）

`CHARS_PER_TOKEN = 4`、`BLOCK_OVERHEAD = 4`；文本块 `ceil(len/4)+4`，
tool-call 块 `ceil(name/4)+ceil(args/4)+4`，image 块按附件引用 JSON 长度，每条消息再 `+4`。

### 2.4 摘要请求（`COMPACTION_INSTRUCTION`，34 行）

system 用当前拼装结果、工具用当前清单、messages = 被压缩区间的逐条投影，最后追一条固定指令
（八小节 Markdown：Primary Request and Intent / Key Technical Concepts / Files and Code /
Errors and Fixes / Pending Jobs / Current Work / Next Step / Critical Context）。
摘要输出上限 `maxTokens = 65536`（上游 `maxTokens` 默认 = `headroomTokens`）。
**只收文本**：reasoning 进 `rawOutput`，不进 checkpoint。

### 2.5 命令文案（逐字）

| 场景 | 文案 |
|---|---|
| 成功 | `Compacted {N} history items (~{T} tokens).` |
| 没有可压缩历史 | `No compactable history yet.` |
| 带参数 | `Usage: /compact (no arguments)` |
| 忙（轮次中/已在压缩） | `Compaction is unavailable because this process has an active compaction, or the agent is not idle.` |
| 摘要没变小 | `Compaction could not produce a useful summary. The attempt is recorded in the session log.` |
| 区间变了 | `The history selected for compaction changed before it could be replaced. The attempt is recorded in the session log.` |
| 取消 | `Compaction cancelled.` |

## 四、与上游的差别（全部有意，写在这里避免下轮重复研究）

1. **只做手工路径**：自动阈值压缩（`thresholdRatio 0.8` / `headroomTokens 65536` / `compactionRetries` /
   溢出恢复 `CONTEXT_WINDOW_EXCEEDED`）没搬——原生没有 token meter，也没有路由容量概念；
2. **保留预算**：上游 `retainTokens = floor((W - O) × 0.16)`；原生用「当前历史价 × 0.16，下限 2048」
   现算（`Compaction.retainBudgetFor`），这样小会话不会因为「保留区比历史还长」永远压不动；
3. **工具结果修剪 / 图片卸载**（`compaction/tool-result-pruner`、`compaction/image-offload`）没搬，
   因此也不会写 `compaction/prune`、`image/offload`；
4. **`compaction/summary-error` 没写**：上游在「摘要请求失败」时同步写这条、留给恢复监听器；
   原生失败直接写 `compaction/end{error}` + `command/done{kind:"error"}`，语义更简单；
5. **摘要请求不带运行时上下文**：原生运行时上下文是每请求现拼的前缀，不在会话面里；
6. **摘要请求带工具清单**（与上游一致，为前缀复用），但原生本来就没有 KV 缓存收益，纯为同形；
7. **会话内搜索排除 checkpoint**：与时间上下文/技能目录同一条规则（内部注入不参与搜索）。
