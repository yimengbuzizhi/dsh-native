## 三、隐私与数据清理（`ui/settings/PrivacyScreen.kt` 新增）

原来设置里那行只是 `onClick = onOpenBehavior` 的占位 + 「待做」chip。现在：

- **占用情况**：网页缓存与本地存储（`app_webview`）、临时文件（`cacheDir`）、插件本体、会话历史、记忆库，
  逐项算大小（读不到给「—」）；
- **可以清理**（每项二次确认，清完提示清了多少）：
  ① 网页缓存与 Cookie（WebStorage + CookieManager + WebViewDatabase + flush）；
  ② 临时文件（清空 `cacheDir`）；③ 头像内存缓存（`AvatarLoader.clear()`）；④ 上面两项一起；
- **不会动的东西**白纸黑字列出来：API Key / 账号令牌、插件本体与配置、会话历史、记忆库、助手配置、技能；
  并给一个「打开对话历史管理」的入口（要删会话去那儿）；
- 设置页那行改成真入口（`onOpenPrivacy`），去掉「待做」。

## 四、提示词注入 / 助手配置类 DSH 插件的调研结论（下一步用）

子任务实测了桌面版 `D:\dshdsh\resources\app.asar` 里的 DSH 0.2.2-rc.1 与 npm 上的社区插件，要点：

1. **官方没有「角色卡」这个概念**：官方是 `preset`（id + 一串 cordis 子插件行）+ `persona`
   （`prefix`/`suffix` 两段文本）。内置 4 个预设（standard/ptc/minimal/cordis）就是 4 个 `presets/*.patch.yml`。
2. **插件注册人设的唯一规范写法**是 `ctx.systemPrompt.section({name, order, text})`
   （字段是 `text` 不是 `content`；同名重复注册会抛错）→ 鲸歌 shim 已支持，`PluginRecord.promptSections` 就是它。
   另有 `ctx.systemPrompt.variable(name, fn)` + 段文本里写 `{{name}}` 的**主流社区写法**。
3. **鲸歌现在看不见插件人设的直接原因**：社区插件（`dsh-persona-card`、`dsh-cosplay` 等）大量用
   `variable('xxx', …)` + `text: '{{xxx}}'`；鲸歌 shim 把 `variable` 记成 unsupported，`PromptPack`
   只替换 `{{model}}`/`{{provider}}` → system 里只剩字面量 `{{cosplay_active}}`。
4. **没有 `ctx.agentPreset.register` 这种写法**（真名是 `ctx.agentPresets.register`，且由
   `@deepseek-ai/dsh-agent-preset` 行调用），`package.json` 里也**没有**任何人设/提示词字段。
5. 社区同类插件（都带 `dsh.client`）：`dsh-persona-card@0.1.0`（SillyTavern 风，`shell.overlay` 面板）、
   `dsh-cosplay@0.5.1`（`settings.section` 角色库 + 远程方法）、`dsh-tavern@2.8.1`、
   `dsh-soul-md@0.12.2`、`dsh-agent-persona@0.2.2`、`dsh-system-prompt-studio@0.2.1` 等 12+ 个。

**下一步（建议按这个顺序）**：

1. shim 实现 `ctx.systemPrompt.variable(name, fn)`（apply 时求值一次存进记录）+ `PromptPack` 把
   `{{name}}` 替换成实际值 —— 这一条做了，`dsh-persona-card` / `dsh-cosplay` 这类插件的人设就能真进提示词；
2. 解析 `cordis.patch.yml` 的 `config:` 子树（现在 `BundlePatchParser` 只记 `hasConfig`），
   把 `@deepseek-ai/dsh-agent-preset` 行的 `id/name/description/order` 和其 `plugins[]` 里
   `@deepseek-ai/dsh-persona` 的 `prefix/suffix` 读出来，在助手配置页显示成「插件预设」并可一键套用；
3. 助手配置页的插件段加「预览拼装结果」按钮（把当前角色卡 + 插件段按 order 拼出来给用户看）。

## 五、诚实限制 / 没做的

1. **插件 `variable` 还是不支持**（见 §四.3），所以「插件自带角色卡的正文」目前只能看到占位符
   `{{xxx}}`，还没做替换；助手配置页列的是**段定义**，不是渲染后的文本。
2. 多助手**没有「按会话绑定」**：切换是全局的（所有会话用同一份），会话级覆盖留到后面；
   已有会话从**下一轮请求**开始用新助手（system prompt 每次请求现算）。
3. 助手配置**没有导入/导出**（Operit 那种 JSON 角色卡文件），也没有头像裁剪（只支持选图）。
4. 隐私页的清理动作只真机点了「清理网页缓存与 Cookie」；「临时文件 / 全清」没逐个点。
5. 头像文件仍然只有一份目录（`files/avatars`），删除角色卡不会回收它的头像文件。
