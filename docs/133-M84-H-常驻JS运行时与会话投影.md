## 一、问题与做法

之前 `core:js` 的 `QuickJs` 是「一次 `evaluate` = 新建 runtime、根 Promise 结算后销毁」。
插件 `apply(ctx)` 里 `ctx.sessionProjections.register(...)` 注册的 `apply(state, event)` 是闭包，
runtime 一销毁就没了，所以这条能力只能标 unsupported。

M84-H 加了一个**常驻**形态：

| 层 | 新增 | 说明 |
|---|---|---|
| `core/js` C++ | `JsMachine::Start/Dispatch/Shutdown` | `Start` 建 runtime + 装 hook + 跑启动脚本，**不销毁**；`Dispatch` 在同一个 runtime 里调 JS 全局 `__dshDispatch(method, payloadJson)` 并等它结算（返回值可以是普通对象或 Promise）；`Shutdown` 释放。`Run`（workflow）语义不变。 |
| `core/js` Kotlin | `QuickJsSession` | 自带单线程执行器；`start` / `dispatch` / `interrupt` / `complete` / `close`。JNI runtime 只被这一条线程碰，宿主事件按投递顺序串行进 JS（投影折叠依赖顺序）。超时（启动 20s / dispatch 5s）到点 interrupt。 |
| `core/plugins` | `PluginModule.residentScript()` + `RESIDENT_DISPATCH` | 与试运行同一份 PRELUDE/宿主桥/模块包装；启动脚本跑完 `apply` 后装 `globalThis.__dshDispatch`。 |
| `core/plugins` | `sessionProjections.register` 真实现 | 定义留在 JS（`__dshProjectionDefs` + 每会话 cell），元数据进 `__dsh.projections`，返回可 await 的宽松 handle（`key` / `stateOf` / `dispose`）。没有 key / 不是对象仍记 unsupported，不假装成功。 |
| `core/plugins` | `PluginProjection` + 记录持久化 | `plugins.json` / 试运行结果新增 `projections`（key / stateVersion / hasView / hasApply）。 |
| `core/session` | `SessionSession.addEventListener` | `appendRaw` 落库后同步回调（异常吞掉，不影响落库）；给投影一个单一事件源。 |
| `app` | `PluginResidentRuntime` | 只给「启用 + 有 projections」的插件起常驻 runtime；事件入队、按序 dispatch、值按 `(会话, 插件, key)` 存内存；停用/删除/重载关闭并收回；打开会话时重放历史事件。 |

### JS ↔ 宿主协议（本片用到的部分）

```text
host → JS  __dshDispatch('projection.event', {
             sessionId, header, inheritedEventCount: 0,
             event: { type, seq, time, data, surfaceOp? }
           })
JS → host  { ok, keys: [...],
             values: [{ key, seq, view }],     // 只在 apply 返回新引用时出现
             errors: [{ key, error }] }
```

- `init(header, inheritedEventCount)` 每会话每 key 懒初始化一次；
- `apply(state, event)` 必须**同步**：返回 Promise 记为插件错误（照 DSH 的同步纪律）；
- 不关心的事件返回**同一个 state 引用** → 零下游工作（DSH 的 `Object.is` 门）；
- `wire.view(state)` 有就取视图，没有就落 state 本身；也不允许返回 Promise。

### 开关联动

`AppViewModel.syncPluginTools()` 末尾调 `PluginResidentRuntime.sync(...)`，所以导入 / 启用 / 停用 /
重载 / 删除都会同步：启用且有投影 → 起 runtime；停用 → 关 runtime 并收回该插件的投影值。
`LiveChat.handle` 的 setter 挂 `attach(session)`，新会话拿句柄即收事件；打开旧会话先重放已有事件。

## 二、真机验收（OPPO A55 5G，PEMM00，Android 13）

演示插件 `docs/m84h-demo-plugin`（`m84h-demo` 1.0.0，`inject=['sessionProjections']`）：
注册 key `m84hTurns`（v1，有 `wire.view`），`apply` 只数 `turn/start` / `user/message` /
`assistant/message` / `tool/result`，其余事件返回同一个 state 引用；另有 `m84h_ping` 工具证明同一插件
工具照旧可用（工具仍是每次调用新建 QuickJS）。

| # | 操作 | 证据 |

| 1 | `--es dsh_plugin_zip …/m84h-demo.zip` 导入 | logcat `DshProjection: resident started plugin=m84h-demo keys=m84hTurns`；`DshPlugin: 已导入 m84h-demo 1.0.0；注册 1 个工具：m84h_ping` |
| 2 | 冷启后 `--es dsh_dump_projections` | `{"capabilities":"m84.4","resident":["m84h-demo"],"plugins":[{"id":"m84h-demo","keys":["m84hTurns"]}],"values":[],"errors":[]}`（`docs/m84h-1.json`） |
| 3 | `--es dsh_send …` 真跑一轮 | 逐事件回调：`seq=1 turn/start → turns 1`、`seq=3 user/message → userMessages 1`、`seq=4 user/message → 2`、`seq=5 assistant/message → assistantMessages 1`；dump `seq=5`（`docs/m84h-2.json`） |

### 验收通道（仅 debug）

- `--es dsh_dump_projections <绝对路径>`：常驻插件、key、投影值、最近错误落盘；
- `--es dsh_plugin_off <id>` / `--es dsh_plugin_on <id>`：单个导入插件开关（可同时带
  `--es dsh_dump_projections`，用来验「停用即收回」）；
- logcat tag `DshProjection`：resident started/stopped、attach、每条 `projection ... seq=… view=…`。

## 三、限制（明确未做，别当成已完成）

1. **只对注册了投影的插件起常驻 runtime**：其余插件仍是「每次调用新建 QuickJS」；
   `ctx.on` 的事件订阅、`ui.registerView`、`ctx.effect` 的 cleanup 还没有接到这个 runtime 上。
2. **投影值只在内存**：App 重启靠打开会话时重放日志重建；没有持久化 checkpoint（DSH 有
   `session-projection-cache`），大会话重放成本随事件数线性增长（本机 9 条事件，毫秒级）。
3. **没有 zod 校验**：`stateSchema` / `wire.viewSchema` 只记录「有没有」，不校验值；投影回调返回
   Promise 会被记成插件错误，但不做深层 schema 报错。
4. **单会话重放**：只重放 App 打开过的会话；后台会话没有 attach，投影按需（下次打开）才折。
5. **插件 `llm.register` 的 `stream` 回调仍未接**：宿主还是配置式供应商；`ui.registerView` 仍
   unsupported；独立插件页仍未进抽屉/设置入口；`operit-extended-http` 15s 超时未排查。
6. **M84-B 142 项未重跑**：本片没改页面结构（只加了插件详情一段文字），但按纪律页面改动后应重跑。
7. 本批未发版；发布树 `D:\dsh\native-publish` 未动。
