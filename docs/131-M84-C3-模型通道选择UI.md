# 131 · M84-C3：模型通道选择 UI

> 2026-11-13 20:4x。补齐 `docs/115 §C` 的 C3（可选件）与 E2 留下的「插件供应商只能用调试通道指定」缺口。
> 证据：`docs/c3-check.json`、`docs/c3-providers.json`、截图 `131-01…131-03`。本批未发版。

## 一、做了什么

- `SettingsStore` 新增 `llm_provider_id`（空 = 跟随 API 提供商协议）与 `setLlmProviderId()`。
- `AppViewModel.llmStream()` 的优先级改成：
  **调试通道 `debug_llm_provider` > 用户选的 `llm_provider_id` > 按 API 提供商协议兜底**
  （选中的通道未注册时自然回落到协议通道，不抛错）。
- 模型配置页「API设置」新增 **模型通道** 选择行：列出当前 `LlmProviders.ids()` 的标签与 id，
  第一项是「跟随协议（anthropic/openai）」；插件供应商只在插件启用时出现。
- `--es dsh_dump_providers` 新增 `llmSelected`，方便验收/排查。
- 测试连接在宿主 key 为空但选中了通道时不再提前报错，交给通道自己给准确原因。

## 二、真机验收

1. 启用 `m84e2-demo` → 日志 `plugin providers=[e2.demo.probe, e2.demo.provider] active=null`。
2. 模型配置页打开「模型通道」→ 选「E2 演示供应商」（截图 `131-01`、`131-02`、`131-03`）；
   `prefs: llm_provider_id=e2.demo.provider`，dump `llmSelected=e2.demo.provider`。
3. **不传任何 `--es dsh_llm_provider`** 冷启跑一轮：
   ```
   I DshProvider: plugin provider id=e2.demo.provider protocol=openai model=deepseek-chat ... requestModel=deepseek-flash plugin=m84e2-demo
   I DshTurnHook: step-start turn=1 step=1
   I DshTurnHook: step-end turn=1 step=1
   ```
   选择器真的驱动了请求，不再依赖调试参数。
4. 停用 `m84e2-demo` 后再跑一轮：没有 plugin provider 日志，`DshTurnHook` 仍 step-start/step-end，
   说明回落到协议通道（OpenAI 兼容）成功。
5. 选择器清回「跟随协议」→ `llm_provider_id` 为空。

## 三、限制 / 未做

- debug 包的选择列表会包含 `debug.echo` / `debug.slow` / `debug.tool`（release 不注册）；
- 插件停用后选择值不清空，只是运行时回落；插件重新启用后自动恢复该通道；
- 没单独测「插件自带 key + 宿主 key 为空」的测试连接（代码已不再提前拦截）。
- 本批未发版。
