## 六、悬浮窗结果气泡挡触摸（重点：M76 的判断是错的）

**用户现象**：后台任务完成、白色结果气泡弹出时，点屏幕其它地方没反应，点掉气泡才恢复。

**M76 的做法**：给 BALL/VOICE_BALL/RESULT_DISPLAY 补 `FLAG_NOT_TOUCH_MODAL`，但没真机验。

**本批实测（改前）**：
- 结果气泡窗口 `mAttrs=(228,820)(wrapxwrap)`，实测 **Requested 640×1504**、
  `Frames: frame=[-148,884][492,2388]`——它是一块几乎整屏的透明窗口，白色气泡只是其中
  一小块；`NOT_TOUCH_MODAL` 只对「窗口外」的触摸生效，而屏幕大部分都在窗口内。
- 在气泡显示期间点电话图标 (102,1497)（该点落在窗口内、气泡外）→ 前台仍是 launcher，
  触摸确实被吞了。证据：`docs/shots/103-21-result-bubble.png`（气泡被裁到屏幕左边）。
- 结论：**根因不是缺 `NOT_TOUCH_MODAL`，而是 WRAP_CONTENT 窗口被根节点 `fillMaxSize()`
  撑成整屏**。

**修法**（两处）：`FloatingChatWindow` 在 `RESULT_DISPLAY` 时根节点用 `wrapContentSize()`；
`FloatingWindowManager` 的 `RESULT_DISPLAY` 参数改为 `Gravity.CENTER` + wrap，
并且 `switchMode()` 里那条单独的 `Target` 也同步（原来它又把 gravity 改回 TOP|END、
位置沿用悬浮球坐标）。另外结果气泡不再走 `AnimatedContent`——过渡容器会按悬浮球尺寸量内容，
实测把气泡压成 120×95、文字截成「命…」。

**改后实测**（0.3.1 复测）：
- 窗口 `(0,0)(wrapxwrap) gr=CENTER`，**Requested 560×358**、`frame=[80,637][640,995]`；
- 气泡期间点电话图标 → `topResumedActivity=com.android.contacts/...RequestPermissionsActivity`，
  触摸穿透成功，进程存活无崩溃。
- 证据：`docs/shots/103-23-result-bubble-fixed.png`（白色气泡居中完整显示）、
  `103-20-floating-ball-home.png`（悬浮球本身，柔和光团）、
  `103-20d-ball-tap.png`（点球展开悬浮窗）。
- 已知观感问题（不阻塞）：气泡里是纯文本，`## 结果`、`**命令**` 这类 Markdown 原样显示；
  3 秒后自动回悬浮球。

### 7.2 前台服务竞态崩溃（验收中发现，已修）

- 现象：退后台又立刻回前台时，进程崩：
  `ForegroundServiceDidNotStartInTimeException: Context.startForegroundService() did not then
  call Service.startForeground()`。
- 根因：`ProcessLifecycle.onStart → hideWhenForeground()` 在 Service 还没执行到
  `startForeground()` 时就 `stopService()`；系统仍按「前台服务必须及时 startForeground」判死。
- 修法：`FloatingBallService` 增加 `starting` / `hideRequested`；启动窗口期内的「收起」
  只记标记，等 `onCreate` 先 `startForeground()` 再自己 `stopSelf()`。重启/反复前后台
  验证不再崩（验收期间进程存活：pid 12098，崩溃缓冲区无新增）。

## 十一、用户 23:0x 补报三条（验收后修复，同 0.3.1 重打包）

用户原文（归纳）：①「悬浮窗怎么消失了？软件不在主台、在后台的时候悬浮窗应该出现，但是这次没了」；

③「聊天界面里内部滚动的东西（比如思考、比如包）滑到底之后，还会影响整个聊天界面往下滑」。

### 11.1 结果气泡卡住、悬浮球不回来（第 1 条的真根因）

- 复现：发一条消息 → 按 Home → 气泡在 t≈6s 出现（`wrapxwrap gr=CENTER`），到 t=28s 仍是
  `wrapxwrap`，120×120 的悬浮球再没回来；`docs/shots/104-06-stuck-bubble.png` 是白色「OK」
  气泡卡在桌面中央。
- 根因：`FloatingChatWindow` 把「3 秒后回球」写在 `LaunchedEffect(streaming, mode)` 里；
  切到 `RESULT_DISPLAY` 会让 key 里的 `mode` 变化，effect 立即被取消，`delay(3000)` 永远跑不完。
- 修法：拆两个 effect——`LaunchedEffect(streaming)` 只管「流式结束 → 弹气泡」，
  `LaunchedEffect(mode)` 只管「RESULT_DISPLAY → 3s → 回 BALL」，切模式不再打断计时。
- 实测（最终包）：t≈2.5s 气泡 `104-19-result-bubble.png` → 4s 后 `mAttrs={(600,740)(120x120)}`、
  `104-20-ball-returned.png`（球已回来）。
- 顺带修服务状态机：`onStartCommand` 补 `starting=false` + `ensureWindow()` 重入；
  `showWhenBackground` 不再因旧的 `running` 提前返回。修掉「start 打到未销毁实例 → 直接 stopSelf」
  与「starting 卡住 → 回前台收不起球」两个悬挂态。回归：回前台球消失、退后台球出现（实测）。

### 11.2 悬浮窗聊天页仍把引用包/文件铺开（第 2 条）

- 主聊天 `ChatScreen.UserMessage` 已有 `parseQuotedAttachment` + chip；悬浮窗两套渲染都没有：
  `FloatingWindowScreen.MessageItem`（小窗）与 `FloatingFullscreenScreen.FullscreenMessage`（全屏页）。
- 修法：解析/摘要/chip 抽到 `ui/chat/QuotedAttachment.kt` 共用；全屏页是透明浮层，用白字
  半透明底的同款 chip（`FullscreenQuoteChip`）。
- 实测：主聊天 `104-07-main-chip.png` / `104-08-main-chip-visible.png`（chip 显示
  `dsh-104-long.txt · 5.7 KB · 121 行 · 点开看原文`）；小窗 `104-11-window-chip.png`；
  全屏页 `104-12-fullscreen-chip.png`。改前同一条消息在全屏页铺开 120 行全文（`104-10-floating-chip.png`）。

### 11.3 内层滚动到底带动整页（第 3 条）

- 根因：Compose 嵌套滚动默认把内层吃不完的手势继续交给外层 `LazyColumn`；思考正文、工具卡
  参数/结果、引用正文都是内层 `verticalScroll`。
- 修法：新增 `Modifier.consumeInnerScroll(scrollState)`（`ui/chat/NestedScrollGuard.kt`）：
  内层 `maxValue > 0` 且在顶/底时消费剩余 delta；内容不溢出时完全不拦截（否则短文本上的拖动
  会把列表锁住）。应用到思考正文、工具卡参数/结果、引用 chip 正文（三处共用）。
- 实测：展开「思考过程（1222 字）」后在内层连滑 4 次——内层文本滚到底
  （`104-14-expanded.png` → `104-15-nested-inner-scrolled.png`），用户气泡、「已完成 · 用时 9 秒」、
  思考标题的 y 坐标不变；改前同样的滑动会带着整页走。外层列表在非内层区域仍可正常滚动。

### 11.4 已知（未改，等用户决定）

- 从最近任务**划掉**鲸歌时 ColorOS 会结束进程，悬浮球不会留在桌面（前台服务也拦不住系统级
