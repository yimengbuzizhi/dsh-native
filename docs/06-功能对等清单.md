# 06 · 功能对等清单（DSH 有的 + 旧版自研的，原生都要有）

> 2026-11-06｜用户要求：**DSH 有的功能原生都要有；旧版自研的（虚拟屏等）也要有。**
> 本文是功能验收的总账：每条都写「原生怎么做 / 哪个阶段 / 怎么算有」。
> 与 `00-立项与契约.md` 的 7 条行为契约互补——那 7 条管"行为一致"，这张表管"功能不缺"。

图例：**复制**=从 Operit 拿现成实现｜**移植**=把 DSH 的 JS 逻辑翻成 Kotlin｜**重写**=没有可抄的，重新设计｜

## 三、结构性消失的东西（不是砍功能，是架构变了）

| 旧版有 | 为什么不需要 |
|---|---|
| 启动引擎 / 等端口 / 端口冲突处理 | 原生没有独立引擎进程 |
| 引擎保活 / 前台服务看住 Node | 单进程应用，前台服务只为长任务 |
| 安全模式 / 启动失败计数 | 没有"引擎起不来"这种故障 |
| WebView 兼容检测 | 没有 WebView（浏览器功能内部仍用） |
| 补丁层 / 内核自检 / 内核清单 | 补丁是给 JS 内核打的，原生代码直接改源码 |
| adb forward / token 鉴权 | 没有回环 HTTP 服务 |
| 三变体里的 compat（GeckoView） | 除非还要覆盖老 WebView 设备，否则没必要 |

**这几项要跟用户确认一次**：它们不是"功能缺失"，是"问题不存在了"。

## 四、怎么算"有"（验收口径）

每个功能至少要有一种可验证的证据，三类之一：

1. **可操作**：界面上能点出来、能产生真实副作用（有截图/日志/文件）
2. **对拍通过**：与旧版行为逐字节一致（适用契约 #1–#6 的项）
3. **清单核对**：工具/触发词/schema 与 DSH 导出一致

覆盖统计（按本表行数）：
