# 144 · M85 终态设计：宿主只留骨架，一切由插件提供或替换

> 2026-11-13 用户定调（原话）：「宿主只留骨架，工具/页面/提示词/模型/回合/存储/UI 全部由插件提供或替换」。
> 这份文档是 **M85 的设计基线 + 交接说明**；实现从 `M85-A` 开始，按 §8 的批次推进。
> **本批（M84 A~R）已收口但未发布**；`docs/143-发布草案-v0.3.3.md` 仍待用户确认，发布树/tag/Release 一律不动。

---

## 1. 什么叫「骨架」

**骨架 = 原语 + 总线 + 安全/生命周期 + 平台能力宿主。骨架里不允许出现任何产品语义。**

| 骨架必须提供（P0 原语） | 骨架**不得**包含 |
|---|---|
| JS 运行时（QuickJS 常驻、超时、沙箱、宿主回调） | 「工具」注册表 / 工具 ABI 语义（`ToolRegistry`） |
| 插件注册表 / 启用开关 / 服务容器（provide/inject、同 id 覆盖） | 「页面」路由 / 内置页枚举（`BuiltinPageIds` / `BuiltinPages`） |
| 事件总线（发布/订阅，JSON） | 「提示词」拼装（`PromptPack` / sections） |
| Surface 渲染器（UI 树 → Compose）+ WebView 原语 + 主题 token | 「模型」协议（`LlmClient` 的 Anthropic/OpenAI 实现） |
| 持久化原语（按插件命名空间的 raw file / KV） | 「回合」循环（`TurnEngine`）、压缩/图片卸载/plan/goal 等流程 |
| 网络原语（HTTP(S) fetch，权限 + 域名白名单） | 「会话」格式与仓库（`SessionRepository` / `sessions/*.jsonl`） |
| 平台能力宿主：通知、无障碍、悬浮窗服务、文件选择、剪贴板、分享、定时器、后台任务 | 「聊天」界面（消息渲染、输入栏、抽屉、设置页） |
| 凭据存储（用户级，插件按权限读） | 插件角色的启动顺序硬编码（应来自 boot 清单） |
| 安全：权限校验、超时/配额、数据目录隔离、安全模式 | 任何「鲸歌默认行为」的硬编码 |

**产品语义全部下沉为「插件之间的协议约定」**，由内置插件实现并在文档里版本化（§3）。
宿主只强制三件事：**契约名登记与启动依赖解析**、**权限/配额/超时**、**数据目录隔离**。

> 判断标准（写代码时的自检）：如果删掉这个 Kotlin 类会让「鲸歌」不再像鲸歌，它就不该在骨架里；
> 如果删掉它只会让某个内置插件缺失，它就是插件。

## 2. 终态架构

```
┌──────────────────── 宿主骨架（native，无产品语义）────────────────────┐
│ 运行时：QuickJS 常驻 / 插件生命周期 / 事件总线 / 服务容器             │
│ 界面原语：native UI 宿主插槽 / Surface 渲染器 / WebView / 主题 token   │
│ 数据原语：namespaced raw file+KV / 网络 fetch / 凭据 / 定时器          │
│ 平台宿主：通知 / 无障碍 / 悬浮窗服务 / 文件选择 / 分享 / 剪贴板        │
│ 安全：权限 / 配额 / 超时 / 崩溃恢复 / 安全模式（唯一硬编码小屏）        │
└───────────────▲──────────────────────────────────────┬────────────────┘
        服务总线（同步 call / 异步 Promise / 事件）      │ 状态推送
┌───────────────┴──────────────────────────────────────▼────────────────┐
│ 插件层：内置插件 = 默认鲸歌；第三方同格式、同开关，全部可换            │
│ builtin.storage.jsonl  ← 会话格式/查询（storage/v1）                   │
│ builtin.agent.dsh      ← 回合循环/上下文装配/工具调度（agent/v1）       │
│ builtin.shell.native   ← 全部 UI（原样 Compose）：聊天/22 页/设置/抽屉 │
│ builtin.shell.whale    ← 可选第二套壳（Surface），不是默认、不替代原生  │
│ builtin.tools.* / builtin.prompt.* / builtin.model.*                  │
│ 第三方：任意 shell（native/Surface/WebView）、agent、storage            │
└───────────────────────────────────────────────────────────────────────┘
```

**默认鲸歌 = 一组内置插件的组合**，不是宿主。任何一块（含整壳、整回合循环、整存储）都能被同角色的
另一个插件替换（同 id 覆盖或换 active）。

## 3. 插件角色契约（约定层，版本化）

每个角色一个契约名 + 版本；宿主只做登记/依赖解析/权限，不理解契约内容。

| 角色 | 契约 | 必需方法（v1 草案） | 默认实现 |
|---|---|---|---|
| 存储 | `storage/v1` | `session.append(entry)` / `session.list(query)` / `session.load(id)` / `session.delete(id)` / `kv.get/set`（可选） | `builtin.storage.jsonl`（沿用现有会话文件格式，保证平滑迁移） |
| 回合 | `agent/v1` | `run(turn, ctx)`；ctx 原语：`llm.stream` / `tools.invoke` / `storage.*` / `notify` / `abort` | `builtin.agent.dsh`（**native 实现**也注册成插件，可停用/被覆盖） |
| 模型 | `model/v1` | `stream(request, emit)`（现有 `llm.register({stream})` 演进） | `deepseek` / `openai` 内置插件（现有 LlmClient 下沉） |
| 工具 | `tool/v1` | `invoke(args)` + schema；批量注册沿用 `ctx.tools.register` | `builtin.tools.*`（现有 32 工具分组） |
| 提示词 | `prompt/v1` | `assemble(ctx) -> sections`；段/变量/抑制运行时上下文 | `builtin.prompt.dsh`（现有 PromptPack 下沉） |
| 界面 | `shell/v1` | 后端二选一：**native**（Compose 渲染函数）/ Surface（`mount` / `state` / `action` / `event` → UI 树）/ WebView（M85-F） | **`builtin.shell.native`（原生 UI 原样插件化，默认）**；`builtin.shell.whale`（Surface）为可选第二套壳 |
| 页面 | `page/v1` | 页面 id/标题/层级 + 渲染（Surface 树或 WebView） | 各 `builtin.page.*`（现有 22 页） |
| 服务 | `service/v1` | `provide(name,value)` / `inject(names)` | 沿用 M83 服务容器 |
| 能力 | `capability/v1` | `list()` / `check(id)` / `invoke(id, args)`，能力 id 如 `root` / `nfc` / `shizuku` / `adb-shell`；宿主只做**登记 + 权限门 + 超时** | 可选 `builtin.capability.*`（随骨架平台能力提供）；没有对应能力插件时如实报「不可用」 |

> **特权能力（2026-11-13 用户补充）**：骨架平台能力只覆盖通知/无障碍/悬浮窗/文件/剪贴板/分享/定时器/
> 后台任务；root、NFC、Shizuku、ADB/shell 身份等**不是**骨架必备。若「一切皆插件」也要能扩展这些，
> 统一走 `capability/v1`：能力提供方是插件（内置或第三方），调用方经权限门，宿主不把任何特权写死。
> 这条在 M85-F 收口，不在 M85-A 假装已实现。

**启动清单**：插件在清单里声明自己承担的角色（`dsh.roles: ["shell","storage",...]` 或 `ctx.roles.provide`）。
宿主读取启用集合 → 解析角色 → 选 active（唯一角色的多候选由用户设置/优先级决定）→ 按依赖启动。
启动顺序不再硬编码。

> **2026-11-13 23:4x 用户澄清（修正主线）**：这里的「UI 插件化」是**把现有原生 UI 原样搬进内置
> UI 插件**，不是用 Surface/JS 从零重画一套 UI。`ChatScreen`/`ChatComposer`/22 页/设置/抽屉/
> onboarding 的 Compose 实现保留、体验不变、仍是默认界面；插件边界只负责「由谁提供这些页面」。
> `builtin.shell.native` 是默认的内置实现；`builtin.shell.whale`（Surface）与 WebView 壳是可选替代，
> 不是主路线，更不能拿它们去删原生 UI。只有宿主里**私有引用具体页面**的代码要在 M85-C 移走/删掉，
> 页面本身不删。

## 4. 服务总线（宿主原语 API）

```text
JS → 宿主（同步，__dshCallSync / callAsync）：
  fs.read/write/list/stat/remove          （namespaced 根 = 插件数据目录）
  net.fetch({url, method, headers, body}) （权限 + 域名白名单）
  kv.get/set/remove/keys                  （namespaced）
  ui.render/patch?                        （壳用，见 §5；v1 用返回树，无需 patch）
  surface.command                         （壳 → 宿主动作，见 §5）
  notify / toast / clipboard / share / pickFile
  timer.wait / jobs.*
  device.* / a11y.* / floating.*          （能力宿主，权限门）
宿主 → JS（dispatch）：
  plugin.apply / projection.event / shutdown / llm.stream / shell.mount|state|action|event
  agent.run / storage.*（由插件间调用转发，见下）
```

**插件间调用**：走服务容器（`ctx.inject('service-name')` 返回代理，方法调用经宿主事件总线转发，
宿主只做路由 + 权限 + 超时）。这样「agent 调 storage」「shell 调 chat 服务」都是插件约定。

## 5. Shell 协议 v1（native / Surface / WebView）

**默认后端 = native（2026-11-13 23:4x 修正）**：`builtin.shell.native` 是一个内置 **UI 插件**，用现有
Compose 实现（聊天页/页面/设置/抽屉/onboarding）注册到 `shell/v1`；宿主只通过 `ui.shell` 契约拿到
「当前壳的入口 Composable + 它声明的页面」，不 import 任何具体页面。它和 Surface 壳享有同样的
可停用/可替换/可回退语义，只是实现语言是 Kotlin/Compose，因此**用户看到的还是原来的 UI**。

Surface 后端保留给「用 18 原语拼一套不同 UI」的可选壳（如 `builtin.shell.whale`），协议如下；
它不是默认实现，也不是删原生 UI 的理由。

```text
宿主 → 壳：
  shell.mount   {state}            → {tree, title?}     首屏
  shell.state   {state}            → {tree}             结构变化（新消息/切会话/回合状态）
  shell.action  {id, payload, state} → {tree}           点击/输入/提交
  shell.event   {event, state}     → {tree}             可选宿主事件
壳 → 宿主：
  surface.command {command, args}   （sync，权限门）
  命令：send / stop / newSession / openSession / deleteSession / setSetting /
        selectModel / openPlugins / notify / copy / pickFile / screenshot /
        removeAttachment / setShellView / answer / openFloating / back
state = {
  chat: {title, status, draft, turn:{active,step}, messages:[{
    id, role, text, blocks:[{type:'text'|'thinking'|'tool_use'|'tool_result', ...}],
    toolCalls:[...], streaming, error, seq }]},
  sessions: [{id,title,updatedAt,current}],
  settings: {...}, theme: {...}, capabilities: {...}
}
```

**性能纪律（关键）**：token/流式文本走 **绑定**（宿主直接更新渲染，不跨 JS）；只有结构变化才 dispatch。
UI 树带 `key`；`list` 用 `bind` + `item` 模板；`bind` 是只读路径表达式（`chat.messages` / `item.text` /
`settings.x` / `chat.draft`）。

**通用交互/视图状态（M85-B2 补充）**：`onTap` 可挂在任何非输入原语上（button/chip/textfield/
switch/slider 除外），壳用它把任意行/卡做成点击目标；`setShellView {key,toggle|value,clearPrefix?}`
存壳自己的展开/收起/单选组状态（按会话隔离、宿主不解释 key），壳通过 `item.*Expanded` 之类只读绑定读回。
`list lazy:false` 用于 `scroll` 内的小列表（避免 LazyColumn 嵌套无限高），`maxHeight` 用于需要内部
滚动的卡片（如 plan detail）；`answer` 命令提交 ask_user_question 的答案（空数组 = 跳过）。

**原语 v1（Surface 后端用，先这 18 个）**：
`column row stack scroll list text markdown image icon button textfield switch slider divider spacer
progress chip webview`。Surface 壳的智能组件（消息气泡/工具卡/思考折叠/引用卡）由壳用原语拼，
**不做成宿主组件**；native 壳的组件属于内置 UI 插件，和宿主骨架的边界同样清晰。

**三种壳后端**：
- `native`（默认）：内置 UI 插件提供 Compose 入口，现有原生 UI 原样迁入；无 JSON/JS 跳转，体验与性能不退化。
- `surface`（可选）：JS 壳返回 Surface 树，宿主 Compose 渲染；适合完全不同的 UI。
- `webview`（M85-F）：整屏 WebView + 同一套 state/command 桥，第三方自由 UI。

## 6. Agent 协议 v1

```text
agent.run({turnId, sessionId, input, state}, ctx) -> Promise<{stopReason, text?}>
ctx.llm.stream(request)              → 异步流（宿主 LLM 传输原语，或 model 插件）
ctx.tools.names() / invoke(name,args) → 工具原语（宿主执行 + 审批 + 权限）
ctx.storage.session.append(...)      → 存储插件（经服务总线）
ctx.notify / ctx.status / ctx.abort
```

- 默认 `builtin.agent.dsh` 是**现有 TurnEngine 的 native 实现**，注册成插件（可停用/被同 id 覆盖）；
  不要求先用 JS 重写（避免压缩/图片卸载/goal/jobs/plan/审批全部重写）。
- 第三方 JS agent（示例 `m85.echo-agent`，十行）证明「回合循环可换」。
- 会话/投影/工具卡等数据结构由 **storage/agent/shell 三个插件约定**，宿主不解释。

## 7. 存储协议 v1

- 宿主只给 `fs.*` / `kv.*` 原语（按插件命名空间隔离）。
- 默认 `builtin.storage.jsonl` 沿用现有 `files/sessions/*.jsonl` 格式（平滑迁移、可回退）；
  第三方可换 SQLite/远程/加密实现（`storage/v1` 同接口）。
- 投影 checkpoint（M84-N）随 storage 契约走：默认实现沿用 `projection-checkpoints.json`。

## 8. 迁移计划（绞杀者：每一步都可真机回退）

| 批次 | 内容 | 验收（真机） |
|---|---|---|
| **M85-A 骨架地基** | Surface 渲染器（18 原语）+ 壳宿主（选择/超时/安全回退/`dsh_shell` 调试通道）+ `shell/v1` + 一个 `m85.minimal-shell`（只用原语拼聊天：会话条/消息/输入框） | 启用 demo 壳后**主界面由插件提供**：发消息、流式回复、切会话、停止；切回原生壳无残留 |
| **M85-B 可选 Surface 壳** | `builtin.shell.whale` 用 Surface 实现聊天页（消息/思考/工具卡/审批/附件/停止），作为**第二套可选壳**；原生 UI 继续是默认。**B1/B2 已完成**（`docs/146`~`150`） | 两壳同会话对拍；legacy 不参与替代/删除。Surface 壳的缺口只影响「可选壳」，不阻塞默认 UI |
| **M85-C 原生 UI 插件化（不是重画）** | 把现有 Compose UI **原样**移进内置 UI 插件 `builtin.shell.native`：聊天页/输入条/22 页/设置/抽屉/onboarding；宿主改为只认 `shell/v1` + `page/v1` 契约，删掉宿主里**私有 import/路由/页面清单**，**不删 UI 实现**；Surface/WebView 壳保持可选 | 默认仍是原界面、142/142 等价回归；停用内置 UI 插件 → 安全模式/回退壳；同 id 第三方 UI 插件可接管；源码扫描证明宿主不再 import 具体页面 |
| **M85-D 回合服务化** | `agent/v1` + `builtin.agent.dsh`（native 注册成插件）+ `m85.echo-agent`（JS） | 切到 echo agent：输入什么回什么；换回 dsH agent 正常；停用 agent 插件 → 安全模式提示 |
| **M85-E 存储/提示词/模型契约化（已完成）** | `storage/v1`（`builtin.storage.jsonl`）+ `prompt/v1` + `model/v1` 下沉；宿主删 `SessionRepository`/`PromptPack`/`LlmClient` 的产品语义 | 换一个 storage 插件（如只读导出器）仍能开会话；提示词段/模型插件行为与 M84 一致（`docs/166`） |
| **M85-F 收口** | WebView 壳后端 + 浮动窗 Surface + `capability/v1`（root/NFC/Shizuku 等可选能力不写死）+ 三终点回归（空壳/全装配/可换可加）+ `docs/115` 终点④⑤⑥ + 发版准备 | 空壳启动、全装配不少于 0.3.2、**换壳/换 agent/换 storage 三个 demo 全过**；发布内容先给用户看 |

**批次硬验收（不许软化）**：

- **M85-C 必须真的把原生 UI 移进插件边界（修正）**：22 页/设置/抽屉/onboarding/聊天页的 Compose
  实现**原样保留**，整体搬进内置 UI 插件 `builtin.shell.native`；宿主里只允许存在 `shell/v1` 契约、
  壳宿主、页面注册表，**不允许**再私有 import/硬编码具体页面或页面清单。
  验收：默认跑的还是原界面且 M84-B 142/142 等价回归；停用内置 UI 插件 → 安全模式/回退壳；
  同 id 第三方 UI 插件可接管。**「原生 UI 作为插件继续存在」是目标，不是失败；把 UI 删掉反而不对。**
  源码扫描证明的是「宿主没有私有 UI 引用」，不是「仓库里没有 UI 代码」。
- **M85-D/E 的 native 默认实现必须真的按插件对待**：`builtin.agent.dsh`、`builtin.storage.jsonl`、
  `builtin.prompt.dsh`、`builtin.model.*` 都是 native 代码注册出来的插件——**同契约、可停用、可被同 id
  覆盖、不享受宿主特权**（不能绕过权限门/配额，也不能因为「是内置的」就跳过后面的校验）。
  验收：停用后行为消失/进安全模式；同 id 的第三方实现能接管；覆盖后回退原实现不丢数据。
- **M85-A 不碰 legacy UI**：本批只证明「插件壳能作为主界面跑起来」，不删、不改原生聊天页；避免在 Surface
  原语还没被工具卡/审批/附件/Markdown/长列表压测前就跳 M85-C（用户 2026-11-13 提醒）。

**红线**：每一步都保持「不删用户数据、不卸载 `com.deepseek.harness`、不关无障碍、不发版」；
**不删原生 UI 实现**。M85-C 只删宿主对具体 UI 的私有引用，且要有 M84-B 等价回归兜底。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| Surface 树大/重绘慢（长会话） | token 走绑定不跨 JS；list 带 key；只推结构变化；长会话用虚拟列表原语；M85-A 就做 1000 条消息的压测 |
| 输入法/滚动/Markdown 体验退化 | 默认壳是**原样 Compose 的 native UI 插件**（不是重画、不是 WebView），体验不变；Surface 壳只作为可选替代 |
| 22 页 + 设置「插件化」工作量大 | 不是重画：把现有 Compose 页面原样移进内置 UI 插件，按模块分批搬；宿主每搬一块就少一个私有 import；每批跑 142/142 等价回归 |
| 插件拥有会话/网络权限的安全面 | 新权限 `session:read/write`、`ui:shell`、`agent:run`；装壳/换 agent 需用户确认；默认壳内置免确认；宿主保留数据目录隔离与审计日志 |
