## 1. 这一片做了什么

把聊天页的「工作步骤」补齐：思考可折叠、工具卡可折叠并显示耗时/状态，顶部有运行状态头，
输入条上方显示本轮用量。仍然**没有增加宿主聊天组件**——只加了通用原语能力和通用状态。

- **通用点击**：`onTap` 现在可以挂在任何非输入原语上（`column/row/text/image` 等）；
  `button/chip/textfield/switch/slider` 保持自己的交互，不重复包点击。
  壳因此可以把「思考标题行」「整张工具卡」做成点击目标，不需要宿主提供折叠组件。
- **通用壳视图状态**：新命令 `setShellView {key, toggle|value}`，按会话存进
  `ChatSessionState.shellView`（Compose 状态，最多 400 条，不落盘）。
  宿主**不认识 key 的语义**；壳用 `item.thinkingExpanded` / `item.toolExpanded` 只读绑定读回来。
- **通用绑定/数据**：`item.thinkingChars`、`item.thinkingLabel`、`item.toolLabel`、
  `item.duration`、`item.status`、`item.done`；`chat.turnSummary`、`chat.hasTurnSummary`、
  `chat.hasUsage`。
- **工具耗时**：`EngineHooks.onToolStart/onToolEnd` 记录 `toolCallId → ms`（前台/后台/子代理同一套），
  工具卡显示「完成 · 175ms」；先接 debug 钩子再叠加，不改回合循环。
- **准确的轮次耗时**：`turnStartedAt` 改在 `startTurn` 真正起点写，`lastTurnDurationMs` 在
  `DshTurn: turn end after` 同一处收口；状态头运行中每秒刷新，结束后显示「上一轮 · 用时 10s」，
  与引擎日志 `turn end after 10507ms` 对得上（旧实现会少算首包前的几秒）。
- **壳 UI（1.2.0）**：
  - 思考块：标题「思考 · N 字 · 展开/收起」，默认 3 行，展开看全文（最多 200 行）；
  - 工具卡：标题「工具名 · 状态 · 耗时 · 展开/收起」，默认 2 行结果，展开看完整结果；
  - 顶部状态头：`运行中 · 12s · 正在执行 bash` / `上一轮 · 用时 10s`；
  - 上下文行下方显示本轮 `usage`（如 `29603 in / 1306 out`）。

## 3. 明确没做 / 下一片

- **展开状态不持久化**：只在本进程、按会话存在内存里；杀进程后回到默认折叠。会话切换保留。
- **耗时只对本进程跑过的工具有效**：重开旧会话时工具卡显示「完成」但没有 ms（legacy 也没有逐工具耗时）。
- **超长结果**：展开上限 200 行；更长的输出仍截断（完整结果还在会话文件/工具结果里）。
- **答题卡 / plan / goal** 未做（B2-3）；**1000 条消息压测**未跑（B2-4）。
- **默认壳仍是 native**：本片用 `--es dsh_shell builtin.shell.whale` 验收，验完回 `native`。
