# 196 · 终端会话初始化超时（fresh install 100%）修复

> 2026-11-25 · 对应 bug 报告 `终端会话超时-bug报告.md`（PLT120 / Android 15 / 0.3.6，全新安装 100% 超时）。
> 结论：**不是 Android 15 的 exec 限制，是 APK 里两个同名 `libbash.so` 打架**——终端拿到了「bash 工具链」那份
> Termux bash，缺 `libandroid-support.so` / `libiconv.so`，PTY 子进程一启动就退出；30 秒后只剩 timeout。
> 版本 **0.3.8 / versionCode 11**（0.3.7 → 0.3.8）。

---

## 一、根因

APK 合并时 `lib/arm64-v8a/libbash.so` 有两个来源：

| 来源 | 大小 | 用途 | 依赖 |
|---|---|---|---|
| `app/src/main/jniLibs/arm64-v8a/libbash.so` | 880,416 B | docs/187 的 bash 工具链（`Toolchain.kt`） | `libandroid-support.so` + `libiconv.so`；这两份**不在 jniLibs**，在 `assets/toolchain/lib`，只有工具链自己的 `LD_LIBRARY_PATH` 能命中 |
| `thirdparty/terminal/src/main/jniLibs/arm64-v8a/libbash.so` | 1,696,448 B | 终端会话（`TerminalManager.linkNativeLibs` → `usr/bin/bash`） | 自包含（除 libdl 外无外部 `.so`） |

`app` 模块的 880KB 那份在合并中胜出。终端把 `usr/bin/bash` 软链到 `nativeLibraryDir/libbash.so`，
`LD_LIBRARY_PATH` 只有 `nativeLibraryDir:usr/bin`，于是：

```
CANNOT LINK EXECUTABLE "/data/user/0/xin.dshaa.nativeapp/files/usr/bin/bash":
  library "libandroid-support.so" not found: needed by main executable
→ Terminal session ... exited with code 1
→ 30s 后 Session initialization timeout
```

bash 从未跑起来，所以 `common.sh` 的 `install_ubuntu` / `configure_sources` / `bump_progress` 全都没执行——正好是
报告里的「启动流程零副作用」「无 proot 进程」。手动 `source common.sh` 能成功，是因为手动 shell 的库路径和 App 内 PTY
不一样，掩盖了这个依赖问题。

## 二、复现（真机 PEMM00 / Android 13 / 0.3.7）

- 既有终端环境（`files/usr` 在）：`dsh_terminal_selftest` PASS。
- 删掉 `files/usr` + `common.sh`（等价全新安装 / 环境重建）后立刻 100% 复现：
  `create_terminal_session` → 30.2 s → `Session initialization timeout`，logcat 里就是上面那行 linker 报错。
  说明与 Android 15 无关，任何设备只要环境是重建的都会中。

## 三、修复

1. **终端用专属 bash，不再和工具链抢文件名**
   - `thirdparty/terminal/.../libbash.so` → `liboperit_terminal_bash.so`（`git mv`，1,696,448 B 原字节）；
   - `TerminalManager.linkNativeLibs()`：`"liboperit_terminal_bash.so" to "bash"`；
   - APK 里两个 bash 共存（工具链仍用 `libbash.so`），终端拿到自包含的那份。
2. **失败立刻说真话（报告要求 1/2）**，`TerminalManager`：
   - 采集 PTY 启动期输出（末 4KB）；
   - 进程在 READY 前退出 → 立即失败，错误里带 `process exited (code=1): <bash/proot 最后输出>`，不再干等；
   - 初始化等待 30 s → **120 s**（首次解 rootfs 需要时间），超时消息也附最后输出；
   - 工具层错误照旧提示「首次要解 rootfs，稍后重试」。
3. 未改：工具链（`libbash.so` + `assets/toolchain/lib`）、`host.mjs`、终端 UI/命令语义。

## 四、验证（真机 PEMM00 / Android 13 / arm64，0.3.8 / versionCode 11）

- 删 `files/usr`、`common.sh` 后冷启动跑 `--ez dsh_terminal_selftest true`：
  **RESULT: PASS（0 failures）**，`create_terminal_session` 返回 `state: READY`，全程 29 s（含第一次解 rootfs）；
  会话 `cat` 交互、Ctrl+D、隐藏执行、关闭会话全部通过。
- 工具链回归（`--ez dsh_toolchain_probe true`）：`ok=true failed=0`，`bash 5.3.20(1)-release`、
  `curl 8.21.0`、HTTPS 200、symlink exec 正常。
- JVM：全量单测结果见 `docs/release-0.3.8-tests.log`。
- 失败路径（人工检查）：报告里的 `CANNOT LINK ...` 现在会直接出现在工具错误里（例如
  `terminal failed to start: process exited (code=1): CANNOT LINK EXECUTABLE ...`），不再只剩 timeout。

## 五、已知限制 / 未覆盖

- 首次会话仍需解 rootfs（本机 29 s；慢设备可能更久），期间 UI 有进度，AI 侧最多等 120 s。
- 真机只覆盖 arm64 PEMM00（Android 13）；报告机型 PLT120（Android 15）机制相同（与 exec 限制无关），
  但未在该机型复测。
- 未做「bash 二进制自检」：如果以后再把别的同名 `.so` 塞进 jniLibs，同类问题仍可能出现；jniLibs 命名应保持
  每个模块唯一（本次教训）。
