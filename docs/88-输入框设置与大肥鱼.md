## 一、输入栏浮层菜单（M58 首版做错 → M60 按源码重做）

用户截图是 Operit 的输入条浮层。**M58 首版做成了底部弹层（ModalSheet）+ 三颗胶囊，还在输入条上方
自创了一排状态胶囊——结构与源码不符，用户指出后已全部删除。** M60 按源码重做：

  - `AgentExtraSettingsPopup`（2219–2466）：齿轮打开，含记忆 / 工具 / 行为 / 插件四组；
  - 两者共用的浮层几何：`Popup(fillMaxSize + 透明点击层)` + `Card(BottomEnd, padding(bottom=44.dp,
    end=12.dp), width=300.dp, heightIn(max=420.dp), RoundedCornerShape(8.dp), elevation=4.dp,
    verticalScroll)`（1550–1595、2289–2334）。
- 鲸歌实现：`ui/chat/ComposerMenus.kt` 的 `ComposerMenuPopup`（照抄上面的几何）+
  `ComposerMenuGroupHeader` / `ComposerMenuGroupBody` / `ComposerMenuRow`；
  `ChatComposer` 的 `settingsSheet` / `modelSheet` / `behaviorSheet` 全部换成这个浮层（不再是底部弹层）。
- 记忆 / 工具 / 行为 / 插件是**可折叠分组**：点标题原地展开（记忆列出记忆空间、工具列出允许/询问、
  行为列思考展开/时间上下文/流式说明、插件给入口），和 `AgentExtraSettingsPopup` 一致。
- 思考程度按 `ThinkingQualitySlider` 改成 **Slider 三档**（低 / 高 / 最高），不再是三颗胶囊。
- **D 档 bug 修复（2026-11-10）**：Slider 的 index 用了 `coerceAtLeast(1)`，把 low(0) 顶成 high(1)，
  表现就是「拉到最左又弹回高」；改成 `takeIf { it >= 0 } ?: 1` 后三档都能停住

| 行 | 取值 | 真实行为 |

## 四、插件命令执行（P5，接 docs/86 第二批）

上一批只登记 `ctx.commands.register`，本批把执行链路接完：

1. `core/plugins/PluginModule.kt` → `commandScript()`：与 `invokeScript()` 同一条 QuickJS 链路
   （注入宿主符号 → 执行模块 → `apply(ctx)`），再调
   `__dshDefs['command:<name>'].handler({agent, rawInput, attachments: []})`；
   `{kind:'error'}`、Promise reject、同步异常都归一成 `{ok:false,error}`，字符串/`{text}`/其它对象归一成 `{ok:true,text}`。
2. `data/PluginToolRuntime.kt` → `invokeCommand(record, commandName, rawInput, workspace)`：
   和工具共用沙箱/权限/超时/宿主回调，只是入口不同（`runWithScript`）。
3. `AppViewModel.submit()`：`parseCommandLine` 之后、模型命令之前查
   `pluginsUi.filter{enabled}.flatMap{commands}`；命中就异步执行，结果用 `showCommandNotice()` 显示，
   **不进模型历史**，并写 `DshCmd` 日志。
4. `ChatComposer` 的 `/help` 面板新增「插件命令」分组（点一行插入 `/名字 `）。
5. 插件详情里「命令执行链路下一版接入」改成「输入 /名字 直接执行」。

真机验证：`whale-compat-test` 注册的 `/compat`：

```
adb shell am start -n xin.dshaa.nativeapp/.MainActivity --es dsh_send "/compat"
logcat: 11-10 00:08:14.458 I DshCmd: plugin command /compat from whale-compat-test ok=true
```

截图 `docs/shots/88-04-plugin-command.png`：输入条上方命令提示条显示 `compat ok`（handler 返回值）。

## 六、大肥鱼（dsh-dafeiyu）原生适配（M59）

### 4.1 上游事实（源码读全）

- 仓库 <https://github.com/QCYTSN/dsh-dafeiyu>，npm `dsh-dafeiyu@0.1.23`，作者 QCYTSN。
- 安装包 **242 MB / 7007 个文件**：角色素材 3,444 帧 WebP + 三平台原生 Helper（Qt / PySide / Swift）。
- 结构（读过的文件）：
  - `src/plugin.js`：`inject: ['sessions','settings']`；`ctx.on('session/event', …, {global:true})`
    把 DSH 会话事件交给 `CompanionReducer`；`HelperProcess` 用 **stdio 协议**把消息推给原生窗口；
    `ctx.inject(['webServer'])` 注册 `/plugins/dsh-dafeiyu/{config,events,manifest,frame}`，给页面内 overlay 用；
    余额查询走 DSH 凭据服务 + DeepSeek `/user/balance`。
  - `src/protocol.js`：`PROTOCOL_VERSION=1`，状态 `IDLE/THINKING/WORKING/WAITING/SUCCESS/ERROR/DISCONNECTED`，
    消息 `ready/hello/state/pulse/alert/task/tasks/config/balance/settings/ping/pong/closed/shutdown`，
    `ALERT.APPROVAL`。
  - `src/companion-reducer.js`：状态优先级 `WAITING 60 > ERROR 50 > WORKING 30 > THINKING 20 > IDLE 0`；
    `toolActivity()` 把工具名映射成 searching/editing/testing/commanding/using-tool；
    `turn/start`、`tool/call`、`tool/result`、`approval/asked|decided`、`turn/end`、`todo/write` 的归约逻辑。
  - `lib/client.js`（`dsh.client`）：Web 设置页 + 页面右下角轻量角色；不参与原生窗口。
- **结论**：大肥鱼不是纯 JS 插件，它的核心是桌面原生 Helper（Electron `child_process` 启 Qt/PySide）。
  Android 既没有 Electron 主进程，也跑不了 Qt/Swift；照搬 JS 只能得到「状态机 + 协议」。

### 4.2 鲸歌的做法：同一套状态机 + 原生悬浮窗

新增 `app/.../fish/`：

- `BigFish.kt`：照 `companion-reducer.js` 移植的状态机与文案。入口
  `onTurnStart / onStatus / onWaiting / onApprovalResolved / onTurnEnd / onError / onIdle`；
  `activityOf()` 的工具名正则与上游逐条对齐；`FishSnapshot` 合并了 `state/task/config` 三类消息。
- `BigFishService.kt`：`TYPE_APPLICATION_OVERLAY` 前台服务，纯 Canvas 画蓝鲸 + 气泡（不依赖 Compose/主题）：
  - 拖动（保存 bigfish_x/y）、点一下回对话、长按收起并关设置；
  - 应用退后台出现、回前台收起；**开着大肥鱼时代替悬浮球**，两个都弹会挡界面；
  - SUCCESS/ERROR 2000–2400ms 脉冲后自动回 IDLE；提示音默认只对 SUCCESS/ERROR 响一声（对应插件 soundStates 默认值）。
- 设置（`SettingsStore` + 设置 → 显示与行为 → 大肥鱼悬浮窗）：
  `bigfish_enabled / scale / bubble(always|hidden) / activity(quiet|normal|lively) / reduced_motion / sound`，
  对应插件 Config 的 enabled/scale/bubbleMode/activityLevel/reducedMotion/soundEnabled。
- 事件来源：`AppViewModel.ComposeTurnUi` 的 `setStreaming(true)`、`setStatus()`（引擎每步的
  `运行工具 X…`/`思考中…`）、`setError()`、`awaitApproval()`、`resolveApproval()`、
  `startTurn` 的 `finally`（turn/end）。

### 4.3 插件包映射

- 导入 `dsh-dafeiyu` 后：`pluginsUi` 里 id 命中 → 自动打开 `bigfish_enabled`，notice 追加
  「已启用原生大肥鱼悬浮窗」；插件详情顶部显示「已原生适配：大肥鱼悬浮窗」+ 说明；
  `dsh.client` 的文案改成「Web 设置页不在手机上执行；状态鱼已用原生悬浮窗替代」。
- 验收夹具：`D:\dsh\fish-fixture`（1 KB，package.json + 空 apply + cordis.patch.yml），
  模拟真实包清单导入（真实 242 MB 包不装到手机）：截图 `88-06-dafeiyu-import.png`（导入成功 + notice）、
  `88-07-dafeiyu-detail.png`（原生适配卡片）。

### 4.5 本批没做的（诚实标注）

- 真实包的 Qt/PySide/Swift Helper（桌面窗口）与 Electron 主进程：Android 不可能执行，
  鲸歌用原生悬浮窗替代，**不是把原 Helper 跑起来**。
- 页面内 overlay（`webOverlay`）、余额查询（DSH 凭据服务/`/user/balance`）、
  `bubbleMode=custom`、`soundStates` 逐场景开关、子 Agent 抢占排序、鼠标右键菜单。
- 角色素材（3,444 帧 WebP）没有随包，鲸歌画的是矢量鲸鱼；要换素材需要单独挑帧并注意 ASSET_LICENSE。
