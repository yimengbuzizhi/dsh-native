# 132 · M84-G：整页插件页面与页面替换

> 2026-11-13 20:5x。补 `docs/115 §B/§E` 的「页面内容由插件提供」：`ctx.ui.registerPage` /
> `registerRoute({page:true})` 让插件用自己的 `dsh.client` 当整页；route id 与宿主内置页同名时**替换内置页**，
> 插件停用自动恢复。证据：`docs/m84g-check.json`、截图 `132-01…132-04`。本批未发版。

## 一、做了什么

### 1. JS API

```js
ctx.ui.registerPage({ path: 'About', title: '插件关于页', description: '...' })
// 等价于
ctx.ui.registerRoute({ path: 'About', title: '...', page: true })
```

- `PluginRoute` 新增 `page` 字段（`plugins.json` 只写 true），安装/重载都带上；
- 能力清单新增 `ui.page`（m84.3，**25/27** 已实现）；`ui.view` 仍 unsupported。

### 2. 宿主渲染

- 新增 `pluginui/PluginPageScreen.kt`：全屏 WebView 跑插件自己的 `dsh.client`（复用
  `client-host` 资源与 `/plugin/` 目录服务），顶栏显示插件页标题 + `插件页面 · <插件名>`，返回走宿主路由。
- `App.kt` 在解析内置页之前先查 `vm.pluginPageFor(pageId, subId)`：
  **启用中 + 有 dsh.client + route.page=true + id 与当前页/二级页同名 → 用插件整页替换内置页**。
- 插件详情「页面路由」段给 `page` 路由标「整页」，并新增「以整页打开」按钮；
  该按钮启动 `PluginPageActivity`（同一套 `PluginPageScreen`），用于打开**独立插件页**（如 `/m84e2`）。

### 3. 演示插件

`m84e2-demo` 现在注册：
- `/m84e2` 整页（演示页）；
- `About` 整页（替换宿主「关于」页）。

## 二、真机验收

1. 启用 `m84e2-demo` → 打开「关于」：
   - `DshPage route page=Settings sub=About`；
   - 界面是插件页「E2 替换的关于页」，内容来自插件 `client.js`（截图 `132-01`）。
2. 停用 `m84e2-demo` → 再开「关于」：恢复宿主内置关于页（版本/协议/许可），截图 `132-02`。
3. 插件详情：`/m84e2` 与 `About` 都显示「整页」，各带「以整页打开」（截图 `132-03`）。
4. 点「以整页打开」→ `mCurrentFocus=...pluginui.PluginPageActivity`，整页标题「E2 演示页」、
   插件内容渲染（截图 `132-04`）。
5. 验收后 `m84e2-demo` 已停用，About 恢复内置页。

## 三、限制 / 未做

- 整页内容只能是插件 `dsh.client`（WebView），**不能**往宿主 Compose 页面插任意组件
  （`ui.registerView` 仍 unsupported）。
- 只有 route id 与内置页/二级页 id 相同才替换；独立插件页目前从插件详情以 Activity 打开，
  没有自动进抽屉/设置入口。
- 只对 About 做了真机替换/恢复；其余 21 页未逐页替换。
- `PluginPageScreen` 的静态资源服务逻辑与 `ClientPluginWindowService` 有重复，后续可抽公共层。
- M84-B 142 项逐页对拍未重跑；本批未发版。
