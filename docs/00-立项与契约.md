# 00 · 立项与契约

> 状态：P0（可行性验证）｜落盘 2026-11-06｜本文件是这条产品线的唯一立项依据。

## 一、要做什么

把现有 DSH 手机版（Java 壳 + Node 引擎 + WebView UI）**整体移植为原生 Android 应用**：

- UI：Jetpack Compose 原生控件（不再是网页）
- 内核：Kotlin 重写 `@deepseek-ai/dsh 0.2.1-rc.2` 的语义层（不再依赖 Node）
- 设备能力：Shizuku / 无障碍 / 虚拟屏 / 悬浮球 —— 旧版已是原生，改造复用

**不是**：给旧版换皮肤、给 WebView 套壳、Flutter/RN 跨平台。

## 二、和旧项目的关系

| | 旧项目（Node 版） | 本项目（原生版） |
|---|---|---|
| 维护人 | 另有人负责 | 本项目 owner |
| 角色 | 用户兜底 + **对拍 oracle** + 移植取材来源 | 新产品线 |
| 源码 | `D:\dsh\release-src` 等，**只读** | `D:\dsh\native`，独立 git |
| 上游跟进 | 换 npm 包 | 人工移植 stable 版本 |

**红线**：本项目不修改旧项目任何文件；不把旧项目源码拷进本仓库（除登记过的取材，见 `移植取材台账.md`）。

## 三、验收契约（7 条，前 6 条要求逐字节等价）

1. **提示词逐字节一致** —— 同一场景下发给模型的 request body diff 为空
2. **工具 schema 一致** —— 30 个工具导出 JSON Schema 后逐字段比对
3. **会话格式一致** —— 新写出的 `session.v4.jsonl.zstd` 旧版可读；旧版 41 条会话新版可读且行数/哈希一致
4. **工具行为一致** —— 同输入同工作区，输出逐字节一致（含错误码与文案）
5. **流式与中断一致** —— 断线重连/取消/超时/重试的时序与终态一致
6. **数据目录与迁移一致** —— 装机后老数据原地可用，无需清数据
7. **UI 行为等价** —— 按交互清单逐项验收（网页→原生是重画，不做代码级移植）
8. **功能不缺** —— DSH 内核功能与旧版自研功能全部落地，逐条见 `06-功能对等清单.md`；
   确实因架构变化而消失的项（如引擎启动、补丁层）必须在清单里注明理由并经用户确认

## 四、追版节奏（用户已拍板：跟着上游）

- 只追 **stable**，不追 rc；攒 1–3 个版本一次合并（季度节奏）
- 每次合并：拉**未剪枝**源码（含 `src/*.ts`）→ 变更报告 → 只移植 delta → 对拍全绿 → 发布
- 对拍台是长期资产，不是一次性脚本

## 五、里程碑

| 阶段 | 内容 | 判据 |
|---|---|---|
| P0 | 门 1 构建 / 门 2 对拍台 / 门 3 纵向切片 | 见 `P0-门1-环境探测.md` |

## 六、纪律

1. 每个里程碑必须**可装机自用**，不允许「搬了 20 万行没人见过它跑」。
2. 移植 = 翻译，不是重新设计；禁止「顺手优化」改变行为。
3. 任何偏离契约的改动，必须写进决策日志并说明理由。
