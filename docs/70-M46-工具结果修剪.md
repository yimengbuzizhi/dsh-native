## 二、上游依据（宁抄勿研）

`<workspace>021\node_modules\@deepseek-ai\dsh-compaction-tool-result-pruner\`：

1. **配置**（`lib/index.js` 第 8–52 行）：`PRUNE_MARKER`、`DEFAULTS = {8192, 4096, 1024}`、
   `resolveConfig()` 的三条校验（threshold 正整数、head/tail 非负、`head + marker + tail <= threshold`），
   未知键直接抛错；
2. **切法**（`pruneContent()` 第 91–124 行）：`measureContent` 只价 text 块（码点）；
   总量 `<= threshold` 返回 null；`removedStart = headChars`、`removedEnd = total - tailChars`；
   逐块按**全局文本流**偏移切：`headEnd = min(len, max(0, removedStart - blockStart))`、
   `tailStart = min(len, max(0, removedEnd - blockStart))`；标记只在「与被删区间相交」的第一块插一次；
   非 text 块原样保留、不推进 `consumed`；最后 `check` 标记必须插入、替换必须更小且不超阈值；
3. **落库**（`pruneSession()` 第 137–191 行）：遍历当前会话面快照，对每个超预算 `tool/result`
   先 append `compaction/prune{shadowedRange:{start,end}, shadowedSeqs:[seq], shadowedTokenCount}`
   （用 token meter 价原消息），再 append 新 `tool/result`（只换 `message.content`，
   `surfaceOp:{op:"replace",startSeq:seq,endSeq:seq}`、`sourceEventSeqs:[seq]`）；
4. **调用点**（`dsh-compaction-basic/lib/index.js` 第 914–961 行）：
   - 压力：先量 → 低于阈值直接返回；确认高于阈值 → `prune.pruneSession()` → **重新量** →
     仍低于阈值就 `return null`（README 明确：修剪可能免掉摘要）；
   - 溢出：**不看阈值先剪**（第 927–931 行），再 `selectCompactableRange(..., 0)`；
   - 手工 `compactNow()` 不剪（第 985–1007 行）——原生 `/compact` 同样不剪。

### 3.1 切片（逐字照抄的四个细节）

- 按**码点**切：`5000` 个 emoji = 5000 码点（10000 个 UTF-16 单元），9000 码点时头 4096 个
  emoji 完整保留、不会出现半个代理对（单测断言 `\uFFFD` 不出现）；
- 头/尾预算按**整条结果的文本流**算，不是每块各一份；图片等富块原样保序、不计价；
- 标记只在第一块「与 `[removedStart, removedEnd)` 相交」的 text 块里插入一次；
- 替换后必须**更小且不超阈值**（上游 `check`，原生 `check` 同样是 invariant）。

### 3.2 事件与顺序

```
auto-compact: prune seq=7 replacement=11 chars=41705->5159 pruneSeq=10
```

- `compaction/prune`：`{"shadowedRange":{"start":7,"end":7},"shadowedSeqs":[7],"shadowedTokenCount":10435}`
  —— 与 `compaction/summary` 同形，纯读取方据此减令牌；
- 新 `tool/result`：根上 `turn/step` 原样、`message.{role,source,toolCallId,isError,id}` 原样、
  只换 `message.content`；根上 `surfaceOp` + `sourceEventSeqs`；
- 位置：**原地**。`surfaceOf` 把替换消息插回区间第一条的位置（不是追加），
  这是请求体里「tool result 必须紧跟它的 tool_use」的前提（M43 的 checkpoint 也顺带修正）。

### 3.3 两个触发里的顺序

- **压力**：`total < threshold` → 不剪；确认超标 → 剪 → 重新量 → 仍低于阈值 → 只写日志
  （`pruning relieved the pressure … skipping summary`），不建摘要、不写 `compaction/start`；
- **溢出**：先剪（不看阈值），再 `retainTokens = 0` 选区；摘要请求读的是**剪过的**会话面
  （单测 `overflowPrunesBeforeSelecting…` 锁：`summary.shadowedSeqs` 里是替换后的新 seq）。

### 3.4 重开会话的投影（顺手修的 bug）

早先 `projectSession` 的处理是「先 `removeAll(被顶掉的 seq)`，再 `state.messages += 替换消息`」，
替换消息落在列表末尾：

- 压缩：`[保留的最近历史…, checkpoint]` —— checkpoint 应该在保留历史**之前**；
- 修剪：剪过的工具结果跑到所有消息后面 —— 请求体里跟在 assistant 的 tool_use 后面才合法。

现在统一走 `SessionCodec.surfaceOf()`（核心层、有单测）：替换消息占被顶掉区间的**第一个位置**；
`surfaceOf` 也顺带用于会话列表的条数/预览（`summarizeCached`），列表不再把被顶掉的旧消息算进去。

## 四、与上游的差别（全部有意，写在这里避免下轮重复研究）

1. **修剪预算不可配置**：原生没有插件配置目录，先用上游默认值（8192/4096/1024）；
   `PruneConfig` 已带上游三条校验，将来接「设置 → 压缩」一行就能改；
2. **影子价用启发式**（`Compaction.estimateMessageTokens`，4 字符 1 令牌）而不是真 token meter——
   与 M43–M45 的记账口径一致；
3. **没有 `image/offload`**：非 text 块原样保留（上游 pruner 本来也只动 text 块）；
4. **没有 `sourceCommandId`**：上游 `compaction/prune` 本来就不带（它不是一次压缩事务）；
5. **手工 `/compact` 不剪**：与上游 `compactNow()` 一致（只有自动触发才剪）；
6. `compactionRetries` 循环仍未搬（M45 的 §四.4 不变）。
