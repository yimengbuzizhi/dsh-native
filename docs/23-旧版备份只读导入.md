# 23 · 旧版备份只读导入（v0/v3 → v4 副本）

> 2026-11-07 01:5x｜基线 `bdf7a22` + 本轮（M6）。
> 目标：把旧版 App 的 `DSH备份-*.zip` 里的历史会话**只读**搬进原生版，让用户第一天就能看到过去几个月的对话。
> 用户红线：**不改、不删任何旧数据**；备份包原样保留。

---

## 一、一句话结果

真机选 `DSH备份-20260924-193035.zip`（14.16 MB，45 个旧会话，v0 × 25 / v3 × 20）：

- 扫描 45 条 → 默认勾选 41 条（4 条 0 消息的空会话不勾）→ 一键导入；

- 备份包、旧版 App 数据**一个字节没动**（导入只写本 App 的 `files/sessions`）。

## 二、为什么先做这个

`docs/06` 里「备份导出 / 导入（含会话）」是 M2 项，但用户可见价值最高：换到原生版后，
旧版里 25 个 v0 + 20 个 v3 会话如果打不开，等于历史全丢。先做「**只读列表 + 预览 + 导入**」，
写入侧（导出/备份）和完整迁移链后置。

## 三、旧备份长什么样（实测）

`DSH备份-yyyyMMdd-HHmmss.zip`，176 entries：

```
manifest.json                                  # {"type":"dsh.backup","version":1,...}
prefs.txt
dshhome/
  settings.yaml / .credentials.yaml            # 本轮不导入
  storages/session_projcache.json              # 标题缓存；不用（标题在日志里）
  sessions/<projectKey>/session-<uuid>/
      session.jsonl.zstd                       # v0（packed chunk 行 + seedLength）
      session.v3.jsonl.zstd                    # v3（每行一个事件）
      session.v4.jsonl.zstd                    # v4（与当前一致）
      session.lock
```

- 每个文件是**多 zstd 帧拼接**（单个 v0 文件最多 1820 帧），必须逐帧解压；
  复用 `core:session` 的 `ZstdFrames.decompressAll`（对真实旧文件实测通过）。
- 同一会话可能同时存在多代文件（`.v3` 与无版本号）→ 扫描按 **v4 > v3 > 无版本** 取最高，
  并给出 warning（45 条里没有出现重复代）。
- 旧 v0/v3 的消息形态：
  - 用户消息：事件 `user/message`（v0 早期可能叫 `steering/message`）；
  - 助手消息：`assistant/message`（正文含 reasoning / text / tool-call 块；v0 另有顶层
    `assistant/chunk` 与 packed 行，**投影不需要**，最终正文已在 message 里）；
  - 工具结果：`tool/result.message.role="user"`，正文包在 `tool-result` 块里（v4 之前的形态）；
  - 标题：`session/title`，**最后一条生效**（fallback 短标题 → LLM 长标题）；
  - 运行时上下文：v3 里是一条 `role:user`、`source.kind:"plugin"`、
    `plugin:"@deepseek-ai/dsh-system-prompt"`、`form:"snapshot"` 的消息，**不是用户打的字**。

## 四、实现

### 4.1 新模块 `:core:legacy`

| 文件 | 职责 |
|---|---|
| `LegacyLog.kt` | 物理 header（v0 的 `seedLength` → `isSeeded`）+ 事件解析（未知 type 不丢） |
| `LegacyProjection.kt` | 事件 → 消息：v3 的 `tool-result` 包装块提升成 `role=tool`；过滤 system 头节点与运行时上下文；标题取最后一条；模型/provider 提取 |
| `LegacyV4.kt` | 消息 → **结构合法的 v4**：header + `request/header` + turn/step 骨架 + `user/message`/`assistant/message`/`tool/call`/`tool/result` + `session/title`，seq 从 0 连续；写出多帧 zstd |
| `LegacyBackup.kt` | 扫 zip（`ZipInputStream`，按会话目录分组、取最高版本）、预览摘要、只读导入、`imported.json` 侧车、`sha256` 去重索引 |

### 4.2 只读导入的三种情况

| 源 | 做法 | 结果 |
|---|---|---|
| v4 | **逐字节复制**（保留原 id；同 id 已存在则 `Skipped`） | 与备份完全一致 |
| v0/v3 | 投影成 v4 副本（新 UUID）；只搬对话，不搬日志类事件 | 可看、不可续聊 |
| 任何 | 都写 `imported.json`：来源包名/条目/格式版本/sha256/只读标记 | 列表与聊天页据此标记 |

`imported.json` 示例：

```json
{"type":"import.legacy","version":1,"sourceName":"DSH备份-….zip",
 "entryName":"dshhome/sessions/--…--/session-…/session.v3.jsonl.zstd",
 "formatVersion":3,"importedAt":1794000000000,"readOnly":true,
 "sourceSha256":"00431f9f…","messageCount":290,"originalBytes":38503}
```

### 4.3 只读三处闭环

1. 会话列表：`SessionSummary.legacy=true` → 行尾绿色「旧版」chip；排序用**原始最后事件时间**，
   不用文件拷贝时间（否则 9 月的会话全挤在「今天」）。
2. 聊天页：`ChatSessionState.readOnly=true` → 底部输入条换成锁形提示「旧版会话 · 只读」；
   `AppViewModel.send()` 二次拦截（不依赖 UI）。
3. 数据层：`SessionRepository.load()` 见侧车即 `readOnly`；本 App 自己永远不 append 到这种会话。

### 4.4 UI（Operit 设置语言）

`设置 → 数据和权限 → 旧版数据导入`（`DataMigrationScreen`）：

- SAF 选 zip（`OpenDocument`，MIME：`application/zip` / `x-zip-compressed` / `octet-stream`）；
- 扫描中进度条 → 「45 条 · v0 25 / v3 20 · 5617 条消息」摘要 + 全选/全不选；
- 每条：标题 / 日期 / 消息数 / 工作区 / 版本 chip / 已导入 chip / 首条预览；
- 点行 → 预览弹窗（前 4 条消息，用户/助手标签）；
- 底部固定「导入 N 条会话（只读）」→ 逐条进度（成功/失败）→ 完成卡 + 「去会话列表查看」；
- 导入后原地把成功项标「已导入」（不重新解压 14 MB 备份）。

调试通道：`--es dsh_import_zip <绝对路径>` 直接打开本页并预扫描（真机自动验收用）。

## 七、已知限制（诚实清单）

1. **不是官方 v0→v4 迁移链**：没有重排 60k 事件的 seq、没有重写 `surfaceOp/sourceEventSeqs`、
   没有把 v0 的 chunk 流内嵌成 `assistant/message.stream`。导入副本是「对话投影」，
   结构合法但**不能交给上游当原会话继续写**。完整链在 `docs/port/01 §5.7`，后置。
2. **日志类事件不搬**：token/approval/goal/schedule/compaction/todo 事件、request 工具清单等。
   UI 能回放的消息/工具卡/思考过程/任务清单都在（任务清单来自 assistant 消息里的 tool-call 参数）。
3. **附件不搬**：旧消息里的 `image` 块保留原始 JSON（附件不在 zip 的会话目录里，索引会断）；
   渲染时是未知块，不显示破图。
4. **v1/v2 没有真实样本**：代码走同一套消息投影（有 `user/message`/`assistant/message` 就能导入），
   但未用真文件验证；`v2` 的 `assistant/message.stream` 内嵌流不在投影范围内。
5. **不导入设置/凭据/主题**：本轮只导入会话；`settings.yaml`/`.credentials.yaml` 留在备份包。
6. **去重按 sha256**：同一备份重复扫描会标「已导入」，默认不勾；v0–v3 若手动重复导入会生成第二份副本
   （UI 默认阻止，importer 本身不做 sha 查询，避免每次导入都全盘扫描）。

## 八、踩到的坑（血泪）

1. **PowerShell 把 UTF-8 源码读成 GBK 再写回 = 文件报废**：`Get-Content -Raw` + `Set-Content -Encoding UTF8`
   往返一次，中文全变 `娌℃湁…`，还把引号吃掉导致 40 处语法错。
   **纪律：改 Kotlin/文档一律用编辑器工具（read/write/edit），不要用 shell 做文本替换写回。**
2. **`adb shell` 默认带 pty，二进制 stdin 会被控制字符打断**：`cat > file` 只写 66 字节就退出。
   `-T` 关 pty 又不转发 stdin。最终方案：**base64 文本**分 76 列 + `base64 -d`（sha256 校验一致）。
3. **App 读不到 `/sdcard/Android/data/<pkg>/files`**：shell 创建目录的 SELinux/属主不对，直接 EACCES；
   SAF 的 `content://` 和 App 自己的 `filesDir` 没问题。调试通道因此用 `files/import/backup.zip`。
4. **DocumentsUI 的「文档」筛选会把 zip 藏掉**：`OpenDocument` 传 `*/*` 时它默认按文档类过滤，
   Download 里 12 个 DSH 备份 zip 一个都不显示。改成 zip/octet-stream MIME 列表后正常。
5. **旧会话的「今天」分组**：`updatedAt` 用文件 mtime 会把 9 月会话显示成今天；改为取最后事件时间。
6. **`session/title` 要取最后一条**：`SessionRepository.summarize` 原来取第一条（fallback 短标题），
   重命名/LLM 起名后列表不更新；本轮顺手改成 last-wins（与 docs/port/01 §7 一致）。
