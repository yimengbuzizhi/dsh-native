## 二、上游依据（宁抄勿研）

1. **触发**（`<workspace>021\node_modules\@deepseek-ai\dsh-compaction-image-offload\lib\index.js`
   第 146–151 行）：
   ```js
   ctx.on("compaction/summary-error", ({ session, sourceEventSeqs, error, signal }, next) => {
       if (!(error instanceof LlmError) || error.code !== IMAGE_OFFLOAD_REQUIRED_CODE ||
           error.failure.offloadImages === void 0) return next();
       signal?.throwIfAborted();
       if (!offloadOldestImages(session, sourceEventSeqs, error.failure.offloadImages)) return next();
       return true;
   });
   ```
   只认 `IMAGE_OFFLOAD_REQUIRED` + `offloadImages`；只动 `sourceEventSeqs`（摘要选区）；
   没有可卸的图就 `next()`（原错误由 backend 抛出）。
2. **重试环**（`dsh-compaction-basic/lib/index.js` 第 582–595 行 `summarizeCompaction()`）：
   ```js
   for (;;) {
       try { summaryResult = await dependencies.summarize(prepared.input, agent, signal); break; }
       catch (error) {
           if (signal?.aborted === true) throw error;
           assertStable(dependencies, agent.session, prepared);
           if (!dependencies.recover(error, agent, prepared.shadowedSeqs, signal)) throw error;
           prepared = prepareCompaction(dependencies, agent.session,
               validateSurfaceRegion(agent.session, prepared.start, prepared.end));
       }
   }
   ```
   重试前**重新量选区/重新计价**（`prepareCompaction`），区间边界不变；每次卸载至少少一张图，
   所以循环必然收敛；`compaction/end` 只有一次（`closing` 标志，本轮沿用既有 catch 结构）。
3. **README 语义**（`dsh-compaction-image-offload/README.md`）：
   「Summary failures use the synchronous `compaction/summary-error` waterfall. The plugin selects
   only the supplied summary region and returns true after recording an omission. The compaction
   backend re-derives and re-prices that region before retrying; each retry omits additional
   retained occurrences, so recovery ends when none remain. Cancellation and unrelated selection
   changes reject the summary. Recorded omissions survive later failure or cancellation.」

### 3.1 事件与重试

```
command/run
compaction/start{compactionId, sourceCommandId, turn}
image/offload{targets:[{seq,imageIndexes}]}        ← M48 新增（在 bracket 内、summary 之前）
compaction/summary{shadowedRange, shadowedSeqs, shadowedTokenCount(重新计价), …}
user/message{surfaceOp:replace, source.kind:"compact-checkpoint"}
compaction/end
command/done{success}
```

- 第一份摘要请求**不发网络**：本地按 `ImageOffload.requiredCount()` 算超预算，合成
  `LlmEvent.Failed(code="IMAGE_OFFLOAD_REQUIRED", offloadImages=n)`，直接进恢复分支；
- 卸载只选摘要选区里的图（`ImageOffload.selectOldest(shadowedMessages, n)`），不会碰选区外；
- 重试不新开 `compaction/start`，`compaction/end` 仍只有一条（成功无 error / 失败带 error）；
- 失败/取消时：没有可卸的图、会话写入失败、`deps.stop.requested`、重试预算用完 →
  抛原来的失败，调用方记 `compaction/end{error}`，**已落的 `image/offload` 不撤销**
  （上游「Recorded omissions survive later failure or cancellation」）。

### 3.2 重新计价

卸载后选区的 image 块变成 `offloaded:true` 的占位投影，选区价按卸载后的消息重算
（真机 1108 → 1112；启发式里 image 块按 raw JSON 计价，占位文本的差异很小），
`compaction/summary.shadowedTokenCount`、缩小判定、`command/done` 文案都用新价。
与上游 `prepareCompaction()` 的重新量价同义；差别见 §四.3。

## 四、与上游的差别（全部有意，写在这里避免下轮重复研究）

1. **触发点仍在引擎**：原生没有 Files 通道，摘要请求也按 base64 直传；引擎在
   `buildCompactionRequest()` 之后按默认预算算一遍，合成同形失败（与 M47 主请求同一套
   `ImageOffload.requiredCount()`）。少一次真实网络往返，但「每次都对应一次失败」的语义保留；
2. **重试上限 `ImageOffload.MAX_RETRIES=40`**：上游靠「没有可卸的图」自然收敛；原生加了一个
   防呆上限（每轮至少少一张图，40 轮覆盖 600 张极端会话），防止 `recover` 实现错误时死循环；
3. **重新计价只重算价、不重选区间**：上游 `prepareCompaction()` 会重新量整个选区、校验
   `selectedNodes` 与选区一致（不一致抛 `SurfaceChangedError`）；原生在同一个协程里，
   会话面不会在摘要期间变化，`shadowedSeqs` 也显式校验过（`ui.messages()` 的 seq 列表），
   所以只重算价。占位文本的实际价没有被启发式完整建模（image 块仍按 raw JSON 计价），
   差异 < 10 tokens 量级，不影响缩小判定；
4. **取消语义**：上游在 `recover` 里 `signal.throwIfAborted()`；原生用 `deps.stop.requested`
   提前退出恢复分支，按普通摘要失败收口（`compaction/end{error}`），不再补一条 CANCELLED；
   流式中的 `CancellationException` 仍走原来的 `compaction/end{CANCELLED_TEXT}`；
5. **手工路径的 `recover` 在 App 层**（`executeCompactCommand`）：手动压缩的界面替换本来就在
   AppViewModel 里，卸载后要同时更新 `state.messages`；自动路径在引擎里。两条路径共用
   `TurnEngine.summarizeCompaction` 的重试环，行为一致。
