# 167 · M85-F1：能力契约（capability/v1）——特权能力由插件提供，宿主只登记/权限门/超时

> 2026-11-14 09:1x。按 `docs/144` §3/§8 的 M85-F 第一项做 **capability/v1**：
> root / NFC / Shizuku / adb-shell 等特权能力**不在宿主写死**，由内置或第三方插件登记；
> 宿主只做「登记 + 权限门（`capability` 授权）+ 超时」，没有提供方时如实报「不可用」。
> 真机：OPPO A55 5G（PEMM00 / 720×1600 / Android 13）；本批未发布（0.3.2 / versionCode 5）。
> 演示插件：`docs/m85f-capability-demo/`。

---

## 1. 结论

1. **契约落地**：`capability/v1` 有独立纯 Kotlin 模块 `:core:capability-api`
   （`list` 语义 = 全部候选，`check(id)` = 解析提供方，`invoke(id,args)` = 执行），
   选择规则在 JVM 单测 `CapabilityRoutingTest` **10/10** 锁死。
2. **插件可提供任何能力**：`ctx.capability.register({id,label,description,kind,invoke})`，
   定义留在常驻 JS 运行时，宿主 dispatch `capability.invoke`；新权限 `capability`
   （导入即允许，调用才生效）。第三方同 id **覆盖内置**（演示插件覆盖了内置 `notify`）。
3. **没有提供方就如实不可用**：停用提供方插件 / 未安装 / 缺授权时，解析结果带可读原因
   （「能力 nfc 的提供方插件 m85f.capability-demo 已停用。」），插件页与 dump 原样展示；
   同 id 有内置实现时回落到内置（`notify` 回落成 Toast），**不是把失败藏起来**。
4. **内置只有骨架平台原语**：`notify`（Toast）/ `clipboard.read` / `clipboard.write` / `share`；
   root / NFC / Shizuku / adb-shell 一条都没有内置。
5. **真机**：插件提供 `nfc` / `adb-shell` / 覆盖 `notify` 调用成功；停用后 nfc/adb-shell
   不可用、notify 回内置；插件页「能力插件（6）」可调用并显示结果。
6. **M84-B 142/142 PASS**（M85-F1 最终 APK，见 §4）。

## 2. 实现

### 2.1 契约与选择规则（`:core:capability-api`）

- `CAPABILITY_CONTRACT = "capability/v1"`、`CAPABILITY_INVOKE_METHOD = "capability.invoke"`；
- `CapabilityCandidate(id,label,description,kind,pluginId,builtin,enabled,permitted)`；
- `CapabilityRouting.resolve(id, candidates)`：
  | 情况 | 结果 |
  |---|---|
  | 同一 id 有「启用 + 有 capability 授权」的插件 | 选插件（按候选顺序；内置被覆盖） |
  | 只有内置 | 选内置 |
  | 插件停用 | 同 id 有内置 → 回内置；没有 → `Unavailable`（说明停用） |
  | 插件缺 `capability` 授权 | 同上；没有内置 → `Unavailable`（说明缺授权） |
  | 完全没提供方 | `Unavailable`（「没有提供方」） |
  | id 为空/非法 | `Unavailable`（不猜、不截断） |
- `CapabilityRouting.catalog` 按 id 去重（插件优先展示），供插件页/dump。

### 2.2 插件侧（`:core:plugins`）

- `ctx.capability.register({id,label,description,kind,invoke})`；`invoke(args)` 允许 async，
  返回 `string/object` 或 `{ok,value}` / `{ok:false,error}`；
- 元数据 `PluginCapabilityProvider` 进 `PluginRecord.capabilities`（`plugins.json` 持久化、
  试运行/热重载都解析，旧清单没有 = 空表）；
- 常驻运行时 dispatch `capability.invoke`（`__dshCapabilityDispatch`）；
- 新权限 `capability`（`capability:provide` / `capabilities` 等价），自动授予、`implemented=true`；
- 插件 API 清单新增 `capability.provide`（版本 `m85f`）。
- **修了一个真机才暴露的 bug**：`PluginResidentRuntime.sync` 的「需要常驻运行时」条件原先只认
  投影/订阅/清理器/stream/壳/回合/存储/提示词，**纯能力插件不会起运行时**（日志
  `resident start failed: nothing registered`）。已把 `record.capabilities` 加进条件，
  启动返回值也解析 `capabilities`，否则能力插件永远「运行时不可用」。

### 2.3 宿主（app）

- `app/data/CapabilityHost.kt`：
  - `candidates()` = 内置 4 条 + 每个已安装插件的 `capabilities`（带开关/授权）；
  - `ui()` = 每个 id 一行（插件优先内置；不可用带 `unavailableReason`）；
  - `invoke(id,args)`：插件 dispatch 4.5s + 外层 5s 超时；`ok=false` 时返回真实原因
    （HTML/JS 报错、超时、运行时不存在、没有提供方都分开）；
  - 内置实现：Toast 通知、剪贴板读/写、系统分享（文本）。
- `AppViewModel`：`capabilityHost`、`capabilityUi`、`capabilityNotice`、`invokeCapability`、
  `dumpCapabilities`、`runCapabilityTest`。
- 插件页新增「能力插件（N）」分组：id/提供者/分类/可用性 + 「调用」按钮，结果显示在分组上方。
- 调试通道（仅 debug）：
  - `--es dsh_capability_list <绝对路径>`：能力清单 + 全部插件提供方 + 内置清单；
  - `--es dsh_capability_test <绝对路径>`：等常驻运行时后依次调用
    `notify` / `clipboard.write` / `clipboard.read` / `nfc` / `adb-shell` / `m85f.missing`。

## 6. 没做 / 限制（不许当成已完成）

1. 演示的 `nfc` / `adb-shell` 是**模拟结果**（不读硬件、不执行命令）；真实特权实现要由后续插件
   自己接（root/Shizuku 通道仍不在骨架，宿主没有写死）。
2. v1 的调用入口是**插件页 + 调试通道**；插件之间的「A 插件调用 B 插件能力」尚未开放
   （避免从 JS 线程同步回灌另一个常驻运行时造成死锁），契约 id/参数形状已留好。
3. 能力授权是「注册时就绪、调用时生效」的粗粒度门；没有按能力 id 的细粒度授权 UI（v1）。
4. 内置 `share` 只支持纯文本；剪贴板只支持文本。
5. 未发布；发布树/tag/Release 一律未动。
