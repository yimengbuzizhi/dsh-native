## 1. 同 id 第三方壳接管（本片唯一代码改动）

背景：`NativeShells` 只注册编译期的 `BuiltinNativeShell`（不做 DEX 动态加载，`docs/144` §10），
所以「同 id 接管」用 **Surface 插件壳**证明：第三方插件声明一个**与内置 UI 插件同 id**
（`builtin.shell.native`）的壳，宿主不因 id 相撞而拒绝。

`AppViewModel.resolveShellTarget` 改为：

```kotlin
if (raw == BuiltinPlugins.NATIVE_UI_SHELL) {
    // 启用 + ui 授权 + 声明了同 id 壳的第三方插件优先；没有则回内置 native 后端
    return pluginShellByShellId(NATIVE_UI_SHELL)
}
```

- `dsh_shell=native` / 空 → 永远内置 native 后端；
- `dsh_shell=builtin.shell.native` → 若第三方插件声明了同 id 壳则选中它，否则回内置 native；
- 插件停用/失效 → 解析回 null → 自动回内置 native（pref 保留，重新启用按 pref 恢复）。

演示插件 `m85c3.sameid`：`ctx.ui.registerShell({ id: 'builtin.shell.native', label: '同 id 第三方壳' })`，
界面与原生明显不同（顶部「M85-C5 · 同 id 接管」+ 提供者行）。

## 4. 宿主源码扫描（`docs/m85c3-5-source-scan.txt`）

`app/src/main/java` 里 import 的 `ui.*` 只剩：

| 位置 | 用途 | 是否允许 |
|---|---|---|
| `MainActivity` → `ui.DshApp` | 应用入口本身 | 是（宿主入口） |
| `ui.App` → `SafeModeScreen`、`surface.PluginShellScreen` | 安全模式兜底 / 可选 Surface 壳宿主 | 是（宿主骨架） |
| `data.PluginShellHost` → `surface.SurfaceRow` | Surface 渲染器 | 是（宿主骨架） |
| `device/floating/**` → `ui.chat.{QuotedAttachment,QuotedAttachmentChip,parseQuotedAttachment,consumeInnerScroll}` | 悬浮窗全屏/窗口复用聊天气泡公共组件 | 是（C3-3c 已记录的技术债，M85-F 浮动窗 Surface 化时处理） |

- 具体页面/壳/路由类名：`app` 源码中**零引用**（只有 `ui/App.kt` 注释里提到历史路径）；
- 已搬走的页面包（`ui.settings/plugins/sessions/agents/jobs/remote/workspace/terminal/packages/
  device/permissions/onboarding/screen/shell.native`）：`app` **零 import**；
- `memory`：`app` 只 import `MemoryTools`/`MemoryPluginHost`（工具/宿主桥，在 `:support` 或 app 的
  非 UI 包），没有 UI 页引用。

结论：宿主只剩「壳选择 / 安全模式 / Surface 渲染器 / 浮动窗公共组件」，
页面清单/路由/抽屉/设置/onboarding/虚拟屏都已在内置 UI 插件（`:ui:native-shell`）里。
