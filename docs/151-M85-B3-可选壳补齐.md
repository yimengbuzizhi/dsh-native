## 1. 这一片做了什么

全部是**宿主通用能力 + 壳自己的 Surface 树**，没有把聊天/页面语义塞进宿主：

| 缺口（docs/150 §2） | 宿主侧 | 壳侧（1.4.1） |
|---|---|---|
| 审批「总是允许/拒绝」逐项 | 无（已有 `approval` 命令） | 无（已有按钮） |
| 相机拍照 | 无（B2 已接 `pickFile(camera)`） | 无（已有拍照入口） |
| 文件卡「点开看原文」 | 消息里识别宿主自己产出的附件块（`[附件: …]` / `<attachment …/>`）→ `SurfaceRow.Attachment.body`；新增 `item.body/hasBody/isImage/isFile/fileExpanded/fileLabel`；待发文本文件也带 `body` | 消息/待发文件卡可展开原文（`setShellView` 存展开态） |
| 引用 chip | 通用 `onLongPress`（与 `onTap` 同一套动作 id 校验）；动作 payload 只多带一次消息原文 | 长按消息 → 输入条上方引用条；发送时壳自己拼 `>` 引用块 |
| 多题自定义回答 | 无（复用通用 `chat.draft` + `answer`） | 每题「其他回答」入口 + 一个共享输入框；自定义只归当前选中的题 |
| goal 控制 | 新命令 `goal {action: pause|resume|edit|clear, objective?, maxRounds?}`；state 补 `chat.goal.*` 布尔绑定 | 目标条「管理」面板：暂停/继续/编辑目标/改上限/清空（两步确认） |
| 日程/提醒 | `chat.schedules` 行 + `deleteSchedule` 命令；新增 `schedulesRevision` 快照状态（提醒不在会话状态里，必须给 Compose 一个可观察值） | 「会话提醒 N 条 → 查看」列表 + 删除 |
| 后台会话等待横幅 | `chat.waiting` 行 + `chat.hasWaiting` / `chat.waiting.label` + `focusSession` 命令（不带 id = 第一条等待项） | 顶部黄色横幅，点一下切到等待中的会话 |

另外修了两个真实问题：

- **Compose 跳过重组**：`SurfaceNode` 是 data class，结构相同的树会被 Compose 判为“参数没变”，
  读非快照数据（提醒文件）的绑定永远不刷新。提醒改用 `schedulesRevision` 快照状态驱动
  （`currentSchedules()` 里读一次），新建/投递/删除后壳立即刷新。
- **goal 编辑时输入区重复**：goal 编辑复用 `chat.draft`，底部聊天输入框和面板输入框会各显示一份；
  编辑态下壳把底部输入区换掉（`.concat(goalEdit ? [] : [...])`），只剩面板里的输入框。

调试通道小补：`--es dsh_attach_text <路径>` 现在**不带** `dsh_send` 时也会新建会话并把文件放进
待发列表（原来只有跟 `dsh_send` 连用才会读附件），用于验收「待发文件卡展开」。

## 3. 明确没做 / 已知限制

- **引用只做「长按 → 引用」**：legacy 长按菜单里的复制/朗读/重发/重新生成/创建分支/信息仍未迁
  （要等消息动作面/`onLongPress` 菜单原语，或直接由 native UI 插件承担）。
- **文件预览最多 200 行**（与思考/工具卡展开同一上限），没有内部滚动；超长文件只能看前 200 行。
- **提醒只读+删除**：创建仍由模型的 `schedule_*` 工具负责；「下次触发」文案在壳重组时刷新，
  没有单独的倒计时刷新。
- **goal 编辑复用全局 draft**：编辑期间底部输入区隐藏；保存/取消后还原进入编辑前的草稿。
- **等待横幅只显示第一条 + 总数**：点击切到第一条；没有多会话选择面板。
- **抽屉/设置/模型切换/搜索/22 页**仍未进 Surface 壳——按新方向这些**不再迁进 Surface**，
  而是随原生 UI 原样进入 `builtin.shell.native`（M85-C 新定义，见 `docs/HANDOFF.md` 顶部）。
- **默认 UI 仍是 native**：本片只动可选壳，验完已把设备恢复 `dsh_shell=native`。
